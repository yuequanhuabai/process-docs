## 三、Day 31 挂起项展开（含来源与落地方案）

> 拆分文档前这些标记散落在 P1/P3/P4 各 Day 条目里，复查却全在这一天。此处集中收口，动手时看这一节即可。

### 1. 接口鉴权粒度 ⚠️ 唯一有实质生产风险的一条
- **来源**：P3 · Day 11（2026-07-21 发现）
- **现状**：`LoginInterceptor` 只做「登录与否」的**认证**，没有「能干什么」的**授权**。实测 employee 账号同样能调 `deploy`。
- **影响面**：`ProcessDefinitionController` 全部写接口；`ProcessInstanceController.terminate`（任何人可终止任何实例）；`SystemUserController` 全部 CRUD（employee 可增删改用户）
- **方案**：① `@PreAuthorize` 风格自定义注解 + 拦截器读 `UserContext.role`（**倾向**，轻量、契合现有 ThreadLocal 方案）；② 引入 Spring Security 做完整 RBAC（重，与手写 JWT 冲突）
- **验收判据**：employee token 调 `deploy` 应 403 而非 200

### 2. 业务异常状态码粒度
- **来源**：P3 · Day 13（2026-07-21 实测时登记）
- **现状**：`BizException` 一律 `code:500`，越权/不存在/状态冲突全混在一起，前端无法按码分流
- **方案**：给 `BizException` 加 code 字段或派生子类，`GlobalExceptionHandler` 按类型映射 403/404/409
- **建议**：与第 1 条一并做，是同一类问题。另注 `HttpMessageNotReadableException` 当前也落 500 兜底

### 3. CORS
- **来源**：P1 · Day 6（2026-07-06 决策）
- **现状**：后端不写 `CorsConfig`，交给 nginx。拦截器已埋 OPTIONS 放行兜底
- **方案**：首选同源化（nginx 同时服务前端静态 + 反代 API，CORS 根本不触发）；若分域名则 nginx `add_header` + 直答 OPTIONS
- **验收判据**：实测一次跨源登录，预检 OPTIONS + POST 两条请求都通

### 4. 中文字体
- **来源**：P3 · Day 10（2026-07-09 决策）
- **现状**：`activity-font-name` / `label-font-name` / `annotation-font-name` 默认全是 **Arial**（不含中文字形），只影响**后端出图**时的中文显示
- **方案**：确有出图需求才改这三项为宋体等中文字体。前端 bpmn-js 渲染不经后端出图，很可能根本用不上
- **落点**：`application.yml` 的 Flowable 段（2026-07-21 已把默认值显式写出并加注释）
