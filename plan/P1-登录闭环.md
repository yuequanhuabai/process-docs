- [x] `LoginVO`：token + id/username/realName/role 登录一并返回（坑2 已解，2026-07-06；id 用字符串防前端丢精度）
- [ ] ⚠️ **CORS 挂起标记**（2026-07-06 决策，暂可过，Day 31 复查）：后端不写 `CorsConfig`，生产由 nginx 承担——首选同源化（nginx 同时服务前端静态 + 反代 API，CORS 不触发）；若前端/API 分域名，则 nginx `add_header` 发通行证并直答 OPTIONS。拦截器已有 OPTIONS 放行兜底（写 Day 6 时已埋，防预检穿透到后端时全线 401）
- [x] **验收**：登录拿 token；不带 token 401（swagger/postman 已可验）。2026-07-06 晚 curl 实测：正确密码返回完整 `LoginVO`（token+id/username/realName/role），错误密码返回 `{code:401}`。比对逻辑欠账已清（2026-07-09）：登录逻辑整体收进 `AuthServiceImpl.login()`，Controller 一行委托；用户不存在/密码错误统一 401「账号或密码错误」防用户名枚举

**Day 7 · 前端：登录页**　✅
- [x] `views/login` 真表单（用户名/密码框 + el-form + handleLogin）+ `api/auth.ts`（发 JSON body），登录成功 `setToken` 落 `fe_token`
- [x] 守卫读 token 放行、登出清理（P0 已具备，复用）
- [x] 顶栏用户名：登录响应 `setUserInfo` 落 store，layout 顶栏读 `realName`（坑2 已解）
- [x] `/auth/me` 补拉（2026-07-06 晚）：后端 `UserInfoVO`（`LoginVO` 改为继承它，与前端 `LoginResult extends UserInfo` 对称）+ `GET /auth/me`（UserContext 取 userId 回表查库）；前端 layout `onMounted` 时 userInfo 为空则补拉 → 刷新后顶栏用户名不再丢。curl 实测：带 token 200 返用户信息（无 password 字段）、不带 token 401
- [x] **验收**：浏览器实测通过（2026-07-06）——登录→进主框架→刷新保持且顶栏用户名不丢（`/auth/me` 补拉生效）；API 层登录/取我信息/无 token 401 均 curl 验过
