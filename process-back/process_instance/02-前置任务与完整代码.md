## 一、职责划分与设计决策

### 分层：与 Day 11 同构

| 层 | 类 | 职责 |
|---|---|---|
| Controller | `ProcessInstanceController` | 收参数、文档标注、一行委托 |
| Service | `ProcessInstanceService` / `Impl` | 业务校验 + 接线 Authentication + 调 `RuntimeService` |
| 持久层 | **没有** | `ACT_RU_*` 全归引擎管，同 Day 11 |

新意思一处：**Impl 同时注入两个门面**（`RuntimeService` 干活 + `RepositoryService` 发起前校验定义）——门面按域切，业务按需组合，一个 Service 用几个门面很正常。

### 接口契约（4 个端点，路由前缀 `/process-instance`）

| 方法 | 路径 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| POST | `/start` | JSON body：`processDefinitionKey`（必填）+ `businessKey` + `variables`（均可选） | `R<ProcessInstanceVO>` | 发起 |
| GET | `/page` | `current` / `size` / `definitionKey`（可选过滤） | `R<IPage<ProcessInstanceVO>>` | 运行实例分页 |
| GET | `/my-started` | `current` / `size` | `R<IPage<ProcessInstanceVO>>` | 我的发起（运行中的） |
| DELETE | `/{instanceId}` | 路径参数 + `reason`（可选） | `R<Void>` | 终止 |

### 设计决策的理由

- **发起按 key 而非 definitionId**：key 自动选最新版本（01 文档⑤），改版后前端不用换参数；发起前先按 `latestVersion()` 校验"定义存在且未挂起"，把引擎的生硬异常换成统一 `R` 友好报错。
- **砍掉计划里的 `MyStartedVO`**：字段与 `ProcessInstanceVO` 完全重合（id/key/name/businessKey/startTime/…），单独建 VO 只会多一个要同步维护的镜像。Day 14 历史版"我的发起"（含已完结的）若确需额外字段（结束时间、耗时）再建历史专用 VO。
- **`my-started` 只查运行中的**：本块坚持只用 `RuntimeService`（`startedBy` 过滤 `START_USER_ID_`），已完结实例从 RU 表消失属正常现象，Day 14 用 `HistoryService` 补全貌——先接受这个已知局限，见 05 疑问 Q1。
- **发起入参用 JSON body 而非 multipart**：与登录一致（`@RequestBody` + `@Valid`）；variables 是 `Map<String, Object>`，JSON 天然表达。
- **id 全是字符串**：instanceId、definitionId 均引擎生成的字符串，无雪花丢精度问题。
- **分页复用 `IPage` 外壳**：与 Day 11 完全同一套路（`count()` + `listPage()` 手动装 `Page`），前端 `PageResult<T>` 直接复用。

```java
package com.ha.pr.flowwork.dto.request;

import io.swagger.v3.oas.annotations.media.Schema;
import jakarta.validation.constraints.NotBlank;
import lombok.Data;

import java.util.Map;

/**
 * 发起流程实例入参。配合 Controller 的 @Valid 生效：key 缺失 → 400 统一 R 错误。
 */
@Data
public class StartProcessInstanceRequest {

    @Schema(description = "流程定义 key（如 leaveProcess），自动使用该 key 的最新版本", example = "leaveProcess")
    @NotBlank(message = "流程定义 key 不能为空")
    private String processDefinitionKey;

    @Schema(description = "业务键：关联自己业务表的记录 id（如请假单 id），可选", example = "10001")
    private String businessKey;

    @Schema(description = "流程变量：随实例流转的业务数据，可选。值建议用 string/number/boolean 基本类型",
            example = "{\"days\": 3, \"reason\": \"年假\"}")
    private Map<String, Object> variables;
}
```

### 文件 2：`dto/response/ProcessInstanceVO.java`

```java
package com.ha.pr.flowwork.dto.response;

import com.fasterxml.jackson.annotation.JsonFormat;
import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;
import org.flowable.engine.runtime.ProcessInstance;

import java.util.Date;

@Data
@Schema(description = "流程实例（运行中）")
public class ProcessInstanceVO {

    @Schema(description = "流程实例 id（引擎生成，天生字符串）")
    private String id;

    @Schema(description = "所用流程定义 id（发起时锁定的具体版本）")
    private String processDefinitionId;

    @Schema(description = "流程定义 key")
    private String processDefinitionKey;

    @Schema(description = "流程定义名称")
    private String processDefinitionName;

    @Schema(description = "业务键（关联业务表记录，可能为 null）")
    private String businessKey;

    @Schema(description = "发起人 userId（来自 Authentication，对应 START_USER_ID_）")
    private String startUserId;

    @Schema(description = "发起时间")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date startTime;

    @Schema(description = "是否挂起")
    private boolean suspended;

    public static ProcessInstanceVO of(ProcessInstance instance) {
        ProcessInstanceVO vo = new ProcessInstanceVO();
        vo.setId(instance.getId());
        vo.setProcessDefinitionId(instance.getProcessDefinitionId());
        vo.setProcessDefinitionKey(instance.getProcessDefinitionKey());
        vo.setProcessDefinitionName(instance.getProcessDefinitionName());
        vo.setBusinessKey(instance.getBusinessKey());
        vo.setStartUserId(instance.getStartUserId());
        vo.setStartTime(instance.getStartTime());
        vo.setSuspended(instance.isSuspended());
        return vo;
    }
}
```

```java
package com.ha.pr.flowwork.service.impl;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ha.pr.flowwork.common.BizException;
import com.ha.pr.flowwork.dto.request.StartProcessInstanceRequest;
import com.ha.pr.flowwork.dto.response.ProcessInstanceVO;
import com.ha.pr.flowwork.service.ProcessInstanceService;
import com.ha.pr.flowwork.util.UserContext;
import jakarta.annotation.Resource;
import lombok.extern.slf4j.Slf4j;
import org.flowable.common.engine.impl.identity.Authentication;
import org.flowable.engine.RepositoryService;
import org.flowable.engine.RuntimeService;
import org.flowable.engine.repository.ProcessDefinition;
import org.flowable.engine.runtime.ProcessInstance;
import org.flowable.engine.runtime.ProcessInstanceQuery;
import org.springframework.stereotype.Service;

import java.util.List;

@Slf4j
@Service
public class ProcessInstanceServiceImpl implements ProcessInstanceService {

    /** 运行域门面：实例的发起/查询/终止 */
    @Resource
    private RuntimeService runtimeService;

    /** 仓库域门面：发起前校验流程定义（一个 Service 组合多个门面很正常） */
    @Resource
    private RepositoryService repositoryService;

    @Override
    public ProcessInstanceVO start(StartProcessInstanceRequest req) {
        String key = req.getProcessDefinitionKey();
        // 预检：把引擎的生硬异常（找不到定义/定义挂起）换成统一 R 友好报错
        ProcessDefinition def = repositoryService.createProcessDefinitionQuery()
                .processDefinitionKey(key)
                .latestVersion()
                .singleResult();
        if (def == null) {
            throw new BizException("流程定义不存在：" + key);
        }
        if (def.isSuspended()) {
            throw new BizException("流程定义已挂起，无法发起：" + key);
        }
        // 接线：把我们的 UserContext 用户告诉引擎的 ThreadLocal，
        // 引擎发起时写 START_USER_ID_ + initiator 变量；用完必须清（同 UserContext 的纪律）
        Authentication.setAuthenticatedUserId(UserContext.userId());
        try {
            ProcessInstance instance = runtimeService.startProcessInstanceByKey(
                    key, req.getBusinessKey(), req.getVariables());
            log.info("流程实例已发起：instanceId={}, definitionId={}, startUserId={}",
                    instance.getId(), instance.getProcessDefinitionId(), instance.getStartUserId());
            return ProcessInstanceVO.of(instance);
        } finally {
            Authentication.setAuthenticatedUserId(null);
        }
    }

    @Override
    public IPage<ProcessInstanceVO> page(long current, long size, String definitionKey) {
        ProcessInstanceQuery query = runtimeService.createProcessInstanceQuery()
                .orderByStartTime().desc();
        if (definitionKey != null && !definitionKey.isBlank()) {
            query.processDefinitionKey(definitionKey);
        }
        return toPage(query, current, size);
    }

    @Override
    public IPage<ProcessInstanceVO> myStarted(long current, long size) {
        ProcessInstanceQuery query = runtimeService.createProcessInstanceQuery()
                .startedBy(UserContext.userId())   // 过滤 START_USER_ID_
                .orderByStartTime().desc();
        return toPage(query, current, size);
    }

    @Override
    public void terminate(String instanceId, String reason) {
        ProcessInstance instance = runtimeService.createProcessInstanceQuery()
                .processInstanceId(instanceId)
                .singleResult();
        if (instance == null) {
            // 已完结的实例不在 RU 表里，报"不存在"是正确语义（历史在 Day 14 查）
            throw new BizException("运行中的流程实例不存在：" + instanceId);
        }
        runtimeService.deleteProcessInstance(instanceId,
                reason != null && !reason.isBlank() ? reason : "手动终止");
    }

    /** count() + listPage() 装进 MP Page 外壳，同 Day 11 的套路 */
    private IPage<ProcessInstanceVO> toPage(ProcessInstanceQuery query, long current, long size) {
        long total = query.count();
        List<ProcessInstance> instances = query.listPage((int) ((current - 1) * size), (int) size);
        Page<ProcessInstanceVO> page = new Page<>(current, size, total);
        page.setRecords(instances.stream().map(ProcessInstanceVO::of).toList());
        return page;
    }
}
```

### 文件 4：`controller/ProcessInstanceController.java`

```java
package com.ha.pr.flowwork.controller;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ha.pr.flowwork.common.R;
import com.ha.pr.flowwork.dto.request.StartProcessInstanceRequest;
import com.ha.pr.flowwork.dto.response.ProcessInstanceVO;
import com.ha.pr.flowwork.service.ProcessInstanceService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.annotation.Resource;
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@Tag(name = "流程实例", description = "发起 / 运行实例查询 / 我的发起 / 终止")
@RestController
@RequestMapping("/process-instance")
public class ProcessInstanceController {

    @Resource
    private ProcessInstanceService processInstanceService;

    @Operation(summary = "发起流程实例（按 key 用最新版本，当前用户记为发起人）")
    @PostMapping("start")
    public R<ProcessInstanceVO> start(@RequestBody @Valid StartProcessInstanceRequest req) {
        return R.ok(processInstanceService.start(req));
    }

    @Operation(summary = "分页查询运行中的流程实例")
    @GetMapping("page")
    public R<IPage<ProcessInstanceVO>> page(
            @Parameter(description = "当前页，从 1 开始") @RequestParam(defaultValue = "1") long current,
            @Parameter(description = "每页条数") @RequestParam(defaultValue = "10") long size,
            @Parameter(description = "按流程定义 key 过滤，可选") @RequestParam(required = false) String definitionKey) {
        return R.ok(processInstanceService.page(current, size, definitionKey));
    }

    @Operation(summary = "我的发起（当前用户发起的运行中实例）")
    @GetMapping("my-started")
    public R<IPage<ProcessInstanceVO>> myStarted(
            @Parameter(description = "当前页，从 1 开始") @RequestParam(defaultValue = "1") long current,
            @Parameter(description = "每页条数") @RequestParam(defaultValue = "10") long size) {
        return R.ok(processInstanceService.myStarted(current, size));
    }

    @Operation(summary = "终止运行中的流程实例（历史保留原因）")
    @DeleteMapping("{instanceId}")
    public R<Void> terminate(
            @Parameter(description = "流程实例 id") @PathVariable String instanceId,
            @Parameter(description = "终止原因，可选") @RequestParam(required = false) String reason) {
        processInstanceService.terminate(instanceId, reason);
        return R.ok();
    }
}
```

## 三、坑清单（写代码时已规避，理解即可）

1. **`Authentication` 必须 finally 清**——引擎的 ThreadLocal，不清则线程池复用时"上一个请求的用户"变成下一次发起的发起人。和你写 `LoginInterceptor.afterCompletion` 清 `UserContext` 是同一条纪律。
2. **`Authentication` 的 import 是 `org.flowable.common.engine.impl.identity.Authentication`**——IDE 补全时别选成 Spring Security 的同名类（本项目没引 Spring Security，选错会直接编译不过，算是天然防呆）。
3. **数实例用 `createProcessInstanceQuery`**——`createExecutionQuery` 会把游标子执行也算进去，count 翻倍（01 文档④）。
4. **variables 的值控制在基本类型**——string/number/boolean 落 `ACT_RU_VARIABLE` 的对应类型列；塞复杂对象会走序列化存字节，Day 13 取任务表单时徒增麻烦。
5. **终止已完结的实例会报"不存在"**——RU 表里确实没有了，这是对的语义，不是 bug；front 端将来只对运行中的实例显示终止按钮。
6. **预检和发起之间理论上有竞态**（预检通过后、发起前定义被挂起）——引擎会在发起命令里再查一次并抛异常，兜底仍在，预检只是为了友好报错，不承担正确性。
7. **`@RequestBody` 忘了配 `@Valid` 则 `@NotBlank` 不生效**——校验注解只是声明，触发靠 Controller 参数上的 `@Valid`（Day 1 的 GlobalExceptionHandler 已能接住转统一 R）。
