## 3. `service/impl/ProcessInstanceServiceImpl.java`（完整替换）

> `start()` / `terminate()` 原样未动，`page()` **真的零改动**。
> 新增：`HistoryService` / `TaskService` / `SystemUserMapper` 三个依赖 + `applyStatusFilter()` + `enrich()` + `toHiPage()`。

```java
package com.ha.pr.flowwork.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ha.pr.flowwork.common.BizException;
import com.ha.pr.flowwork.dto.request.StartProcessInstanceRequest;
import com.ha.pr.flowwork.dto.response.ProcessInstanceVO;
import com.ha.pr.flowwork.entity.SysUser;
import com.ha.pr.flowwork.mapper.SystemUserMapper;
import com.ha.pr.flowwork.service.ProcessInstanceService;
import com.ha.pr.flowwork.util.UserContext;
import jakarta.annotation.Resource;
import lombok.extern.slf4j.Slf4j;
import org.flowable.common.engine.impl.identity.Authentication;
import org.flowable.engine.HistoryService;
import org.flowable.engine.RepositoryService;
import org.flowable.engine.RuntimeService;
import org.flowable.engine.TaskService;
import org.flowable.engine.history.HistoricProcessInstance;
import org.flowable.engine.history.HistoricProcessInstanceQuery;
import org.flowable.engine.repository.ProcessDefinition;
import org.flowable.engine.runtime.ProcessInstance;
import org.flowable.engine.runtime.ProcessInstanceQuery;
import org.flowable.task.api.Task;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;
import java.util.Objects;
import java.util.Set;
import java.util.stream.Collectors;

@Service
@Slf4j
public class ProcessInstanceServiceImpl implements ProcessInstanceService {
    /** 运行域门面：实例的发起/查询/终止 */
    @Resource
    private RuntimeService runtimeService;

    /** 仓库域门面：发起前校验流程定义（一个 Service 组合多个门面很正常） */
    @Resource
    private RepositoryService repositoryService;

    /** 历史域门面：ACT_HI_PROCINST 的只读查询（Day 16 myStarted 的新数据源） */
    @Resource
    private HistoryService historyService;

    /** 任务域门面：enrich 里批量查在途实例的当前任务节点 */
    @Resource
    private TaskService taskService;

    /** enrich 里批量把 startUserId 换成 sys_user.real_name */
    @Resource
    private SystemUserMapper systemUserMapper;

    @Override
    public ProcessInstanceVO start(StartProcessInstanceRequest req) {
        String key = req.getProcessDefinitionKey();
        // 预检：把引擎的生硬异常（找不到定义/定义挂起）换成统一 R 友好报错
        ProcessDefinition def = repositoryService.createProcessDefinitionQuery()
                .processDefinitionKey(key)
                .latestVersion()
                .singleResult();
        if (def == null) {
            throw new BizException("流程定义不存在：" + key);
        }
        if (def.isSuspended()) {
            throw new BizException("流程定义已挂起，无法发起：" + key);
        }
        // 接线：把我们的 UserContext 用户告诉引擎的 ThreadLocal，
        // 引擎发起时写 START_USER_ID_ + initiator 变量；用完必须清（同 UserContext 的纪律）
        Authentication.setAuthenticatedUserId(UserContext.userId());
        try {
            ProcessInstance instance = runtimeService.startProcessInstanceByKey(
                    key, req.getBusinessKey(), req.getVariables());
            log.info("流程实例已发起：instanceId={}, definitionId={}, startUserId={}",
                    instance.getId(), instance.getProcessDefinitionId(), instance.getStartUserId());
            return ProcessInstanceVO.of(instance);
        } finally {
            Authentication.setAuthenticatedUserId(null);
        }
    }

    @Override
    public IPage<ProcessInstanceVO> page(long current, long size, String definitionKey) {
        // 继续查 RU 是故意的：这一页的语义就是"现在有哪些实例在跑"，别改成 HI（07 文档）
        ProcessInstanceQuery query = runtimeService.createProcessInstanceQuery()
                .orderByStartTime().desc();
        if (definitionKey != null && !definitionKey.isBlank()) {
            query.processDefinitionKey(definitionKey);
        }
        // 这一行和改造前一模一样。但 toPage 内部收编了 enrich()，
        // 所以「实例」页白捡 startUserName + currentActivityName 两个新字段
        return toPage(query, current, size);
    }

    @Override
    public IPage<ProcessInstanceVO> myStarted(long current, long size, String status) {
        // Day 16 改造：RuntimeService（只见在途）→ HistoryService（全集），原理见 07 文档。
        // ⚠️ HI 的排序方法叫 orderByProcessInstanceStartTime，与 RU 的 orderByStartTime 不同名
        HistoricProcessInstanceQuery query = historyService.createHistoricProcessInstanceQuery()
                .startedBy(UserContext.userId())   // 过滤 ACT_HI_PROCINST.START_USER_ID_
                .orderByProcessInstanceStartTime().desc();
        applyStatusFilter(query, status);
        return toHiPage(query, current, size);
    }

    @Override
    public void terminate(String instanceId, String reason) {
        ProcessInstance instance = runtimeService.createProcessInstanceQuery()
                .processInstanceId(instanceId)
                .singleResult();
        if (instance == null) {
            // 已完结的实例不在 RU 表里，报"不存在"是正确语义（历史在 Day 14 查）
            throw new BizException("运行中的流程实例不存在：" + instanceId);
        }
        runtimeService.deleteProcessInstance(instanceId,
                reason != null && !reason.isBlank() ? reason : "手动终止");
    }

    /**
     * 状态过滤（前端"全部/进行中/已办结/已终止"下拉）。筛选必须在后端做——
     * 放前端只能过滤当前页，total 还是全量、翻页会出空页。
     * ⚠️ 与 ProcessInstanceVO.statusOf 是同一套判据的两面（那边查回来打标签，这边查之前拼 WHERE），
     *    改一面必看另一面
     */
    private void applyStatusFilter(HistoricProcessInstanceQuery query, String status) {
        if (status == null || status.isBlank()) {
            return;   // 不传 = 全部，不加任何条件
        }
        // 常量写在 equals 左边：status 是外部传进来的，即使为 null 也不会 NPE
        if (ProcessInstanceVO.STATUS_RUNNING.equals(status)) {
            query.unfinished();                   // END_TIME_ IS NULL
        } else if (ProcessInstanceVO.STATUS_COMPLETED.equals(status)) {
            query.finished().notDeleted();        // 已结束且 DELETE_REASON_ IS NULL
        } else if (ProcessInstanceVO.STATUS_TERMINATED.equals(status)) {
            query.deleted();                      // DELETE_REASON_ IS NOT NULL（终止必已结束）
        } else {
            // 传错参数要响亮地报错，安静返回全量是要 debug 半天的软故障
            throw new BizException("未知的状态过滤值：" + status);
        }
    }

    /**
     * 批量回填 startUserName + currentActivityName。整页固定 2 次查询，
     * 严禁在循环里逐条查（N+1：一页 10 条 = 20 次库访问）。
     * Day 17 待办页、Day 18 历史页直接复用这两个字段
     */
    private void enrich(List<ProcessInstanceVO> vos) {
        if (vos.isEmpty()) {
            return;
        }
        // ① 发起人姓名：START_USER_ID_ 存的是 sys_user.id（Long 雪花）的字符串形态，
        //    查库前 Long.valueOf 转过去，转 Map 时 String.valueOf 转回来，两头都要转。
        // ⚠️ Long.valueOf 在这里不设防是有前提的：START_USER_ID_ 的唯一写入口是 start() 里的
        //    Authentication.setAuthenticatedUserId(UserContext.userId())，恒为数字 userId。
        //    哪天有别的途径发起实例（如引擎脚本、数据迁移）写进非数字，这里会 NumberFormatException
        Set<Long> userIds = vos.stream()
                .map(ProcessInstanceVO::getStartUserId)
                .filter(Objects::nonNull)
                .map(Long::valueOf)
                .collect(Collectors.toSet());
        // MP 的 in() 遇空集合会拼出非法 SQL（IN ()），必须判空短路
        Map<String, String> nameMap = userIds.isEmpty() ? Map.of()
                : systemUserMapper.selectList(
                        new LambdaQueryWrapper<SysUser>().in(SysUser::getId, userIds))
                    .stream()
                    // ⚠️ 不能直接写 SysUser::getRealName：Collectors.toMap 内部走 HashMap.merge，
                    //    value 为 null 是直接抛 NPE（不是存个 null 进去）。而 sys_user.real_name
                    //    列可空、CreateUserRequest.realName 也没有 @NotBlank —— 用户管理页建一个
                    //    不填姓名的用户，「我的发起」整页就 500。种子数据三条都有姓名，测不出来
                    .collect(Collectors.toMap(
                            u -> String.valueOf(u.getId()),
                            u -> u.getRealName() == null ? u.getUsername() : u.getRealName()));
        // ② 当前节点名：只有在途实例才有"当前任务"（已结束的不在 ACT_RU_TASK，留 null）
        List<String> runningIds = vos.stream()
                .filter(v -> ProcessInstanceVO.STATUS_RUNNING.equals(v.getStatus()))
                .map(ProcessInstanceVO::getId)
                .toList();
        // 并行网关下一个实例可能同时有多个任务，toMap 无 merge 撞 key 直接抛异常；
        // 当前四个模板都是单路径取谁都一样，(a, b) -> a 是防未来的兜底
        Map<String, String> activityMap = runningIds.isEmpty() ? Map.of()
                : taskService.createTaskQuery().processInstanceIdIn(runningIds).list()
                    .stream()
                    .collect(Collectors.toMap(Task::getProcessInstanceId, Task::getName, (a, b) -> a));
        for (ProcessInstanceVO vo : vos) {
            vo.setStartUserName(nameMap.get(vo.getStartUserId()));
            vo.setCurrentActivityName(activityMap.get(vo.getId()));
        }
    }

    /**
     * 【RU 版】count() + listPage() 装进 MP Page 外壳（Day 11/12 的老套路，参数没变）。
     * 吃 ProcessInstanceQuery，元素是 ProcessInstance，
     * 所以 ProcessInstanceVO.of(...) 会选中 of(ProcessInstance) 那个重载
     */
    private IPage<ProcessInstanceVO> toPage(ProcessInstanceQuery query, long current, long size) {
        long total = query.count();
        List<ProcessInstance> list = query.listPage((int) ((current - 1) * size), (int) size);
        Page<ProcessInstanceVO> page = new Page<>(current, size, total);
        page.setRecords(list.stream().map(ProcessInstanceVO::of).toList());
        enrich(page.getRecords());
        return page;
    }

    /**
     * 【HI 版】与上面 toPage 逐行同构，只有两处不同：吃的 Query 类型、装的元素类型。
     * 元素是 HistoricProcessInstance，于是选中 of(HistoricProcessInstance) 那个重载
     * —— 状态（在途/办结/终止）就是在那个重载里按判据算出来的。
     *
     * 📌 这两个方法是 09 泛型版想合并掉的对象。等泛型补完，
     *    把它俩换成一个 toPage(Query<?, E>, Function<E, ProcessInstanceVO>, ...) 即可，
     *    调用点各改一行。功能等价，现在不做只是不想为它卡住主线
     */
    private IPage<ProcessInstanceVO> toHiPage(HistoricProcessInstanceQuery query, long current, long size) {
        long total = query.count();
        List<HistoricProcessInstance> list = query.listPage((int) ((current - 1) * size), (int) size);
        Page<ProcessInstanceVO> page = new Page<>(current, size, total);
        page.setRecords(list.stream().map(ProcessInstanceVO::of).toList());
        enrich(page.getRecords());
        return page;
    }
}
```

### 为什么两个方法体看着一样，却不能直接合并

这不是"懒得合并"，是**合并不了**——`ProcessInstanceQuery` 和 `HistoricProcessInstanceQuery` 之间**没有继承关系**（javap 已核实，共同祖先只有 `org.flowable.common.engine.api.query.Query`）。所以：

- 参数写 `ProcessInstanceQuery` → HI 的查询器塞不进去；
- 参数写 `HistoricProcessInstanceQuery` → RU 的塞不进去；
- 想让一个方法同时吃两种，**只剩泛型这一条路**。

**看清这一点比会写泛型更重要**：泛型不是为了代码好看，是为了绕开"两个类型没有共同父类"这个编译期硬障碍。等哪天你觉得"这两份重复看着难受"了，再回 `09`，那时泛型就不是语法题而是一个具体需求的答案。
