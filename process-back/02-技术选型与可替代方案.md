# 02 · 技术选型与可替代方案

> 目标：对每个关键依赖回答三件事 —— **为什么用（原由）**、**有哪些备选方案**、**当前选型的优缺点**。
> 帮助你在重写时理解每个依赖的取舍，而不是照抄。

---

## 一、后端

### 1. Spring Boot 3.2.5（基础框架）
- **原由**：Java 生态事实标准，自动装配 + starter 大幅减少样板；Flowable 7 官方就提供 Spring Boot starter，二者天然契合。
- **备选**：Quarkus / Micronaut（启动快、内存省、原生镜像友好）；纯 Spring（无 Boot，配置繁琐）。
- **优点**：生态成熟、招人易、与 Flowable 集成零摩擦。
- **缺点**：启动相对慢、内存占用大；版本 3.x 要求 Java 17+，与老系统并存有门槛。
- **注意**：Boot 3 用 `jakarta.*` 命名空间（非 `javax.*`），选依赖时必须对应。

### 2. Flowable 7.1.0（流程引擎）★核心
- **原由**：项目本质就是工作流引擎，Flowable 提供完整 BPMN 2.0 运行时（部署/实例/任务/历史/网关/事件），开箱即用。本项目只用 process 引擎，关掉了 cmmn/dmn/app/idm/eventregistry 以减小体积和建表数量。
- **备选**：
  - **Camunda 7**（Flowable 同源，社区更活跃、文档更全）—— 但 Camunda 7 已进入维护期，Camunda 8 改为云原生 Zeebe 架构（理念完全不同，重量级）。
  - **Activiti**（Flowable 的前身，三者同根）—— 更新较慢。
  - **自研轻量状态机**（如 Spring StateMachine / COLA StateMachine）—— 适合简单审批，但要自己实现持久化、历史、网关、会签等，成本高。
- **优点**：功能完整、BPMN 标准、社区方案多；自带历史与查询 API。
- **缺点**：概念多（`ACT_*` 几十张表），学习曲线陡；"重"，对简单审批是过度设计。
- **取舍**：选 Flowable 是因为要标准 BPMN + 可视化设计器闭环；若业务只是固定几级审批，自研状态机更轻。

### 3. JWT（jjwt 0.12.6，鉴权）
- **原由**：前后端分离 + 微服务，需要无状态鉴权；JWT 把身份装进 token，服务端不存 session，水平扩展简单。jjwt 是纯做 JWT 的轻量库（不绑定 Spring Security）。
- **备选**：
  - **Spring Security + JWT**（更完整的安全体系：过滤器链、权限模型）—— 但本项目鉴权简单，引入会偏重。
  - **Session + Redis**（有状态，可即时失效 token）—— 需要额外 Redis。
  - **OAuth2 / OIDC（Keycloak 等)**（标准化、单点登录）—— 对当前规模过重。
- **优点**：无状态、易扩展、依赖轻。
- **缺点**：token 签发后**难主动失效**（改密码/登出无法立即作废）；payload 不能放敏感信息。
- **现状提醒**：当前**密码是明文比对**（`AuthService.matches`），代码已留注释说明后续换 BCrypt，重写时应直接上 `BCryptPasswordEncoder`。

### 4. JPA / Hibernate（自有表持久化）
- **原由**：用户、表单定义、流程草稿这类**自有简单表**，用 JPA 的 Repository 几乎零 SQL 即可增删改查。Flowable 自己的表不归 JPA 管。
- **备选**：
  - **MyBatis / MyBatis-Plus**（国内主流，SQL 可控、复杂查询友好）。
  - **JdbcTemplate / Spring Data JDBC**（轻量、无 ORM 魔法）。
- **优点**：自有表 CRUD 写得快、跨数据库方言切换容易（`SQLServerDialect`）。
- **缺点**：复杂查询不如 MyBatis 直观；`open-in-view` 等懒加载坑多（项目已显式关闭）。
- **取舍**：自有表少而简单 → JPA 够用；若后续报表类复杂查询变多，可引入 MyBatis 共存。

### 5. SQL Server（mssql-jdbc，数据库）
- **原由**：**与既有 HR 系统共用同一套 SQL Server 实例**（独立库 `flowable_db`），便于运维和与 HR 用户数据打通。
- **备选**：PostgreSQL / MySQL（Flowable 全支持，开源免费、社区方案多）。
- **优点**：复用现有基础设施，无需新增数据库运维。
- **缺点**：商业授权成本；部分 Flowable 社区经验以 MySQL/PG 为主。
- **取舍**：这是**环境约束驱动**的选型（迁就 HR 系统），并非技术最优。

### 6. Knife4j（API 文档）
- **原由**：基于 OpenAPI 3 的增强 UI，比原生 Swagger UI 更好用（中文、调试友好），方便前后端联调。
- **备选**：springdoc 原生 Swagger UI（已被 Knife4j 内置依赖）；Apifox / Postman（手工维护，离代码远）。
- **优点**：随代码自动生成、联调成本低。
- **缺点**：注解侵入接口代码；生产环境需关闭以免暴露接口。

### 7. Lombok（样板代码）
- **原由**：`@Data`/`@Slf4j`/`@RequiredArgsConstructor` 去掉 getter/setter/构造器/日志样板。
- **备选**：Java 17 `record`（适合不可变 DTO）；手写（啰嗦）。
- **优点**：代码简洁。
- **缺点**：编译期魔法、需 IDE 插件；打包时已配置排除，不进 jar。

## 二、前端

### 1. Vue 3 + TypeScript（框架）
- **原由**：组件化 + 响应式，配合 TS 类型安全；国内生态与 Element Plus 配套成熟。
- **备选**：React（生态更大、设计器类库更多）；Angular（重，企业级）。
- **优点**：上手快、模板直观、与 Element Plus / bpmn-js 集成顺畅。
- **缺点**：大型项目类型体操不如 React 生态完善；部分库 React 版更新更快。

### 2. Vite 8（构建工具）
- **原由**：开发期基于原生 ESM，冷启动和热更新极快；内置 dev proxy 方便转发后端。
- **备选**：Webpack（成熟但慢）；Rspack（Rust 版 webpack，快）。
- **优点**：快、配置简单、proxy 开箱即用。
- **缺点**：生态插件少于 webpack；个别老库兼容需处理。

### 3. bpmn-js 18（流程图设计器）★核心
- **原由**：流程设计器的核心诉求是"画 BPMN 图并导出标准 XML"，bpmn-js 是 Camunda 出品的事实标准库，直接产出 Flowable 能部署的 BPMN 2.0 XML。
- **备选**：
  - **LogicFlow**（滴滴开源，国产、轻、可定制）—— 但非原生 BPMN，导出标准 XML 需自己适配。
  - **X6 / G6**（AntV 图编辑引擎，通用强大）—— 同样要自己实现 BPMN 语义。
  - **jsPlumb**（连线库，太底层）。
- **优点**：直出标准 BPMN XML，与 Flowable 无缝；属性扩展机制成熟（项目用 `FlowableModdle.json` 扩展 flowable 命名空间属性）。
- **缺点**：API 偏底层、定制属性面板要自己写（项目即自建 `PropertiesPanel`）；体积大、文档偏英文。

### 4. Element Plus（UI 组件库）
- **原由**：Vue 3 配套的成熟企业级组件库，表格/表单/弹窗齐全，后台系统标配。
- **备选**：Ant Design Vue（风格更现代）；Naive UI（TS 友好、轻）。
- **优点**：组件全、文档好、社区大。
- **缺点**：风格偏传统、定制主题成本一般。

### 5. Pinia（状态管理）
- **原由**：Vue 3 官方推荐，替代 Vuex，TS 支持好、API 简单。项目用它存用户态、流程态。
- **备选**：Vuex（旧）；仅用 composable + provide/inject（轻量场景）。
- **优点**：轻、类型友好、无样板。
- **缺点**：大型项目需自行约定模块化规范。

### 6. axios（HTTP）
- **原由**：拦截器机制适合统一注入 JWT、统一拆包 `R<T>`、统一处理 401。
- **备选**：原生 `fetch`（无拦截器，要自己封装）；`alova`（新，请求状态管理一体）。
- **优点**：拦截器成熟、生态广。
- **缺点**：体积比 fetch 大；需自己维护封装层（项目即 `utils/request.ts`）。

### 7. vuedraggable（表单设计器拖拽）
- **原由**：表单设计器靠拖拽排列字段，vuedraggable（基于 Sortable.js）开箱即用。
- **备选**：原生 HTML5 Drag API（繁琐）；`vue-draggable-plus`（更新更活跃的替代）。
- **优点**：简单、够用。
- **缺点**：基于 Sortable.js，对 Vue 3 + TS 支持一般，可考虑换 `vue-draggable-plus`。

### 8. CodeMirror（XML 源码查看/编辑）
- **原由**：设计器需要查看/编辑底层 BPMN XML，CodeMirror 提供 XML 高亮编辑。
- **备选**：Monaco Editor（VS Code 内核，功能强但重）。
- **优点**：轻量、按需加载语言包。
- **缺点**：功能弱于 Monaco。

## 三、选型总览（速查表）

| 关注点 | 当前选型 | 主要备选 | 选它的核心理由 |
|---|---|---|---|
| 后端框架 | Spring Boot 3 | Quarkus/Micronaut | 与 Flowable 零摩擦、生态成熟 |
| 流程引擎 | Flowable 7 | Camunda/Activiti/自研状态机 | 标准 BPMN + 设计器闭环 |
| 鉴权 | JWT(jjwt) | Spring Security/Session/OAuth2 | 无状态、轻量 |
| 自有表持久化 | JPA | MyBatis-Plus/JDBC | 简单表 CRUD 快 |
| 数据库 | SQL Server | PostgreSQL/MySQL | **迁就既有 HR 系统**（环境约束） |
| API 文档 | Knife4j | springdoc/Apifox | 联调友好 |
| 前端框架 | Vue 3 + TS | React/Angular | 与 Element/bpmn-js 配套好 |
| 流程图 | bpmn-js | LogicFlow/X6 | 直出标准 BPMN XML |
| 表单拖拽 | vuedraggable | vue-draggable-plus | 开箱即用（可升级替代） |

> 重写建议：**Flowable + bpmn-js 是不可替换的主轴**（决定了整个系统形态）；**SQL Server / 明文密码 / vuedraggable** 是可优化点，重写时可重新评估。
