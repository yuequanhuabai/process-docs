# 重写分析维度参考

> 用途：在自己一步步手动重写 `core` 项目（重建到 `core2`）之前，先确定"从哪些维度去理解原项目"。
> 本文档只**罗列并解释可选的分析维度**，作为后续逐维度深入的索引。
> 范围：原项目 `core`，包含 `flowable-engine-server`（后端）与 `flowable-designer-ui`（前端），**跳过 `flowable-tests`**。
> 当前阶段：**不涉及"重写步骤/执行顺序"**，只做维度梳理与理解准备。

---

## 维度分类说明

把可选维度分成三类：
- **A 类 — 强烈建议补充**：对"真正学会 + 能自己重建"价值最高的维度。
- **B 类 — 锦上添花**：看投入深度决定是否展开。
- **C 类 — 已确定的初始三个**：最初提出的三个核心维度。

每个维度都说明：**内容是什么** + **为什么对理解和重写有用**。

---

## A 类 — 强烈建议补充

### A1. 领域概念与术语表（Glossary）
- **内容**：BPMN 概念（流程定义 / 流程实例 / 任务 / 网关 / 事件 / 流转等）、Flowable 自身术语、项目内部自定义名词。
- **为什么重要**：这是"基础不牢"的根因之一。不先建立词汇，看架构图也只是在背名词。**属于地基，应排在最前。**

### A2. 数据模型 / 数据库结构（Domain & Schema）
- **内容**：核心实体、表结构（Flowable 的 `ACT_*` 表 + 自定义业务表）、表间关系；一张图说清"一个流程从定义→运行→归档，数据落在哪些表"。
- **为什么重要**：工作流引擎的本质是"状态机 + 持久化"。**理解数据怎么存，引擎逻辑就理解了一大半。** `sql/` 目录是重要切入点。

### A3. 端到端运行时流程 / 调用链（Runtime Flow）
- **内容**：挑 2–3 个真实用例（如"设计器画完流程→部署""发起流程实例→办理任务"），从前端点击一路追到后端、到数据库，画时序 / 调用链。
- **为什么重要**：架构图是"静态骨架"，调用链是"动起来的血液"。**重写本质就是在重建这些链路**，有它才知道每个类 / 接口为哪条链路服务。

### A4. 前后端接口契约（API Contract）
- **内容**：后端 REST 接口清单（路径 / 方法 / 入参 / 出参）、前端调用位置、数据结构约定。
- **为什么重要**：前后端是两个独立子项目，**接口是它们的"合同"**。重写时这是天然的模块边界与验收标准。

---

## B 类 — 锦上添花

### B1. 横切关注点（Cross-cutting Concerns）
- **内容**：认证授权、事务管理、全局异常处理、日志、缓存、参数校验——散落各处但成体系的部分。
- **价值**：新手最易忽略，却是工程质量的体现；单独抽出讲，避免重写时遗漏。

### B2. 配置与启动（Config & Bootstrap）
- **内容**：配置文件、profile、启动入口、依赖装配（Spring 自动配置）、前端构建配置。
- **价值**：很多人"能写业务但跑不起来"，卡在配置。讲清"项目怎么被拼起来跑起来"。

### B3. 重写路线图 / 重建顺序（Rewrite Roadmap）
- **内容**：建议的手动重写顺序——先搭什么、再写什么、依赖关系、每步的可验证里程碑。
- **价值**：直接服务"一步步手动编写"的诉求。
- **当前状态**：⏸ **暂不纳入**（当前阶段不考虑加入步骤，后续需要时再展开）。

### B4. 前端专项拆解
- **内容**：状态管理、路由、组件层级、BPMN 画布的渲染与交互逻辑（设计器最难的部分）。
- **价值**：设计器画布逻辑若只在"模块职责"里带过会太粗，值得单独成篇。

---

## C 类 — 已确定的初始三个

### C1. 宏观架构（总文档）
- **内容**：整体架构拆分——子项目 / 模块、分层结构、协作关系、请求 / 数据流向、前后端对接。
- **作用**：全局地图，颗粒度停在宏观架构层面。

### C2. 技术选型与取舍（Tech Selection）
- **内容**：从"业务功能 → 技术依赖"角度，对每个关键依赖回答：为支撑哪个业务功能引入？为什么需要？有无替代方案？当前选型的优缺点？
- **作用**：建立"技术选型背后的取舍判断"，而不只是知道用了什么。

### C3. 模块功能职责（Module Responsibilities）
- **内容**：逐一讲清每个模块负责什么、不负责什么、对外提供什么。
- **作用**：明确每块代码在系统里的角色。
