## 一、职责划分与设计决策

### 分层：与 Day 11 / 12 / 13 同构

| 层 | 类 | 职责 |
|---|---|---|
| Controller | `HistoryController` | 收参数、文档标注、一行委托 |
| Service | `FlowableHistoryService` / `Impl` | 拼历史查询条件 + 转 VO |
| 持久层 | **没有** | `ACT_HI_*` 全归引擎管，同 Day 11/12/13 |

本块只注入**一个**门面（`HistoryService`），且是纯读——没有 `Authentication`、没有 `try/finally`、没有 `assertCanOperate`（01 文档⑦）。是四块里最单纯的一块。

### 接口契约（2 个端点，路由前缀 `/history`）

| 方法 | 路径 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/approved` | `current` / `size` | `R<IPage<ApprovedTaskVO>>` | 我的已审批（分页） |
| GET | `/instance/{instanceId}/activities` | 路径参数 | `R<List<ActivityTraceVO>>` | 实例历史轨迹（不分页） |

### 设计决策的理由

- **`ApprovedTaskVO` 不继承 `TaskVO`**：这是与 Day 13 的关键对照点。Day 13 让 `TaskFormVO extends TaskVO`，因为两者**同源**（都吃 `org.flowable.task.api.Task`）。本块的已审批吃的是 `org.flowable.task.api.history.HistoricTaskInstance`——**不同源的类**，字段还差着（多 `endTime`/`durationInMillis`，少 `suspended`）。硬继承要在父类塞两套 `fill`、还得处理类型分叉，反而更脏。**同源才继承，不同源就独立**——别为了"看起来像"强行复用。
- **轨迹返回 `List` 不分页**：一条流程的节点数天然有限（十几个撑死），分页无意义，也就不套 MP `Page` 外壳。这是本块唯一"不套 `toPage`"的地方，和"实例列表要分页"要区分开——**分页与否看数据量级，不是一刀切**。
- **我的已审批加 `.finished()`**：HI 边跑边写，不加这个条件会把"正等我办、还没办完"的任务历史行也带出来（`END_TIME_` 为 null）。已审批要的是办结的（01 文档④）。
- **轨迹接口不校验调用者**：读操作，Demo 阶段可接受（01 文档⑦）。要收紧时接缝就在 Service 那一个方法，不提前加。
- **`DELETE_REASON_` 带进 VO**：让前端能区分"已完成 / 已终止"（01 文档⑥）。任务级和活动级都可能有（终止时正在办的任务/节点会带删除原因）。

## 二、完整代码

### 文件 1：`dto/response/ApprovedTaskVO.java`

```java
package com.ha.pr.flowwork.dto.response;

import com.fasterxml.jackson.annotation.JsonFormat;
import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;
import org.flowable.task.api.history.HistoricTaskInstance;

import java.util.Date;

/**
 * 我的已审批：一条办结的历史任务。
 * 数据源是 HistoricTaskInstance（不是 Task），所以不继承 TaskVO——不同源，独立即可（02 文档设计决策）。
 */
@Data
@Schema(description = "已审批任务（历史）")
public class ApprovedTaskVO {

    @Schema(description = "任务 id")
    private String id;

    @Schema(description = "任务名称（BPMN userTask 的 name）")
    private String name;

    @Schema(description = "任务节点 key（BPMN userTask 的 id）")
    private String taskDefinitionKey;

    @Schema(description = "办理人 userId（ACT_HI_TASKINST.ASSIGNEE_，Day 13 自动认领写入）")
    private String assignee;

    @Schema(description = "所属流程实例 id")
    private String processInstanceId;

    @Schema(description = "所用流程定义 id（含版本）")
    private String processDefinitionId;

    @Schema(description = "任务创建时间")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date startTime;

    @Schema(description = "办结时间")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date endTime;

    @Schema(description = "耗时（毫秒；前端自行换算成可读时长）")
    private Long durationInMillis;

    @Schema(description = "删除原因：正常办结为 null，任务因实例终止而结束时有值")
    private String deleteReason;

    public static ApprovedTaskVO of(HistoricTaskInstance task) {
        ApprovedTaskVO vo = new ApprovedTaskVO();
        vo.setId(task.getId());
        vo.setName(task.getName());
        vo.setTaskDefinitionKey(task.getTaskDefinitionKey());
        vo.setAssignee(task.getAssignee());
        vo.setProcessInstanceId(task.getProcessInstanceId());
        vo.setProcessDefinitionId(task.getProcessDefinitionId());
        vo.setStartTime(task.getStartTime());
        vo.setEndTime(task.getEndTime());
        vo.setDurationInMillis(task.getDurationInMillis());
        vo.setDeleteReason(task.getDeleteReason());
        return vo;
    }
}
```

### 文件 2：`dto/response/ActivityTraceVO.java`

```java
package com.ha.pr.flowwork.dto.response;

import com.fasterxml.jackson.annotation.JsonFormat;
import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;
import org.flowable.engine.history.HistoricActivityInstance;

import java.util.Date;

/**
 * 历史轨迹的一个节点：流程经过的一个活动（startEvent / userTask / endEvent…）。
 * END_TIME_ 为 null 表示流程当前正停在这个节点（实例还活着时查得到）。
 */
@Data
@Schema(description = "流程活动轨迹节点")
public class ActivityTraceVO {

    @Schema(description = "活动 id（BPMN 节点的 id，如 startEvent / managerApprove；前端据此高亮流程图）")
    private String activityId;

    @Schema(description = "活动名称（BPMN 节点的 name）")
    private String activityName;

    @Schema(description = "活动类型：startEvent / userTask / endEvent / exclusiveGateway…")
    private String activityType;

    @Schema(description = "该节点的办理人 userId（仅 userTask 有值）")
    private String assignee;

    @Schema(description = "进入该节点的时间")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date startTime;

    @Schema(description = "离开该节点的时间；为 null 表示流程当前正停在此节点")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date endTime;

    @Schema(description = "在该节点停留的耗时（毫秒）")
    private Long durationInMillis;

    public static ActivityTraceVO of(HistoricActivityInstance a) {
        ActivityTraceVO vo = new ActivityTraceVO();
        vo.setActivityId(a.getActivityId());
        vo.setActivityName(a.getActivityName());
        vo.setActivityType(a.getActivityType());
        vo.setAssignee(a.getAssignee());
        vo.setStartTime(a.getStartTime());
        vo.setEndTime(a.getEndTime());
        vo.setDurationInMillis(a.getDurationInMillis());
        return vo;
    }
}
```

### 文件 3：`service/FlowableHistoryService.java` + `impl/FlowableHistoryServiceImpl.java`

```java
package com.ha.pr.flowwork.service;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ha.pr.flowwork.dto.response.ActivityTraceVO;
import com.ha.pr.flowwork.dto.response.ApprovedTaskVO;

import java.util.List;

/**
 * 历史查询（纯读）。
 * 名字带 Flowable 前缀是为了躲开引擎的 org.flowable.engine.HistoryService（Impl 里要注入它），见 01 文档③。
 */
public interface FlowableHistoryService {

    /** 我的已审批：当前用户办结（ASSIGNEE_ = 我 且 END_TIME_ 有值）的历史任务 */
    IPage<ApprovedTaskVO> approved(long current, long size);

    /** 实例历史轨迹：一条实例走过的活动节点，按进入时间升序（活着的实例也能查） */
    List<ActivityTraceVO> activities(String instanceId);
}
```

```java
package com.ha.pr.flowwork.service.impl;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ha.pr.flowwork.dto.response.ActivityTraceVO;
import com.ha.pr.flowwork.dto.response.ApprovedTaskVO;
import com.ha.pr.flowwork.service.FlowableHistoryService;
import com.ha.pr.flowwork.util.UserContext;
import jakarta.annotation.Resource;
import org.flowable.engine.HistoryService;
import org.flowable.engine.history.HistoricActivityInstance;
import org.flowable.task.api.history.HistoricTaskInstance;
import org.flowable.task.api.history.HistoricTaskInstanceQuery;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class FlowableHistoryServiceImpl implements FlowableHistoryService {

    /** 历史域门面：ACT_HI_* 的只读查询 */
    @Resource
    private HistoryService historyService;

    @Override
    public IPage<ApprovedTaskVO> approved(long current, long size) {
        // taskAssignee 查 ACT_HI_TASKINST.ASSIGNEE_（Day 13 自动认领写入的值）；
        // finished() 排除"正等我办、还没办完"的行（HI 边跑边写，未完成任务 END_TIME_ 为 null）
        HistoricTaskInstanceQuery query = historyService.createHistoricTaskInstanceQuery()
                .taskAssignee(UserContext.userId())
                .finished()
                .orderByHistoricTaskInstanceEndTime().desc();
        long total = query.count();
        List<HistoricTaskInstance> tasks = query.listPage((int) ((current - 1) * size), (int) size);
        Page<ApprovedTaskVO> page = new Page<>(current, size, total);
        page.setRecords(tasks.stream().map(ApprovedTaskVO::of).toList());
        return page;
    }

    @Override
    public List<ActivityTraceVO> activities(String instanceId) {
        // 按进入时间升序 = 真实流转顺序；不加 finished()，好让"当前停留节点"（END_TIME_ 为 null）也出现
        List<HistoricActivityInstance> list = historyService.createHistoricActivityInstanceQuery()
                .processInstanceId(instanceId)
                .orderByHistoricActivityInstanceStartTime().asc()
                .list();
        return list.stream().map(ActivityTraceVO::of).toList();
    }
}
```

### 文件 4：`controller/HistoryController.java`

```java
package com.ha.pr.flowwork.controller;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ha.pr.flowwork.common.R;
import com.ha.pr.flowwork.dto.response.ActivityTraceVO;
import com.ha.pr.flowwork.dto.response.ApprovedTaskVO;
import com.ha.pr.flowwork.service.FlowableHistoryService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.annotation.Resource;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@Tag(name = "流程历史", description = "我的已审批 / 实例历史轨迹")
@RestController
@RequestMapping("/history")
public class HistoryController {

    @Resource
    private FlowableHistoryService flowableHistoryService;

    @Operation(summary = "我的已审批（我办结过的历史任务）")
    @GetMapping("approved")
    public R<IPage<ApprovedTaskVO>> approved(
            @Parameter(description = "当前页，从 1 开始") @RequestParam(defaultValue = "1") long current,
            @Parameter(description = "每页条数") @RequestParam(defaultValue = "10") long size) {
        return R.ok(flowableHistoryService.approved(current, size));
    }

    @Operation(summary = "实例历史轨迹（走过的节点，按时间升序；运行中的实例也可查）")
    @GetMapping("instance/{instanceId}/activities")
    public R<List<ActivityTraceVO>> activities(
            @Parameter(description = "流程实例 id") @PathVariable String instanceId) {
        return R.ok(flowableHistoryService.activities(instanceId));
    }
}
```

## 三、坑清单（写代码时已规避，理解即可）

1. **自己的接口别叫 `HistoryService`**——Impl 里要注入引擎的 `org.flowable.engine.HistoryService`，同名必有一个得写全限定名。排期里的 `FlowableHistoryService` 就是为此（Day 13 已预告，见 01 文档③）。
2. **三个历史实体分属三个不同包**，IDE 补全时看清楚，别选错：
   - `HistoricTaskInstance` → `org.flowable.task.api.history.HistoricTaskInstance`
   - `HistoricActivityInstance` → `org.flowable.engine.history.HistoricActivityInstance`
   - `HistoricProcessInstance`（本块没直接用，将来做历史实例列表要用）→ `org.flowable.engine.history.HistoricProcessInstance`
3. **`.finished()` 不能省**——不加它，"正等我办、还没办完"的任务（`END_TIME_` 为 null）会混进「我的已审批」。已审批要办结的（01 文档④）。反过来，**轨迹接口故意不加** `finished()`，是为了让"当前停留的节点"也出现。
4. **`durationInMillis` 是毫秒的 `Long`**——不是秒、也不是格式化字符串。前端拿到自己换算成"3 分钟""2 天"。VO 里保持原始毫秒，别在后端猜前端要的格式。
5. **轨迹里没有连线（sequenceFlow）**——`ACT_HI_ACTINST` 只记节点（event/task/gateway），不记 `flow1`/`flow2`。前端画高亮流程图时，连线是 BPMN 静态就画好的，只有节点按 `activityId` 动态染色。别指望这个接口返回箭头。
6. **排序用 `START_TIME_` 升序**——这才是流转顺序。若并发分支同一时刻进多个节点，start time 排序也够用（Demo 的 leave 是纯串行，无分支）。
7. **`orderBy...` 后面一定跟 `.asc()` / `.desc()`**——Flowable 的排序是两段式，只写 `orderByHistoricTaskInstanceEndTime()` 不跟方向会抛异常。别漏。
8. **历史级别（history level）得是 `audit` 或更高**——本项目用引擎默认级别，任务/变量/活动都记全，这些接口才有数据。若哪天为省空间调成 `none`，接口会集体查空——那是配置问题，不是这段代码的 bug（01 文档②）。
