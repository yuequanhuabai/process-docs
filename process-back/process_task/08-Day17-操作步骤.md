## Step 1 · `TaskVO.java`：补 3 个字段（只加声明，不动方法）

**做什么**：加 `processDefinitionName` / `businessKey` / `startUserName` 三个 `String` 字段，各配 `@Schema`（description 写清来源，knife4j 上这行字就是前端的接口文档）。

**不做什么（这步的重点其实是忍住）**：

- **`of()` / `fill()` 一行都不加**。`Task` 对象上没有这三样，你在 `fill()` 里能写出来的任何取值代码都必然是逐条查库——那就是 N+1 的第一步。字段声明出来先空着，由 Step 3 的 `enrich()` 批量填。
- `TaskFormVO` **不用动**：它 `extends TaskVO`，三个字段自动继承。

**建议**：三个新字段单独一段、上面加一行注释说明「ACT_RU_TASK 上没有，由 enrich() 批量回填」——半年后回来看的人（还是你）才知道为什么工厂方法不填它们。

**自测**：编译通过；knife4j 重启后 `TaskVO` 的 schema 里能看到三个新字段（值还是 null，正常）。

## Step 3 · 新增私有方法 `enrich(List<TaskVO> vos)`

**做什么**：两段批量查询 + 一个回填循环，整页固定 2 次库访问。

**怎么写（引导）**：

1. **开头判空**：`vos.isEmpty()` 直接 return（后面两段的批量 in 都吃不得空集合）。
2. **① 段：任务 → 所属实例**：
   - 流收集所有 `getProcessInstanceId()` → `Set<String>`（任务的 instanceId 非空，不用 filter）
   - `runtimeService.createProcessInstanceQuery().processInstanceIds(ids).list()` 一次查出
   - 转 `Map<String, ProcessInstance>`，key 用 `getId()`，value 就是实例自己（`i -> i`）
   - ⚠️ **方法名别照抄 Day 16**：`TaskQuery` 上叫 `processInstanceIdIn(List)`，`ProcessInstanceQuery` 上叫 **`processInstanceIds(Set)`**——名字、参数类型都不同，IDE 补全确认再写。
3. **② 段：发起人姓名**：从①段的 `Map.values()` 流收集 `getStartUserId()` → 后面**整段照 Day 16 `ProcessInstanceServiceImpl.enrich()` 的①段抄**，四个坑一个不少地带上：
   - `filter(Objects::nonNull)` 再 `Long.valueOf`（START_USER_ID_ 是 Long 的字符串形态，查库前转 Long、转 Map 时 `String.valueOf` 转回来，两头都要转）
   - 空集合短路成 `Map.of()`（MP 的 `in()` 遇空集合拼非法 SQL）
   - `Collectors.toMap` 的 value **不能**直接 `SysUser::getRealName`（real_name 可空，toMap 遇 null value 直接 NPE 整页 500）——`u -> u.getRealName() == null ? u.getUsername() : u.getRealName()` 兜底
   - 这段与 Day 16 重复是**已知且故意的**（07 第四节），别在这次顺手抽公共方法
4. **回填循环**：遍历 `vos`，从①段 Map 取实例——**取不到就 `continue`**（理论上不会发生：任务在 RU 其实例必在 RU，但防御一手，免得哪天引擎行为变了整页 NPE）；取到就 set 三个字段，`startUserName` 从②段 Map 里 get。

**自测**：编译过。此时还没人调用 `enrich()`，IDE 会给"方法未使用"的灰色提示，正常。

## Step 4 · 挂上 `enrich()`：`toPage()` 和 `detail()` 两处

**做什么**：

1. `toPage()` 的 `page.setRecords(...)` 之后、`return` 之前加一行 `enrich(page.getRecords())`——列表走这里。
2. `detail()` 把现在的一行 return 拆成三行：先 `TaskFormVO vo = TaskFormVO.of(task, variables)`，然后 `enrich(List.of(vo))`，再 `return vo`——弹窗只读区的「流程 / 节点」「业务标识」靠这步。

**坑**：

- **`detail()` 最容易漏**。漏了不报错、列表还正常，只有打开弹窗才发现流程名是空的——而且你要是先测列表后测详情，会误以为是前端渲染问题。
- `enrich(List.of(vo))` 要**直接写在实参位置**。Java 会按目标类型把 `List.of(vo)` 推断成 `List<TaskVO>`；但如果先 `var list = List.of(vo)` 再传，`list` 被推成 `List<TaskFormVO>`，塞不进 `List<TaskVO>` 参数（泛型不协变），平白多一个编译错。
- `complete()` / `getTaskOrThrow()` / `assertCanOperate()` **一个字不动**。

**自测**：编译全绿。全项目搜一下 `enrich(`——应该恰好 2 个调用点（toPage、detail）。
