## 1. `dto/response/TaskVO.java`（完整替换）

> 变化只有中间那段「Day 17 补的三个字段」；`of()` / `fill()` 与库里现状逐字相同。

```java
package com.ha.pr.flowwork.dto.response;

import com.fasterxml.jackson.annotation.JsonFormat;
import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;
import org.flowable.task.api.Task;

import java.util.Date;

@Data
@Schema(description = "待办任务")
public class TaskVO {
    @Schema(description = "任务 id（引擎生成，天生字符串）")
    private String id;

    @Schema(description = "任务名称（BPMN userTask 的 name）")
    private String name;

    @Schema(description = "任务节点 key（BPMN userTask 的 id）")
    private String taskDefinitionKey;

    @Schema(description = "办理人 userId；候选组任务未认领时为 null")
    private String assignee;

    @Schema(description = "所属流程实例 id")
    private String processInstanceId;

    @Schema(description = "所用流程定义 id（含版本）")
    private String processDefinitionId;

    @Schema(description = "任务创建时间")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date createTime;

    @Schema(description = "是否挂起（随流程实例）")
    private boolean suspended;

    // ===== Day 17 补的三个字段（07 文档）：ACT_RU_TASK 上没有这些数据，
    //       来自所属实例与 sys_user，由 FlowableTaskServiceImpl.enrich() 批量回填。
    //       ⚠️ 别在 of()/fill() 里试图填它们——工厂方法里拿不到，逐条查就是 N+1 =====
    @Schema(description = "流程定义名称（如「报销流程」，来自所属实例）")
    private String processDefinitionName;

    @Schema(description = "业务标识（发起时选填；未填为 null，前端拿 — 占位）")
    private String businessKey;

    @Schema(description = "发起人姓名（sys_user.real_name，无姓名回退 username）")
    private String startUserName;

    public static TaskVO of(Task task) {
        TaskVO vo = new TaskVO();
        fill(vo, task);
        return vo;
    }

    /** 供子类 TaskFormVO 复用父类字段填充（同 LoginVO extends UserInfoVO 的路子） */
    protected static void fill(TaskVO vo, Task task) {
        vo.setId(task.getId());
        vo.setName(task.getName());
        vo.setTaskDefinitionKey(task.getTaskDefinitionKey());
        vo.setAssignee(task.getAssignee());
        vo.setProcessInstanceId(task.getProcessInstanceId());
        vo.setProcessDefinitionId(task.getProcessDefinitionId());
        vo.setCreateTime(task.getCreateTime());
        vo.setSuspended(task.isSuspended());
    }
}
```

> `TaskFormVO extends TaskVO`，三个新字段自动继承，详情接口的出参不需要另改。

## 2. `service/impl/FlowableTaskServiceImpl.java`（完整替换）

> `todo()` / `complete()` / `getTaskOrThrow()` / `assertCanOperate()` 原样未动。
> 新增：`RuntimeService` / `SystemUserMapper` 两个依赖 + `enrich()`；`toPage()` 末尾一行、`detail()` 拆三行。

```java
package com.ha.pr.flowwork.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ha.pr.flowwork.common.BizException;
import com.ha.pr.flowwork.dto.request.CompleteTaskRequest;
import com.ha.pr.flowwork.dto.response.TaskFormVO;
import com.ha.pr.flowwork.dto.response.TaskVO;
import com.ha.pr.flowwork.entity.SysUser;
import com.ha.pr.flowwork.mapper.SystemUserMapper;
import com.ha.pr.flowwork.service.FlowableTaskService;
import com.ha.pr.flowwork.util.UserContext;
import jakarta.annotation.Resource;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.RuntimeService;
import org.flowable.engine.TaskService;
import org.flowable.engine.runtime.ProcessInstance;
import org.flowable.task.api.Task;
import org.flowable.task.api.TaskQuery;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;
import java.util.Objects;
import java.util.Set;
import java.util.stream.Collectors;

@Service
@Slf4j
public class FlowableTaskServiceImpl implements FlowableTaskService {

    /**
     * 任务域门面：ACT_RU_TASK / ACT_RU_IDENTITYLINK 的查询、认领与办理
     */
    @Resource
    private TaskService taskService;

    /** 运行域门面：enrich 里批量查任务所属的在途实例（拿流程名 / businessKey / 发起人 id） */
    @Resource
    private RuntimeService runtimeService;

    /** enrich 里批量把 startUserId 换成 sys_user.real_name */
    @Resource
    private SystemUserMapper systemUserMapper;

    @Override
    public IPage<TaskVO> todo(long current, long size) {
        UserContext.CurrentUser me = UserContext.get();
        TaskQuery query = taskService.createTaskQuery()
                .or()
                .taskCandidateGroup(me.getRole())
                .taskAssignee(me.getUserId())
                .endOr()
                .orderByTaskCreateTime().desc();
        return toPage(query, current, size);
    }

    @Override
    public TaskFormVO detail(String taskId) {
        Task task = getTaskOrThrow(taskId);
        assertCanOperate(task);
        // 取该任务可见的流程变量：会沿执行树向上取到实例级的 days/reason/initiator
        Map<String, Object> variables = taskService.getVariables(taskId);
        TaskFormVO vo = TaskFormVO.of(task, variables);
        // Day 17：弹窗只读区要显示「流程 / 节点」「业务标识」，详情也要补三字段。
        // ⚠️ List.of(vo) 必须直接写在实参位置——Java 按目标类型推成 List<TaskVO>；
        //    先赋给变量再传会被推成 List<TaskFormVO>，塞不进来（泛型不协变）
        enrich(List.of(vo));
        return vo;
    }

    @Override
    public void complete(CompleteTaskRequest req) {
        Task task = getTaskOrThrow(req.getTaskId());
        assertCanOperate(task);
        String userId = UserContext.userId();
        if (task.getAssignee() == null) {
            // 自动认领：把办理人落进 ASSIGNEE_，否则 Day 14「我的已审批」查不到（01 文档⑥）
            taskService.claim(task.getId(), userId);
        }
        taskService.complete(task.getId(), req.getVariables());
        log.info("任务已办理：taskId={}, taskKey={}, instanceId={}, assignee={}",
                task.getId(), task.getTaskDefinitionKey(), task.getProcessInstanceId(), userId);
    }

    /**
     * 查不到 = 不在 ACT_RU_TASK 里（id 错 / 已被办掉 / 实例已终止）；历史任务归 Day 14 查
     */
    private Task getTaskOrThrow(String taskId) {
        Task task = taskService.createTaskQuery()
                .taskId(taskId)
                .singleResult();
        if (task == null) {
            throw new BizException("待办任务不存在或已办理：" + taskId);
        }
        return task;
    }

    /**
     * 越权校验（01 文档⑧）：待办列表按角色过滤只是"看不见"，接口本身是裸的，taskId 泄漏就能越权办理。
     * 已认领 → 只有本人能操作；未认领 → 我的角色须在该任务的候选组里。
     */
    private void assertCanOperate(Task task) {
        UserContext.CurrentUser me = UserContext.get();
        if (task.getAssignee() != null) {
            if (!task.getAssignee().equals(me.getUserId())) {
                throw new BizException("该任务已被他人认领，无权操作");
            }
            return;
        }
        long hit = taskService.createTaskQuery()
                .taskId(task.getId())
                .taskCandidateGroup(me.getRole())
                .count();
        if (hit == 0) {
            throw new BizException("你不在该任务的候选办理人范围内，无权操作");
        }
    }

    /**
     * 批量回填 processDefinitionName + businessKey + startUserName（Day 17，07 文档）。
     * 整页固定 2 次查询，严禁在循环里逐条查（N+1：一页 10 条 = 20 次库访问）。
     * 方向与 ProcessInstanceServiceImpl.enrich() 相反：那边实例找任务（补当前节点），
     * 这边任务找实例（补业务上下文）。待办任务必属在途实例，所以只查 RU、不碰 HI。
     */
    private void enrich(List<TaskVO> vos) {
        if (vos.isEmpty()) {
            return;
        }
        // ① 任务 → 所属实例：ACT_RU_TASK 只有 PROC_INST_ID_ 外键，
        //    流程名 / businessKey / 发起人 id 都在实例行上。
        // ⚠️ 方法名与 Day 16 不同：TaskQuery 是 processInstanceIdIn(List)，
        //    ProcessInstanceQuery 是 processInstanceIds(Set)，名字、参数类型都不同
        Set<String> instanceIds = vos.stream()
                .map(TaskVO::getProcessInstanceId)
                .collect(Collectors.toSet());
        Map<String, ProcessInstance> instanceMap = runtimeService.createProcessInstanceQuery()
                .processInstanceIds(instanceIds)
                .list()
                .stream()
                .collect(Collectors.toMap(ProcessInstance::getId, i -> i));
        // ② 发起人姓名：与 ProcessInstanceServiceImpl.enrich() 的①段同款（已知重复，07 第四节，
        //    Day 18 出现第三份再收编）。坑也同款：两头转型 / 空集合短路 / real_name 可空兜底
        Set<Long> userIds = instanceMap.values().stream()
                .map(ProcessInstance::getStartUserId)
                .filter(Objects::nonNull)
                .map(Long::valueOf)
                .collect(Collectors.toSet());
        // MP 的 in() 遇空集合会拼出非法 SQL（IN ()），必须判空短路
        Map<String, String> nameMap = userIds.isEmpty() ? Map.of()
                : systemUserMapper.selectList(
                        new LambdaQueryWrapper<SysUser>().in(SysUser::getId, userIds))
                    .stream()
                    // ⚠️ 不能直接写 SysUser::getRealName：Collectors.toMap 的 value 为 null
                    //    直接抛 NPE（HashMap.merge），而 real_name 列可空——兜底回退 username
                    .collect(Collectors.toMap(
                            u -> String.valueOf(u.getId()),
                            u -> u.getRealName() == null ? u.getUsername() : u.getRealName()));
        for (TaskVO vo : vos) {
            ProcessInstance instance = instanceMap.get(vo.getProcessInstanceId());
            if (instance == null) {
                continue;   // 理论不会发生：任务在 RU 其实例必在 RU；防御一手免得整页 NPE
            }
            vo.setProcessDefinitionName(instance.getProcessDefinitionName());
            vo.setBusinessKey(instance.getBusinessKey());
            vo.setStartUserName(nameMap.get(instance.getStartUserId()));
        }
    }

    /**
     * count() + listPage() 装进 MP Page 外壳，同 Day 11/12 的套路。
     * Day 17 起末尾加挂 enrich()——漏掉不会编译报错，只会让三个新字段整页全空
     */
    private IPage<TaskVO> toPage(TaskQuery query, long current, long size) {
        long total = query.count();
        List<Task> tasks = query.listPage((int) ((current - 1) * size), (int) size);
        Page<TaskVO> page = new Page<>(current, size, total);
        page.setRecords(tasks.stream().map(TaskVO::of).toList());
        enrich(page.getRecords());
        return page;
    }
}
```
