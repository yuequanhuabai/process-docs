# 02 · 前置任务与完整代码

> 本文包含**可直接使用的完整代码**（5 个新文件），复制进项目、`mvnw compile` 通过即可进入 `03-操作步骤`。对应排期 Day 13「待办任务接口」。

---

## 一、职责划分与设计决策

### 分层：与 Day 11 / 12 同构

| 层 | 类 | 职责 |
|---|---|---|
| Controller | `TaskController` | 收参数、文档标注、一行委托 |
| Service | `FlowableTaskService` / `Impl` | 越权校验 + 认领 + 调 `TaskService` |
| 持久层 | **没有** | `ACT_RU_TASK` 全归引擎管，同 Day 11/12 |

本块只注入**一个**门面（`TaskService`）——Day 12 那种"组合两个门面"不是常态，按需即可。

### 接口契约（3 个端点，路由前缀 `/task`）

| 方法 | 路径 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/todo` | `current` / `size` | `R<IPage<TaskVO>>` | 我的待办 |
| GET | `/{taskId}` | 路径参数 | `R<TaskFormVO>` | 任务详情 + 流程变量 |
| POST | `/complete` | JSON body：`taskId`（必填）+ `variables`（可选） | `R<Void>` | 办理 |

### 设计决策的理由

- **`complete` 内自动认领，不单列 claim 端点**：排期只要"待办/办理/表单"三件事。不认领直接 complete 会让 `ACT_HI_TASKINST.ASSIGNEE_` 留 null，**Day 14 的「我的已审批」直接废掉**（01 文档⑥）。自动认领一次调用搞定，既保证历史有人名，又不给前端多加按钮。**代价**：没有"认领池"语义（认领后先占着、稍后再办）。若 Day 17 的 UI 确实需要，再补 `claim` / `unclaim` 一对端点，届时待办查询要加 `.includeAssignedTasks()`（见坑 3）。
- **`TaskFormVO extends TaskVO`**：详情 = 列表项 + 变量 + formKey，字段是真包含关系，沿用你已有的 `LoginVO extends UserInfoVO` 惯例，父类出 `protected static fill()` 供子类复用填充。这与 Day 12 砍掉 `MyStartedVO` 不矛盾——那个是**字段完全重合**（该砍），这个是**真的多出东西**（该继承）。
- **待办查询用 `or()` 两条腿**：`taskCandidateGroup(role)`（池子里的）**或** `taskAssignee(userId)`（指派给我的）。只写第一条腿，将来 BPMN 里直接写 `flowable:assignee` 的节点就永远进不了待办；只写第二条腿，候选组任务永远看不见。
- **候选组 = 当前用户的 `role`**：不启用 `ACT_ID_*`，直接把 `UserContext.get().getRole()` 当组名传（01 文档⑤）。已知局限：一个用户只能属于一个组。
- **`complete` 不接 `Authentication`**：`claim` 已把办理人显式写进 `ASSIGNEE_`，历史归档取的是该字段，不经引擎 ThreadLocal（01 文档⑦）。别照抄 Day 12 的 `try/finally`——那是 cargo-cult。
- **越权校验放 Service 不放 Controller**：`detail` 和 `complete` 都要，放 Service 里做成私有方法两处复用；Controller 保持"一行委托"的薄。

```java
import io.swagger.v3.oas.annotations.media.Schema;

 * 办理任务入参。配合 Controller 的 @Valid 生效：taskId 缺失 → 400 统一 R 错误。
 */
@Data

    @Schema(description = "任务 id（从 /task/todo 列表里取）", example = "7ccc5cf1-7f5d-11f1-8ded-5eea1d7fcc1d")

    @Schema(description = "办理时写入的流程变量（如审批结论），可选。值建议用 string/number/boolean 基本类型",

}
```

### 文件 2：`dto/response/TaskVO.java`

```java
package com.ha.pr.flowwork.dto.response;

import com.fasterxml.jackson.annotation.JsonFormat;
import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;
import org.flowable.task.api.Task;

import java.util.Date;

@Data
@Schema(description = "待办任务")
public class TaskVO {

    @Schema(description = "任务 id（引擎生成，天生字符串）")
    private String id;

    @Schema(description = "任务名称（BPMN userTask 的 name）")
    private String name;

    @Schema(description = "任务节点 key（BPMN userTask 的 id）")
    private String taskDefinitionKey;

    @Schema(description = "办理人 userId；候选组任务未认领时为 null")
    private String assignee;

    @Schema(description = "所属流程实例 id")
    private String processInstanceId;

    @Schema(description = "所用流程定义 id（含版本）")
    private String processDefinitionId;

    @Schema(description = "任务创建时间")
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private Date createTime;

    @Schema(description = "是否挂起（随流程实例）")
    private boolean suspended;

    public static TaskVO of(Task task) {
        TaskVO vo = new TaskVO();
        fill(vo, task);
        return vo;
    }

    /** 供子类 TaskFormVO 复用父类字段填充（同 LoginVO extends UserInfoVO 的路子） */
    protected static void fill(TaskVO vo, Task task) {
        vo.setId(task.getId());
        vo.setName(task.getName());
        vo.setTaskDefinitionKey(task.getTaskDefinitionKey());
        vo.setAssignee(task.getAssignee());
        vo.setProcessInstanceId(task.getProcessInstanceId());
        vo.setProcessDefinitionId(task.getProcessDefinitionId());
        vo.setCreateTime(task.getCreateTime());
        vo.setSuspended(task.isSuspended());
    }
}
```

```java
package com.ha.pr.flowwork.dto.response;

    @Schema(description = "流程变量：申请内容（days / reason / initiator…），前端据此渲染只读区")

    @Schema(description = "BPMN userTask 上的 formKey；本项目暂未使用（表单设计器是 P6 的活），当前恒为 null")

        TaskFormVO vo = new TaskFormVO();
        fill(vo, task);
        vo.setVariables(variables);
        vo.setFormKey(task.getFormKey());
        return vo;
    }
```

```java
package com.ha.pr.flowwork.service.impl;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ha.pr.flowwork.common.BizException;
import com.ha.pr.flowwork.dto.request.CompleteTaskRequest;
import com.ha.pr.flowwork.dto.response.TaskFormVO;
import com.ha.pr.flowwork.dto.response.TaskVO;
import com.ha.pr.flowwork.service.FlowableTaskService;
import com.ha.pr.flowwork.util.UserContext;
import jakarta.annotation.Resource;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.TaskService;
import org.flowable.task.api.Task;
import org.flowable.task.api.TaskQuery;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;

@Slf4j
@Service
public class FlowableTaskServiceImpl implements FlowableTaskService {

    /** 任务域门面：ACT_RU_TASK / ACT_RU_IDENTITYLINK 的查询、认领与办理 */
    @Resource
    private TaskService taskService;

    @Override
    public IPage<TaskVO> todo(long current, long size) {
        UserContext.CurrentUser me = UserContext.get();
        // or() 两条腿：① 候选组 = 我的角色（池子里没人认领的）② 已认领/直接指派给我的
        // 缺 ①：候选组任务永远看不见；缺 ②：BPMN 里写 flowable:assignee 的节点永远进不了待办
        TaskQuery query = taskService.createTaskQuery()
                .or()
                    .taskCandidateGroup(me.getRole())
                    .taskAssignee(me.getUserId())
                .endOr()
                .orderByTaskCreateTime().desc();
        return toPage(query, current, size);
    }

    @Override
    public TaskFormVO detail(String taskId) {
        Task task = getTaskOrThrow(taskId);
        assertCanOperate(task);
        // 取该任务可见的流程变量：会沿执行树向上取到实例级的 days/reason/initiator
        Map<String, Object> variables = taskService.getVariables(taskId);
        return TaskFormVO.of(task, variables);
    }

    @Override
    public void complete(CompleteTaskRequest req) {
        Task task = getTaskOrThrow(req.getTaskId());
        assertCanOperate(task);
        String userId = UserContext.userId();
        if (task.getAssignee() == null) {
            // 自动认领：把办理人落进 ASSIGNEE_，否则 Day 14「我的已审批」查不到（01 文档⑥）
            taskService.claim(task.getId(), userId);
        }
        taskService.complete(task.getId(), req.getVariables());
        log.info("任务已办理：taskId={}, taskKey={}, instanceId={}, assignee={}",
                task.getId(), task.getTaskDefinitionKey(), task.getProcessInstanceId(), userId);
    }

    /** 查不到 = 不在 ACT_RU_TASK 里（id 错 / 已被办掉 / 实例已终止）；历史任务归 Day 14 查 */
    private Task getTaskOrThrow(String taskId) {
        Task task = taskService.createTaskQuery()
                .taskId(taskId)
                .singleResult();
        if (task == null) {
            throw new BizException("待办任务不存在或已办理：" + taskId);
        }
        return task;
    }

    /**
     * 越权校验（01 文档⑧）：待办列表按角色过滤只是"看不见"，接口本身是裸的，taskId 泄漏就能越权办理。
     * 已认领 → 只有本人能操作；未认领 → 我的角色须在该任务的候选组里。
     */
    private void assertCanOperate(Task task) {
        UserContext.CurrentUser me = UserContext.get();
        if (task.getAssignee() != null) {
            if (!task.getAssignee().equals(me.getUserId())) {
                throw new BizException("该任务已被他人认领，无权操作");
            }
            return;
        }
        long hit = taskService.createTaskQuery()
                .taskId(task.getId())
                .taskCandidateGroup(me.getRole())
                .count();
        if (hit == 0) {
            throw new BizException("你不在该任务的候选办理人范围内，无权操作");
        }
    }

    /** count() + listPage() 装进 MP Page 外壳，同 Day 11/12 的套路 */
    private IPage<TaskVO> toPage(TaskQuery query, long current, long size) {
        long total = query.count();
        List<Task> tasks = query.listPage((int) ((current - 1) * size), (int) size);
        Page<TaskVO> page = new Page<>(current, size, total);
        page.setRecords(tasks.stream().map(TaskVO::of).toList());
        return page;
    }
}
```

### 文件 5：`controller/TaskController.java`

```java
package com.ha.pr.flowwork.controller;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ha.pr.flowwork.common.R;
import com.ha.pr.flowwork.dto.request.CompleteTaskRequest;
import com.ha.pr.flowwork.dto.response.TaskFormVO;
import com.ha.pr.flowwork.dto.response.TaskVO;
import com.ha.pr.flowwork.service.FlowableTaskService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.annotation.Resource;
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.*;

@Tag(name = "待办任务", description = "我的待办 / 任务详情 / 办理")
@RestController
@RequestMapping("/task")
public class TaskController {

    @Resource
    private FlowableTaskService flowableTaskService;

    @Operation(summary = "我的待办（候选组 = 我的角色，或已指派给我）")
    @GetMapping("todo")
    public R<IPage<TaskVO>> todo(
            @Parameter(description = "当前页，从 1 开始") @RequestParam(defaultValue = "1") long current,
            @Parameter(description = "每页条数") @RequestParam(defaultValue = "10") long size) {
        return R.ok(flowableTaskService.todo(current, size));
    }

    @Operation(summary = "任务详情（含流程变量，办理前拉取）")
    @GetMapping("{taskId}")
    public R<TaskFormVO> detail(
            @Parameter(description = "任务 id") @PathVariable String taskId) {
        return R.ok(flowableTaskService.detail(taskId));
    }

    @Operation(summary = "办理任务（未认领则自动认领后办理）")
    @PostMapping("complete")
    public R<Void> complete(@RequestBody @Valid CompleteTaskRequest req) {
        flowableTaskService.complete(req);
        return R.ok();
    }
}
```

## 三、坑清单（写代码时已规避，理解即可）

1. **自己的接口别叫 `TaskService`**——Impl 里要注入引擎的 `org.flowable.engine.TaskService`，同名必有一个得写全限定名。排期里的 `FlowableTaskService` 就是为此。Day 14 的 `FlowableHistoryService` 同理。
2. **`Task` 的包是 `org.flowable.task.api.Task`**，不是 `org.flowable.engine.task.Task`（那是 Flowable 5 的老包，网上老文章满地都是）。`TaskQuery` 同样在 `org.flowable.task.api`。IDE 补全时看清楚。
3. **`taskCandidateGroup()` 默认排除已认领的任务**——这是 Flowable 的既定行为。本块因为"认领+办理"在一次调用里原子完成，池子里不存在"已认领未办理"的中间态，所以不受影响。**但**将来若补显式 `claim` 端点，认领后任务会从候选查询里凭空消失（用户会说"我刚认领的活不见了"），那时要加 `.includeAssignedTasks()`。
4. **`/task/todo` 和 `/task/{taskId}` 都是 GET，不会打架**——Spring 的路径匹配里**字面量优先级高于路径变量**，`/task/todo` 稳定命中 `todo()`。知道原因比碰运气强；真觉得别扭可以改成 `/task/detail/{taskId}`。
5. **`complete` 不需要 `Authentication`**——`claim` 已显式写 `ASSIGNEE_`，历史归档取该字段。别照抄 Day 12 的 `try/finally`。（例外：将来用 `taskService.addComment()` 记审批意见时才需要，comment 的 `USER_ID_` 取自 `Authentication`。）
6. **variables 仍守基本类型**——同 Day 12 坑 4，`approved`/`comment` 用 boolean/string，落 `ACT_RU_VARIABLE` 的类型列，SQL 里肉眼可读。
7. **办完 leave 流程直接结束**——它只有一个审批节点，complete 后令牌撞 endEvent，整条实例的 `ACT_RU_*` 全清。**"任务和实例一起消失"是对的**，不是把数据办丢了，去 `ACT_HI_*` 找（01 文档⑦⑨）。
8. **越权校验不能省**——待办列表过滤只是"看不见"，`complete` 接口是裸的。employee 拿到 taskId 就能替 manager 批假。这是本块唯一的安全点。
9. **`getVariables` vs `getVariablesLocal`**——前者沿执行树向上取（能拿到实例级的 days/reason），后者只取任务自己那层（本块场景下会是空的）。要的是前者。
