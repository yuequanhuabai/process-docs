## 二、故障排查手册

### B1 · 启动就失败
- **建表 SQL 报错**：确认库是空的（上次手动删表可能删了一半）。最干净的处理：跑 `sql/00_reset_db.sql` 整库重建 + 重跑业务建表脚本，或把残余 `ACT_*` 表删干净再启动。
- **提示 schema 版本相关错误**：`ACT_GE_PROPERTY` 和其他表状态不一致（比如只删了部分表）。同上，清干净重来。

### B2 · 启动日志里出现了自动部署
`check-process-definitions` 不是 `false`——检查 `application.yml` 是否被改回，或 IDEA 跑的不是最新配置（重新 build / 确认 active profile 是 dev）。

### B3 · 所有接口都 401
- token 没带上：Authorize 里是否粘的是 `data.token` 的裸值（swagger 的 bearerAuth 模式**不要**自己写 `Bearer ` 前缀；knife4j 全局参数模式则**必须**写）。
- token 过期：重新登录换新 token。
- 分不清是谁拒绝的：401 且响应体是 `R` 结构 → `LoginInterceptor` 拒的（token 问题）；401/403 且响应体不是 `R` → 别的层（比如 Druid 监控页自己的登录）。

### B4 · 文档页没有 Authorize 按钮
`OpenApiConfig` 没按 `02` 文件 5 替换，或改完没重启。用备用方案（全局参数设置）也能继续操作。

### B5 · deploy 返回 400「文件名必须以 .bpmn20.xml 或 .bpmn 结尾」
选的文件不对，或文件被浏览器改名。确认选的是 `src/main/resources/processes/leave.bpmn20.xml`。

### B6 · deploy 返回 500，msg 是 XML/解析类错误
XML 被改坏过（手动编辑引入了语法错误、或 sequenceFlow 引用了不存在的节点 id）。**这类失败是安全的**：引擎命令事务整体回滚，三张表不会留脏数据。用 git 恢复原始 `leave.bpmn20.xml` 重传。

### B7 · deploy 返回「部署未产生流程定义」
`<process>` 缺 `isExecutable="true"`。代码已自动清理这次空部署，改好 XML 重传即可。原理见 `01` 第⑥步。

### B8 · `ACT_GE_BYTEARRAY` 只有 xml 没有 png
- 引擎配置里关了 `createDiagramOnDeploy`（当前项目没关，默认开）；
- 或 XML 没有 DI 坐标段（`bpmndi:BPMNDiagram`）——leave 模板是带的，若你换了别的文件则属正常。
- png 存在但打开中文是方框 → 这就是 Day 10 挂起的中文字体问题，**不阻塞**，Day 31 统一处理。

### B9 · 部署"成功"、资源入库了，但 `ACT_RE_PROCDEF` 是空的
两种可能，按顺序排除：
1. 文件名后缀不对，引擎静默跳过解析（`01` 第④步）——但接口层已校验，理论上到不了这里；若绕过接口直接用别的方式部署过，会出现这种情况。
2. `isExecutable` 不为 true——正常应被接口的兜底检查抓住（B7）。
出现本情况说明库里有**孤儿部署**（有存档无定义），用 `DELETE /process-definition/deployment/{deploymentId}` 清掉。

### B10 · 删除部署报错
- 响应「删除失败：该部署下可能存在流程实例…」：这个部署的流程定义已经有实例在跑（现在还没做实例接口，正常不会出现；若出现说明之前遗留过数据）。确认真要删就带 `cascade=true`——**会连实例和历史一起删**，操作前想清楚。
- 「部署不存在」：deploymentId 传错了，注意删除用的是 **deploymentId**（部署 id），不是 definitionId（三段式那个）。
