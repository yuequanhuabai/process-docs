## 一、职责划分与设计决策

### 分层：和 SysUser 那套形似而神不同

| 层 | 类 | 职责 |
|---|---|---|
| Controller | `ProcessDefinitionController` | 收参数、`@Tag/@Operation` 文档标注、一行委托 Service |
| Service | `ProcessDefinitionService` / `Impl` | 业务校验（文件名后缀、存在性）+ 调 Flowable API |
| 持久层 | **没有！** | 不建 Entity、不建 Mapper——`RepositoryService` 就是 Flowable 提供的"仓库域 DAO"，建表、SQL、事务全由引擎管 |

这是和用户模块最大的区别：**MyBatis-Plus 管我们自己的表（`sys_user`），Flowable 管它自己的表（`ACT_*`）**，两套持久层并存互不干扰。所以 Service 不继承 `ServiceImpl`，也不需要 `@Transactional`（`deploy()` 本身是引擎的一个命令事务，见 01 文档第②步）。

### 接口契约（5 个端点，路由前缀 `/process-definition`）

| 方法 | 路径 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| POST | `/deploy` | multipart：`file`（BPMN 文件）+ `name`（可选部署名） | `R<ProcessDefinitionVO>` | 部署 |
| GET | `/page` | `current` / `size` / `latestOnly` | `R<IPage<ProcessDefinitionVO>>` | 分页列表 |
| DELETE | `/deployment/{deploymentId}` | `cascade`（默认 false） | `R<Void>` | 按部署删除 |
| PUT | `/{definitionId}/suspend` | 路径参数 | `R<Void>` | 挂起 |
| PUT | `/{definitionId}/activate` | 路径参数 | `R<Void>` | 激活 |

### 几个设计决策的理由

- **上传方式选 multipart 文件而不是 JSON 里塞 XML 字符串**：knife4j 里直接点文件选择器就能传，curl 用 `-F file=@路径` 也一行搞定；XML 塞 JSON 字符串则要处理引号/换行转义，手动操作极易出错。Day 16 前端设计器联调时若需要（bpmn-js `saveXML()` 得到的是字符串），前端把字符串包成 Blob 当文件传即可，接口不用改。
- **返回 `ProcessDefinitionVO` 而不是 `Deployment`**：调用者真正关心的是"解析出了什么流程定义"（id/key/version），部署 id 只是其中一个字段。
- **id 直接用 String**：流程定义 id 天生是 `key:version:序号` 字符串（01 文档第⑥步），不存在雪花 Long 丢精度问题，**不需要** `ToStringSerializer`。
- **分页复用 `IPage` 外壳**：Flowable 查询自带 `count()` + `listPage()`，手动装进 MyBatis-Plus 的 `Page` 对象，让前端拿到的结构和用户列表完全一致（records/total/current/size），前端 `PageResult<T>` 直接复用。
- **删除按 deploymentId 而不是 definitionId**：删除的最小单位是"一次部署"（连带它的所有资源和定义），和引擎 API `deleteDeployment` 对齐。

## 二、完整代码

### 文件 1：`dto/response/ProcessDefinitionVO.java`

```java
package com.ha.pr.flowwork.dto.response;

import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;
import org.flowable.engine.repository.ProcessDefinition;

@Data
@Schema(description = "流程定义")
public class ProcessDefinitionVO {

    @Schema(description = "流程定义 id（key:version:序号，天生字符串）")
    private String id;

    @Schema(description = "流程 key（BPMN 里 process 标签的 id，跨版本不变）")
    private String key;

    @Schema(description = "流程名称")
    private String name;

    @Schema(description = "版本号（同 key 内自增）")
    private int version;

    @Schema(description = "所属部署 id")
    private String deploymentId;

    @Schema(description = "是否挂起")
    private boolean suspended;

    @Schema(description = "BPMN 资源名（对应 ACT_GE_BYTEARRAY.NAME_）")
    private String resourceName;

    @Schema(description = "流程图 png 资源名（引擎自动生成，可能为 null）")
    private String diagramResourceName;

    public static ProcessDefinitionVO of(ProcessDefinition def) {
        ProcessDefinitionVO vo = new ProcessDefinitionVO();
        vo.setId(def.getId());
        vo.setKey(def.getKey());
        vo.setName(def.getName());
        vo.setVersion(def.getVersion());
        vo.setDeploymentId(def.getDeploymentId());
        vo.setSuspended(def.isSuspended());
        vo.setResourceName(def.getResourceName());
        vo.setDiagramResourceName(def.getDiagramResourceName());
        return vo;
    }
}
```

```java
package com.ha.pr.flowwork.service;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ha.pr.flowwork.dto.response.ProcessDefinitionVO;
import org.springframework.web.multipart.MultipartFile;

public interface ProcessDefinitionService {

    /** 部署一份 BPMN 文件，返回解析出的流程定义 */
    ProcessDefinitionVO deploy(MultipartFile file, String name);

    /** 分页查询流程定义；latestOnly=true 时每个 key 只返回最新版本 */
    IPage<ProcessDefinitionVO> page(long current, long size, boolean latestOnly);

    /** 删除一次部署（连带其资源与流程定义）；cascade=true 时级联删实例与历史 */
    void deleteDeployment(String deploymentId, boolean cascade);

    /** 挂起流程定义（禁止新实例发起） */
    void suspend(String definitionId);

    /** 激活流程定义 */
    void activate(String definitionId);
}
```

### 文件 3：`service/impl/ProcessDefinitionServiceImpl.java`

```java
package com.ha.pr.flowwork.service.impl;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ha.pr.flowwork.common.BizException;
import com.ha.pr.flowwork.dto.response.ProcessDefinitionVO;
import com.ha.pr.flowwork.service.ProcessDefinitionService;
import jakarta.annotation.Resource;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.RepositoryService;
import org.flowable.engine.repository.Deployment;
import org.flowable.engine.repository.ProcessDefinition;
import org.flowable.engine.repository.ProcessDefinitionQuery;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.util.List;

@Slf4j
@Service
public class ProcessDefinitionServiceImpl implements ProcessDefinitionService {

    /** Flowable 仓库域入口：部署与流程定义都归它管（starter 已注册为 Spring Bean，直接注入） */
    @Resource
    private RepositoryService repositoryService;

    @Override
    public ProcessDefinitionVO deploy(MultipartFile file, String name) {
        String filename = file.getOriginalFilename();
        // 引擎只解析 .bpmn20.xml / .bpmn 结尾的资源，后缀不对会"存了但不解析"（静默空部署）
        if (filename == null || !(filename.endsWith(".bpmn20.xml") || filename.endsWith(".bpmn"))) {
            throw new BizException("文件名必须以 .bpmn20.xml 或 .bpmn 结尾");
        }
        byte[] bytes;
        try {
            bytes = file.getBytes();
        } catch (IOException e) {
            throw new BizException("读取上传文件失败：" + e.getMessage());
        }
        // 用原始字节部署（不转 String），中文等编码原样保留；
        // deploy() 是一个引擎命令事务：XML 非法时三张表整体回滚
        Deployment deployment = repositoryService.createDeployment()
                .name(name != null && !name.isBlank() ? name : filename)
                .addBytes(filename, bytes)
                .deploy();
        ProcessDefinition def = repositoryService.createProcessDefinitionQuery()
                .deploymentId(deployment.getId())
                .singleResult();
        if (def == null) {
            // XML 合法但没有可执行流程（isExecutable 缺失/为 false）：deploy 已提交，
            // 不属于引擎事务回滚范围，这里手动清掉这次空部署再报错
            repositoryService.deleteDeployment(deployment.getId(), true);
            throw new BizException("部署未产生流程定义：请检查 process 标签是否有 isExecutable=\"true\"（本次空部署已清理）");
        }
        log.info("流程部署成功：deploymentId={}, definitionId={}, key={}, version={}",
                deployment.getId(), def.getId(), def.getKey(), def.getVersion());
        return ProcessDefinitionVO.of(def);
    }

    @Override
    public IPage<ProcessDefinitionVO> page(long current, long size, boolean latestOnly) {
        // Flowable 自带查询器：count() 拿总数，listPage(偏移, 条数) 拿当前页
        ProcessDefinitionQuery query = repositoryService.createProcessDefinitionQuery()
                .orderByProcessDefinitionKey().asc()
                .orderByProcessDefinitionVersion().desc();
        if (latestOnly) {
            query.latestVersion();
        }
        long total = query.count();
        List<ProcessDefinition> defs = query.listPage((int) ((current - 1) * size), (int) size);
        // 手动装进 MP 的 Page 外壳，让前端拿到与用户列表一致的 records/total/current/size 结构
        Page<ProcessDefinitionVO> page = new Page<>(current, size, total);
        page.setRecords(defs.stream().map(ProcessDefinitionVO::of).toList());
        return page;
    }

    @Override
    public void deleteDeployment(String deploymentId, boolean cascade) {
        long count = repositoryService.createDeploymentQuery()
                .deploymentId(deploymentId)
                .count();
        if (count == 0) {
            throw new BizException("部署不存在：" + deploymentId);
        }
        try {
            // cascade=false：仅删部署+资源+定义，存在关联实例时会因外键失败
            // cascade=true ：连运行中实例和历史一起删（危险，界面上应二次确认）
            repositoryService.deleteDeployment(deploymentId, cascade);
        } catch (RuntimeException e) {
            if (!cascade) {
                throw new BizException("删除失败：该部署下可能存在流程实例。确认后可用 cascade=true 级联删除（连实例与历史一起删）");
            }
            throw e;
        }
    }

    @Override
    public void suspend(String definitionId) {
        ProcessDefinition def = getDefOrThrow(definitionId);
        if (def.isSuspended()) {
            throw new BizException("流程定义已处于挂起状态");
        }
        // 简单重载：只拦"新发起"，已在途的实例不受影响
        repositoryService.suspendProcessDefinitionById(definitionId);
    }

    @Override
    public void activate(String definitionId) {
        ProcessDefinition def = getDefOrThrow(definitionId);
        if (!def.isSuspended()) {
            throw new BizException("流程定义已处于激活状态");
        }
        repositoryService.activateProcessDefinitionById(definitionId);
    }

    private ProcessDefinition getDefOrThrow(String definitionId) {
        ProcessDefinition def = repositoryService.createProcessDefinitionQuery()
                .processDefinitionId(definitionId)
                .singleResult();
        if (def == null) {
            throw new BizException("流程定义不存在：" + definitionId);
        }
        return def;
    }
}
```

### 文件 4：`controller/ProcessDefinitionController.java`

```java
package com.ha.pr.flowwork.controller;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ha.pr.flowwork.common.R;
import com.ha.pr.flowwork.dto.response.ProcessDefinitionVO;
import com.ha.pr.flowwork.service.ProcessDefinitionService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.annotation.Resource;
import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RequestPart;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;

@Tag(name = "流程定义", description = "部署 / 列表 / 删除 / 挂起 / 激活")
@RestController
@RequestMapping("/process-definition")
public class ProcessDefinitionController {

    @Resource
    private ProcessDefinitionService processDefinitionService;

    @Operation(summary = "部署流程（上传 BPMN 文件）")
    @PostMapping(value = "deploy", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
    public R<ProcessDefinitionVO> deploy(
            @Parameter(description = "BPMN 文件，文件名须以 .bpmn20.xml 或 .bpmn 结尾")
            @RequestPart("file") MultipartFile file,
            @Parameter(description = "部署名称，可选，缺省用文件名")
            @RequestParam(required = false) String name) {
        return R.ok(processDefinitionService.deploy(file, name));
    }

    @Operation(summary = "分页查询流程定义")
    @GetMapping("page")
    public R<IPage<ProcessDefinitionVO>> page(
            @Parameter(description = "当前页，从 1 开始") @RequestParam(defaultValue = "1") long current,
            @Parameter(description = "每页条数") @RequestParam(defaultValue = "10") long size,
            @Parameter(description = "true=每个 key 只看最新版本") @RequestParam(defaultValue = "false") boolean latestOnly) {
        return R.ok(processDefinitionService.page(current, size, latestOnly));
    }

    @Operation(summary = "删除部署（连带其资源与流程定义）")
    @DeleteMapping("deployment/{deploymentId}")
    public R<Void> deleteDeployment(
            @Parameter(description = "部署 id") @PathVariable String deploymentId,
            @Parameter(description = "true=级联删除该部署下的实例与历史") @RequestParam(defaultValue = "false") boolean cascade) {
        processDefinitionService.deleteDeployment(deploymentId, cascade);
        return R.ok();
    }

    @Operation(summary = "挂起流程定义（禁止新实例发起）")
    @PutMapping("{definitionId}/suspend")
    public R<Void> suspend(@Parameter(description = "流程定义 id") @PathVariable String definitionId) {
        processDefinitionService.suspend(definitionId);
        return R.ok();
    }

    @Operation(summary = "激活流程定义")
    @PutMapping("{definitionId}/activate")
    public R<Void> activate(@Parameter(description = "流程定义 id") @PathVariable String definitionId) {
        processDefinitionService.activate(definitionId);
        return R.ok();
    }
}
```

### 文件 5（可选但强烈推荐）：改 `config/OpenApiConfig.java`，给文档页加 Authorize 按钮

改完后 knife4j/swagger 页面出现 **Authorize** 按钮，登录拿到 token 粘贴一次，之后所有接口自动带 `Authorization: Bearer xxx` 头——否则每次调接口都要手动配全局参数。整文件替换：

```java
package com.ha.pr.flowwork.config;

import io.swagger.v3.oas.models.Components;
import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Contact;
import io.swagger.v3.oas.models.info.Info;
import io.swagger.v3.oas.models.security.SecurityRequirement;
import io.swagger.v3.oas.models.security.SecurityScheme;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * Knife4j / OpenAPI 3 文档配置。
 * 依赖：knife4j-openapi3-jakarta-spring-boot-starter（已在 pom）。
 * 访问（context-path = /workflow）：
 *   Knife4j  UI : http://localhost:9090/workflow/doc.html
 *   Swagger  UI : http://localhost:9090/workflow/swagger-ui.html
 *   OpenAPI JSON: http://localhost:9090/workflow/v3/api-docs
 */
@Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI workflowOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("Process-Back 工作流接口文档")
                        .description("Flowable 7 工作流引擎后端 · 流程定义/实例/任务/表单/用户")
                        .version("0.0.1-SNAPSHOT")
                        .contact(new Contact().name("process-back")))
                // Bearer 鉴权声明：文档页出现 Authorize 按钮，粘 token（不带 "Bearer " 前缀），
                // 之后每个请求自动带 Authorization: Bearer <token> 头，与 LoginInterceptor 对上
                .components(new Components().addSecuritySchemes("bearerAuth",
                        new SecurityScheme()
                                .type(SecurityScheme.Type.HTTP)
                                .scheme("bearer")
                                .bearerFormat("JWT")))
                .addSecurityItem(new SecurityRequirement().addList("bearerAuth"));
    }
}
```

## 三、坑清单（写代码时已规避，理解即可）

1. **文件名后缀决定是否解析**——后缀不对时引擎静默存档不解析，接口层必须先校验（deploy 方法第一步）。
2. **`isExecutable="false"` 不算失败**——部署提交成功但查不到定义，且不在引擎事务回滚范围内，要手动清空部署（deploy 方法的 `def == null` 分支）。
3. **用 `addBytes` 传原始字节**——别 `new String(bytes)` 再 `addString`，绕一道字符串就有编码翻车的机会。
4. **不要加 `@Transactional`**——`deploy()` 自带命令事务；套上 Spring 事务反而把引擎事务和 MP 数据源事务搅在一起（当前场景没必要）。
5. **multipart 上传大小限制**——Spring Boot 默认单文件 1MB，BPMN 文件几 KB 足够，无需改配置；将来真超了在 `application.yml` 配 `spring.servlet.multipart.max-file-size`。
6. **knife4j 里文件上传参数要用 `@RequestPart` + `consumes = MULTIPART_FORM_DATA_VALUE`**——否则文档页不出现文件选择器。
7. **新接口自动受 JWT 保护**——`/process-definition/**` 不在 `WebMvcConfig` 白名单里，调用必须带 token（这是对的，不要加白名单）。
