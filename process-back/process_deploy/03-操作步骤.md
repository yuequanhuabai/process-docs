## 步骤 2 · 登录拿 token 并授权文档页

1. 浏览器打开 `http://localhost:9090/workflow/doc.html`
2. 找到「认证」下的 `POST /auth/login`，body 填 admin 的账号密码，执行
3. 复制响应 `data.token` 的值
4. 点页面上的 **Authorize** 按钮（`02` 文件 5 改完才有），粘贴 token（**只贴 token 本身，不要自己加 `Bearer ` 前缀**，框架会加），确认

> 备用方案（没改 OpenApiConfig 时）：knife4j 左侧「文档管理 → 全局参数设置」新增参数：参数名 `Authorization`，参数值 `Bearer <token>`（这里要**手写** `Bearer ` 前缀），类型 header。

**预期**：随便调一个受保护接口（如 `GET /user/page`）返回 `code: 200` 而不是 401。

## 步骤 3 · 部署 leave.bpmn20.xml

在文档页找到「流程定义」下的 `POST /process-definition/deploy`：

- `file`：点文件选择器，选 `process-back/src/main/resources/processes/leave.bpmn20.xml`
- `name`：填 `请假流程-手动部署`（可空，空则用文件名）

**预期响应**（关注 data 里这几个字段）：

```json
{
  "code": 200,
  "data": {
    "id": "leaveProcess:1:xxxx",      ← key:version:序号 三段式
    "key": "leaveProcess",
    "name": "请假流程",                ← 来自 XML 里 process 的 name 属性
    "version": 1,                     ← 干净库第一次部署必须是 1
    "deploymentId": "xxxx",
    "suspended": false,
    "resourceName": "leave.bpmn20.xml",
    "diagramResourceName": "leave.leaveProcess.png"   ← 引擎自动画的流程图（名字以实际为准）
  }
}
```

> curl 等价操作（PowerShell 下用 `curl.exe`，在 process-back 目录执行）：
> ```
> curl.exe -s -X POST "http://localhost:9090/workflow/process-definition/deploy" ^
>   -H "Authorization: Bearer 你的token" ^
>   -F "file=@src/main/resources/processes/leave.bpmn20.xml" ^
>   -F "name=请假流程-手动部署"
> ```

## 步骤 4 · 逐张表查库验证

```sql
USE flowable_db2;

-- ① 部署登记：1 行，NAME_ 是你填的部署名
SELECT ID_, NAME_, DEPLOY_TIME_ FROM ACT_RE_DEPLOYMENT;

-- ② 资源原文：预期 2 行——xml（GENERATED_=0/NULL）+ 引擎生成的 png（GENERATED_=1）
SELECT ID_, NAME_, DEPLOYMENT_ID_, GENERATED_ FROM ACT_GE_BYTEARRAY;

-- ③ 流程定义登记：1 行，注意 ID_ 三段式、VERSION_=1、SUSPENSION_STATE_=1（激活）
SELECT ID_, KEY_, NAME_, VERSION_, DEPLOYMENT_ID_,
       RESOURCE_NAME_, DGRM_RESOURCE_NAME_, SUSPENSION_STATE_
FROM ACT_RE_PROCDEF;
```

**核对三表关联**：`ACT_GE_BYTEARRAY.DEPLOYMENT_ID_` 和 `ACT_RE_PROCDEF.DEPLOYMENT_ID_` 都等于 `ACT_RE_DEPLOYMENT.ID_`——一次部署把三张表串起来了。

## 步骤 6 ·（加餐，建议做）版本机制 + 挂起/激活 + 删除，一次体验完

1. **再部署一次同一个文件**（重复步骤 3）→ 预期返回 `version: 2`，id 变成 `leaveProcess:2:xxxx`。查 `ACT_RE_PROCDEF` 变 2 行、`ACT_RE_DEPLOYMENT` 变 2 行——**同 key 版本递增，老版本不动**。
2. 列表传 `latestOnly=true` → 只剩 version 2 那条（管理页"只看最新"就是这个开关）。
3. **挂起** version 2：`PUT /process-definition/{id}/suspend`（id 用 `leaveProcess:2:xxxx`）→ 查 `ACT_RE_PROCDEF` 该行 `SUSPENSION_STATE_` 由 1 变 2；再挂一次 → 预期报"已处于挂起状态"。
4. **激活**回来：`PUT /{id}/activate` → `SUSPENSION_STATE_` 回到 1。
5. **删除**第二次部署：`DELETE /process-definition/deployment/{deploymentId}`（用 version 2 的 deploymentId，cascade 不传）→ 列表回到只有 version 1；三张表中 version 2 的相关行全部消失。
