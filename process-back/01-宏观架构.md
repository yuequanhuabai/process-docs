# 01 · 宏观架构

> 范围：`flowable-engine-server`（后端）+ `flowable-designer-ui`（前端）。跳过 `flowable-tests`。
> 目标：用最少的篇幅讲清"系统由哪些部分组成、怎么分层、请求怎么流动"。

---

## 1. 系统定位

一个**独立的流程引擎微服务 + 配套的可视化设计器前端**。
- 后端：Spring Boot 3 + Flowable 7，对外暴露 REST 接口，负责流程定义、实例、任务、表单、历史、用户鉴权。
- 前端：Vue 3 + bpmn-js，提供流程图设计器、表单设计器，以及待办/已办/发起/历史等业务页面。
- 两者是**两个独立工程**，通过 HTTP（JSON）+ JWT 对接。

---

## 2. 顶层结构

```
core/
├── flowable-engine-server/        后端（Maven 多模块）
│   ├── flowable-common/           基础层：统一响应、异常、校验、JPA 基座
│   ├── flowable-engine/           核心层：业务逻辑、Flowable 封装、鉴权、实体
│   └── flowable-api/              启动层：Controller、Web 配置、可执行 jar 入口
└── flowable-designer-ui/          前端（Vite 单页应用）
    └── src/{api, views, components, stores, router, utils}
```

---

## 3. 后端分层（依赖单向向下）

```
flowable-api      ──依赖──>  flowable-engine  ──依赖──>  flowable-common
（对外接口/启动）            （业务/引擎封装）            （公共基座）
```

| 层 | 职责一句话 | 关键内容 |
|---|---|---|
| **flowable-common** | 谁都要用的公共件 | 统一响应 `R<T>`、全局异常处理、参数校验、JPA |
| **flowable-engine** | 真正干活的业务核心 | Service（封装 Flowable 7 的 RuntimeService/TaskService/HistoryService 等）、自有实体（用户/表单/草稿）、JWT 鉴权、引擎配置 |
| **flowable-api** | 对外的门面与启动入口 | 8 个 Controller、登录拦截器、CORS、打可执行 fat jar |

> 设计要点：**只有 `flowable-api` 是可启动模块**（含 `WorkflowApplication` 主类、JDBC 驱动、API 文档）。`engine` 和 `common` 是被依赖的库。

---

## 4. 后端内部调用链

```
HTTP 请求
  → LoginInterceptor（校验 JWT，写入 UserContext 线程上下文）
    → Controller（接收/校验入参，返回 R<T>）
      → Service（业务逻辑）
        ├─→ Flowable 引擎 API（RuntimeService / TaskService / HistoryService / RepositoryService）→ ACT_* 表
        └─→ JPA Repository（自有表：SysUser / FormDefinition / ProcessDraft）
```

**两类数据落点**：
- **Flowable 托管表**（`ACT_*`）：流程定义、实例、任务、历史，由引擎自己建表和读写（`database-schema-update: true`）。
- **自有业务表**：用户、表单定义、流程草稿，由 JPA 管理（`ddl-auto: none`，表结构走 `sql/`）。

---

## 5. 前端结构

```
src/
├── api/         按资源拆分的接口封装（auth/process/instance/task/form/history/user/draft/hrUser）
├── utils/       request.ts —— axios 实例：注入 JWT、统一拆包、401 跳登录
├── views/       业务页面：login/designer/process/instance/task/approved/myStart/history/form/user
├── components/  可复用核心组件：BpmnDesigner / FormDesigner / FormRenderer / PropertiesPanel
├── stores/      Pinia 状态：user / process
├── router/      路由 + 登录守卫（按 localStorage 的 fe_token 判断）
└── layout/      整体框架布局（侧边栏菜单）
```

**两个设计器是前端的技术核心**：
- `BpmnDesigner`（基于 bpmn-js）：画流程图，配合 `PropertiesPanel` 编辑节点属性，产出 BPMN XML。
- `FormDesigner`（基于 vuedraggable）：拖拽式表单设计，产出表单 JSON Schema；`FormRenderer` 负责按 Schema 渲染表单。

---

## 6. 前后端对接

```
浏览器(Vue SPA)
  │  axios，baseURL = /workflow，请求头带 Bearer <JWT>
  │  开发期经 Vite proxy 转发
  ▼
后端 http://localhost:9090/workflow（context-path = /workflow）
  │  返回统一结构 { code, message, data }
  ▼
前端响应拦截器：code==200 取 data；401 清登录态跳登录页；XML/图片不拆包
```

- **契约**：统一响应 `R<T>`（`code/message/data`）。
- **鉴权**：登录拿 JWT → 存 `localStorage` → 每次请求注入 `Authorization` 头 → 后端拦截器校验。
- **特例**：流程图 XML、图片等非 JSON 响应不走统一拆包。

---

## 7. 一句话总览

> 前端两个设计器产出 **BPMN XML + 表单 Schema**，通过 REST 提交给后端；后端用 **Flowable 引擎**驱动流程的部署、发起、办理、归档，自有数据（用户/表单/草稿）走 JPA，全程用 **JWT** 串起身份。
