# 03 · 模块功能定位

> 目标：每个模块"负责什么"点到为止，建立角色感即可，不展开实现细节。

---

## 一、后端（flowable-engine-server）

三个 Maven 模块，依赖方向：`api → engine → common`。

### flowable-common —— 公共基座
**定位**：放所有模块都要用的"地基件"，不含具体业务。
- 统一响应结构 `R<T>`（`code/message/data`）
- 全局异常处理、参数校验（`@Valid`）、Jackson、JPA 基座依赖
> 一句话：**统一"对外说话的格式"和公共依赖。**

### flowable-engine —— 业务核心
**定位**：真正干活的层，封装 Flowable + 自有业务逻辑，被 api 调用。
- **service/**：业务逻辑，封装 Flowable 引擎能力
  - `AuthService` 登录鉴权、`SysUserService` 用户
  - `ProcessDefinitionService` 流程定义/部署、`ProcessInstanceService` 发起/查询实例
  - `FlowableTaskService` 待办办理、`FlowableHistoryService` 历史查询
  - `FormDefinitionService` 表单定义、`ProcessDraftService` 流程草稿
- **entity/ + repository/**：自有表（`SysUser`/`FormDefinition`/`ProcessDraft`）及其 JPA 仓库
- **security/**：`JwtUtil`（签发/解析 token）、`UserContext`（线程级当前用户）
- **config/**：`FlowableConfig`（引擎配置，如中文字体）
- **dto/**：请求/响应对象（request / response）
> 一句话：**业务大脑——把 Flowable 引擎和自有数据包成好用的 Service。**

### flowable-api —— 接口与启动门面
**定位**：唯一可启动模块，对外暴露 HTTP 接口。
- `WorkflowApplication`：Spring Boot 启动入口
- **controller/**（8 个）：Auth / User / ProcessDefinition / ProcessInstance / Task / History / FormDefinition / ProcessDraft —— 接收请求、调用 Service、返回 `R<T>`
- **config/**：`LoginInterceptor`（JWT 校验）、`CorsConfig`（跨域）、`WebMvcConfig`（拦截器注册/白名单）
- 含 JDBC 驱动、API 文档、打可执行 fat jar
> 一句话：**对外的门面——接请求、做鉴权、转交业务、统一返回。**

## 二、前端（flowable-designer-ui）

按职责分目录，下面按"角色"归类。

### api/ —— 后端接口封装
按资源拆分：`auth / user / process / instance / task / history / form / draft / hrUser`。每个文件把对应后端接口包成函数。
> 一句话：**前端调后端的唯一出口。**（`hrUser` 对接外部 HR 系统的用户数据）

### utils/request.ts —— HTTP 基座
axios 实例：注入 JWT、统一拆包 `R<T>`、401 跳登录、非 JSON 不拆包。
> 一句话：**所有请求的统一收发管道。**

### views/ —— 业务页面
- `login` 登录
- `designer` 流程设计器列表 + `designer/editor` 流程编辑器
- `form` 表单管理 + `form/designer` 表单设计器
- `process` 流程管理、`instance` 流程实例
- `task` 我的待办、`approved` 我的已审批、`myStart` 我的发起、`history` 历史查询
- `user` 用户管理
> 一句话：**一个页面对应一个业务场景。**

### components/ —— 核心可复用组件
- `BpmnDesigner`：流程图设计器（bpmn-js），含 `BpmnViewer`、`toolbar`、`FlowableModdle.json`（flowable 属性扩展）
- `PropertiesPanel`：流程节点属性面板（Process/StartEvent/UserTask/SequenceFlow/Common 等子面板）
- `FormDesigner`：拖拽式表单设计器（Canvas/FieldPanel/ConfigPanel + 各字段组件）
- `FormRenderer`：按表单 Schema 渲染实际表单
> 一句话：**两个设计器 + 表单渲染，是前端的技术核心。**

### stores/ —— 全局状态（Pinia）
`user`（登录态/用户信息）、`process`（流程相关共享状态）。
> 一句话：**跨页面共享的数据。**

### router/ + layout/ —— 框架骨架
`router`：路由表 + 登录守卫（按 `fe_token` 拦截）；`layout`：整体布局与侧边栏菜单。
> 一句话：**页面怎么跳、整体长什么样。**

## 三、模块协作一图

```
[前端]  views ─调用─> api ─经─> utils/request(注入JWT) ──HTTP──┐
        components(两个设计器) 产出 BPMN XML / 表单 Schema      │
                                                               ▼
[后端]  controller ─> service ─┬─> Flowable 引擎 → ACT_* 表
        (登录拦截器先校验JWT)    └─> JPA repository → 自有表
```
