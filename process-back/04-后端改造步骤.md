# 04 · 后端改造步骤（单体 Spring Boot + Flowable + MyBatis-Plus + Druid）

> 目标：把原来的 **3 个 Maven 模块**（common / engine / api）合并成 **一个 Spring Boot 单体**，
> DAO 层由 **JPA 换成 MyBatis-Plus**，连接池由 **Hikari 换成 Druid**，并手动接入 **Flowable**。
> 现状：已用 Spring Boot 创建 `process-back`，基础包 `com.ha.pr`，已有 web / mssql-jdbc / lombok。
> **已决策：方案 A，Spring Boot `3.3.13`，Flowable `7.1.0`，MyBatis-Plus `3.5.15`，Druid `1.2.25`。**
> 本文档是**手动改造指引**（你自己写代码），不替你生成业务代码。

---

## 0. 先理解：为什么 Initializr 里没有这两个

- **Flowable**：不是 Spring 官方维护的 starter，Spring Initializr 列表里查不到，只能手动在 `pom.xml` 加坐标。
- **MyBatis-Plus**：第三方（baomidou），同理需手动加；且 Spring Boot 3 **必须用 `mybatis-plus-spring-boot3-starter`** 这个专门适配 Boot 3 的包，老的 `mybatis-plus-boot-starter` 在 Boot 3 下因 `javax→jakarta` 改名会加载失败。

---

## 1. 兼容性决策（✅ 已定：方案 A · Spring Boot 3.3.13）

**背景**：开源 **Flowable 7.1.0** 是针对 **Spring Boot 3.3.x** 构建的。若用更新的 3.5.16，Boot 父 POM 会覆盖 Flowable 的传递依赖（Spring Framework 6.2、MyBatis 等），多数能跑，但属"未官方背书"组合，可能在启动建表或个别 API 上踩坑。

**已采用方案 A（稳妥）**：把 Spring Boot parent 锁到 **3.3.13**，与 Flowable 7.1.0 官方测试组合一致，少踩坑、专注学业务。
- `3.3.13` 是 3.3.x 线的**最后一个补丁版**（也是最稳的）。
- 3.3.x 开源维护已 EOL（不再发安全补丁），但对学习/重写项目无影响；将来上生产再考虑升级 3.4/3.5。

**操作**：把 `process-back/pom.xml` 的 parent 版本号改一行即可：
```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.3.13</version>   <!-- 由 3.5.16 改为 3.3.13 -->
    <relativePath/>
</parent>
```
改完让 IDE 重新拉依赖，或 `./mvnw clean compile` 触发一次。

> （备选方案 B：保留 3.5.16，让 Boot 覆盖传递版本、出问题再排查——本项目不采用，记录备查。）

## 2. 包结构规划（单体内部分层）

原来跨模块的职责，现在压成**一个工程里的包**。

> ⚠️ 实操对齐（与本节原稿的差异）：启动类留在根包 `com.ha.pr`，**业务类统一放到 `com.ha.pr.flowwork` 下**（`common/config/controller/service/mapper/entity/dto`）。因此 `@MapperScan("com.ha.pr.flowwork.mapper")`。下面的树按实际包名标注。

```
com.ha.pr
├── ProcessBackApplication.java     启动类（@MapperScan("com.ha.pr.flowwork.mapper")）
└── flowwork/
    ├── common/                 ← 原 flowable-common
    │   ├── R.java                统一响应
    │   ├── BizException.java     业务异常
    │   └── GlobalExceptionHandler.java  全局异常
    ├── config/                 ← 原 engine/config + api/config
    │   ├── FlowableConfig.java   引擎配置（中文字体等）
    │   ├── MybatisPlusConfig.java 分页插件等
    │   ├── IdGeneratorConfig.java 雪花ID生成器 Bean
    │   ├── OpenApiConfig.java    Knife4j/OpenAPI 元信息
    │   ├── WebMvcConfig.java     拦截器注册 + 白名单
    │   ├── CorsConfig.java       跨域
    │   └── LoginInterceptor.java JWT 拦截器
    ├── security/               ← 原 engine/security
    │   ├── JwtUtil.java
    │   └── UserContext.java
    ├── controller/             ← 原 api/controller（8 个）
    ├── service/                ← 原 engine/service
    ├── mapper/                 ← 新增：MyBatis-Plus Mapper（替代原 repository）
    ├── entity/                 ← 自有表实体（改 MyBatis-Plus 注解）
    └── dto/
        ├── request/
        └── response/
```

> 原则：**职责不变，只是从"模块边界"变成"包边界"**。原 `api→engine→common` 的单向依赖，现在靠包内分层自觉维护即可。

### 3.4 关于 Flowable 与 MyBatis-Plus 的"MyBatis 共存"
- Flowable 内部自带 MyBatis，并**自己管理**一套 SqlSessionFactory（走 `ACT_*` 表），不依赖 starter 自动配置。
- MyBatis-Plus 的 starter 给**你自己的表**配一套 SqlSessionFactory。
- 二者各管各的，正常共存。**唯一要注意**：若启动报 MyBatis 版本冲突，多半是 Boot 3.5 与 Flowable 传递的 `mybatis` 核心 jar 版本不一致——这正是第 1 节方案 A 能规避的问题。

## 4. 改造配置文件（`.properties` → `application.yml`）

Initializr 默认给的是 `application.properties`，建议改用 `application.yml`（与原项目一致、层级清晰）。新建 `application.yml`，删掉 `application.properties`。

> ⚠️ 实操对齐：实际按 profile 拆成了两份——
> - **`application.yml`**：公共段（`server`、`spring.application.name`、`spring.profiles.active: dev`、`flowable.*`、`springdoc/knife4j`）。
> - **`application-dev.yml`**：环境相关段（`spring.datasource`(Druid) + `mybatis-plus.*` + `app.worker-id` + `logging.level`）。
>
> 下面这份整合样例仍可作为**字段清单**参考；落地时把 datasource/mybatis-plus/logging 段放进 `application-dev.yml` 即可。另外实际数据库名为 `flowable_db2`，并额外加了 `knife4j.enable/setting.language: zh_cn` 与 `mybatis-plus.configuration.log-impl: Slf4jImpl` + `logging.level` 打印自有表 SQL。

```yaml
server:
  port: 9090
  servlet:
    context-path: /workflow

spring:
  application:
    name: process-back
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource   # 显式指定用 Druid（替代默认 Hikari）
    driver-class-name: com.microsoft.sqlserver.jdbc.SQLServerDriver
    url: jdbc:sqlserver://<host>:1433;databaseName=flowable_db;encrypt=true;trustServerCertificate=true
    username: <user>
    password: <pwd>
    druid:                          # 连接池参数（由原 Hikari 段语义映射而来）
      initial-size: 5               # ← 原 minimum-idle
      min-idle: 5
      max-active: 20                # ← 原 maximum-pool-size
      max-wait: 30000               # ← 原 connection-timeout（取连接超时,毫秒）
      validation-query: SELECT 1    # SQL Server 用 SELECT 1
      test-while-idle: true
      time-between-eviction-runs-millis: 30000    # ← 对应 idle-timeout 思路
      min-evictable-idle-time-millis: 1800000     # ← 对应 max-lifetime 思路
      # 可选：开启 Druid 监控页（访问 /workflow/druid/）
      stat-view-servlet:
        enabled: true
        login-username: admin
        login-password: admin
      web-stat-filter:
        enabled: true
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: Asia/Shanghai
    serialization:
      write-dates-as-timestamps: false

# Flowable：自动建表 + 只开 process 引擎
flowable:
  database-schema-update: true
  async-executor-activate: true
  check-process-definitions: true
  cmmn: { enabled: false }
  dmn: { enabled: false }
  app: { enabled: false }
  idm: { enabled: false }
  eventregistry: { enabled: false }

# MyBatis-Plus（替代原 JPA 配置）
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true   # 表字段下划线 → 实体驼峰
  global-config:
    db-config:
      id-type: assign_id                  # 全局雪花分布式ID（实体字段用 Long，列用 BIGINT、不要 IDENTITY 自增）
  mapper-locations: classpath*:/mapper/**/*.xml   # 若用 XML 写复杂 SQL

# 雪花ID 多实例配置：每个实例给不同 worker-id（0~31），单机用默认 0 即可
app:
  worker-id: 0
  datacenter-id: 0

springdoc:
  swagger-ui:
    path: /swagger-ui.html
```

> 对照原项目变化：**删掉了 `spring.jpa.*` 整段**，换成 `mybatis-plus.*`；连接池 **Hikari → Druid**（原 `spring.datasource.hikari.*` 改为 `spring.datasource.druid.*`）。`flowable.*` 段原样保留。
>
> **关于 Druid 与 Flowable**：Druid starter 会把 `DruidDataSource` 注册为 `@Primary` 数据源，自动接管（Hikari 仍在 classpath 但不被使用）。**Flowable 用的是 Spring 容器里的同一个 DataSource，换池对它透明**，无需额外配置。Hikari→Druid 参数非一一对应，上面是语义最接近的映射，按需微调。

## 5. DAO 层：JPA → MyBatis-Plus（核心改动）

原来自有表用 JPA（`@Entity` + `JpaRepository`），现在改 MyBatis-Plus。涉及 3 张自有表：`SysUser` / `FormDefinition` / `ProcessDraft`。

### 5.1 实体注解替换
| JPA 写法 | MyBatis-Plus 写法 |
|---|---|
| `@Entity @Table(name="sys_user")` | `@TableName("sys_user")` |
| `@Id @GeneratedValue` | `@TableId(type = IdType.ASSIGN_ID)`（雪花分布式ID） |
| `@Column(name="real_name")` | `@TableField("real_name")`（驼峰自动映射时可省略） |
| `@Transient` | `@TableField(exist = false)` |

示例：
```java
@Data
@TableName("sys_user")
public class SysUser {
    // 雪花分布式ID：列用 BIGINT、不要 IDENTITY 自增
    @TableId(type = IdType.ASSIGN_ID)
    // 前端精度：仅 id 字段转字符串，避免 JS 丢精度（其它 Long 不受影响）
    @JsonSerialize(using = ToStringSerializer.class)
    private Long id;
    private String username;
    private String password;
    private String realName;   // map-underscore 开启后自动对应 real_name
    private String role;
    // 直属主管的 sys_user.id（BIGINT 雪花外键）：与 id 同型，也需转字符串防 JS 丢精度
    @JsonSerialize(using = ToStringSerializer.class)
    private Long managerId;
    private Boolean enabled = true;
    private LocalDateTime createTime;
}
// import com.fasterxml.jackson.databind.ser.std.ToStringSerializer;
```

> **ID 方案说明（已选：雪花分布式ID + 逐字段注解 + 全局生成器）**
> - **策略**：全局 `id-type: assign_id`（见第 4 节），实体主键用 `Long` + `@TableId(type = IdType.ASSIGN_ID)`。
> - **前端精度**：雪花 ID 是 19 位 Long，超过 JS 安全整数会丢精度。**给 id 及所有雪花 Long 外键字段（如 `managerId`）加 `@JsonSerialize(using = ToStringSerializer.class)`**，让它们以字符串返回——刻意不用全局 Long→String，避免计数/金额等无关 Long 都被转。（原稿只说"id 字段"，实操中外键同理需要，规则据此细化。）
> - **多实例**：加一个**全局 `IdentifierGenerator` Bean**（下方），workerId 从配置读，每实例配不同值即可，**不需逐类改动**。

```java
// 多实例分布式ID生成器（单机用默认 worker-id=0 即可）
@Configuration
public class IdGeneratorConfig {
    @Value("${app.worker-id:0}")     private long workerId;       // 0~31
    @Value("${app.datacenter-id:0}") private long datacenterId;   // 0~31

    @Bean
    public IdentifierGenerator identifierGenerator() {
        return new DefaultIdentifierGenerator(workerId, datacenterId);
    }
}
// import com.baomidou.mybatisplus.core.incrementer.IdentifierGenerator;
// import com.baomidou.mybatisplus.core.incrementer.DefaultIdentifierGenerator;
```

> **workerId 多实例部署方式（当前：单机用默认 `0`）**
> yml 里的 `app.worker-id: 0` 只是默认/兜底值，**不要靠手动改文件给每个实例配**。Spring 配置优先级 *命令行参数 > 环境变量 > 配置文件*，同一个 jar 用外部覆盖即可。约束：**同时在跑的实例 (workerId, datacenterId) 不能重复**；各 5 bit → 范围 `0~31`，组合上限 `32×32=1024` 节点。
>
> | 方式 | 做法 | 适用 |
> |---|---|---|
> | **① 启动参数 / 环境变量**（推荐） | `APP_WORKER_ID=1 java -jar ...` 或 `--app.worker-id=2`，文件不动 | 少量固定实例 |
> | **② K8s Pod 序号自动注入** | StatefulSet 的 Pod 名 `xxx-0/1...` 取序号注入成 `APP_WORKER_ID`，扩容有序不重复 | 容器化部署 |
> | **③ 动态分配** | 启动时去 Redis/ZooKeeper 申请空闲 workerId（用完释放），思路同美团 Leaf | 大规模 / 弹性伸缩 |
>
> **当前阶段**：单机，默认 `0` 即可；将来多实例时按 ①/② 处理，**代码无需改动，只多传一个启动参数**。

### 5.2 Repository → Mapper
原 `SysUserRepository extends JpaRepository<SysUser, Long>`，改成：
```java
public interface SysUserMapper extends BaseMapper<SysUser> {
    // BaseMapper 已自带 CRUD；自定义查询用 @Select 或 XML
}
```
- 原来的 `findByUsername(...)` 这类**派生查询方法 JPA 自动实现**，MyBatis-Plus **不自动派生**，要改成：
  - `mapper.selectOne(new LambdaQueryWrapper<SysUser>().eq(SysUser::getUsername, username))`，或
  - 在 Mapper 里写 `@Select("...")` / XML。

### 5.3 启动类加 `@MapperScan`
```java
@SpringBootApplication
@MapperScan("com.ha.pr.mapper")   // 扫描 Mapper 接口
public class ProcessBackApplication { ... }
```

### 5.4 Service 层调整
- 原 Service 注入 `XxxRepository`，改注入 `XxxMapper`。
- 方法调用从 `repository.save/findById/findAll` 换成 `mapper.insert/selectById/selectList`（或继承 MyBatis-Plus 的 `IService`/`ServiceImpl` 拿现成方法，看你习惯）。
- **只动自有表的 3 个 Service**；调用 Flowable 引擎（RuntimeService/TaskService 等）的 Service **完全不用改**。

### 5.5 分页插件（可选但建议）
MyBatis-Plus 分页要装拦截器，建 `MybatisPlusConfig`：
```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor it = new MybatisPlusInterceptor();
        it.addInnerInterceptor(new PaginationInnerInterceptor(DbType.SQL_SERVER));
        return it;
    }
}
```
