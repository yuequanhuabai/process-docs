## Step 1 · 新建接口层 `src/api/history.ts`

**做什么**：2 个类型 + 2 个函数，照 `api/task.ts` 的体例。

**类型**：`ApprovedTask`（13 个字段，对着后端 `ApprovedTaskVO` 抄，含新补的三个）、`ActivityTrace`（8 个字段，含新补的 `assigneeName`）。

**⚠️ 本步唯一的坑（第一次遇到）**：

```ts
// 分页的，照旧
export function pageApproved(...) {
  return request.get<never, PageResult<ApprovedTask>>('/history/approved', { params: {...} })
}

// 轨迹：后端返回的是【数组】，不是 PageResult！
export function getActivities(instanceId: string) {
  return request.get<never, ActivityTrace[]>(`/history/instance/${instanceId}/activities`)
}
```

照抄前三页写成 `PageResult<ActivityTrace>` 的话，**TS 不会报错**（拦截器拆包后类型全靠你自己声明），运行时 `res.records` 是 `undefined`，轨迹空白——又一次"编译全绿、界面没数据"。

**哪些字段该声明成可空**：`businessKey` / `startUserName` / `processDefinitionName` / `deleteReason` / `durationInMillis` / `activityName` / `assignee` / `assigneeName` / `endTime`（轨迹的）—— 全部 `| null`。**别图省事全写成 `string`**，那样 TS 就帮不了你（`01` 第 5.2 节列了每个 null 的成因）。

**自测**：`npm run build` 转绿；`api/history.ts` 里两个函数的 URL 与 `HistoryController.java` 逐字对得上。

## Step 2 · 新建 `src/utils/format.ts`

**做什么**：一个 `formatDuration(ms: number | null | undefined): string`，把毫秒说成人话。

**怎么写（引导）**：

1. 先处理 `null`/`undefined` → 返回 `'—'`（轨迹里"进行中"的节点就是 null）；
2. 逐级进位：秒 → 分钟 → 小时 → 天。小于 1 秒的给个「不到 1 秒」（真会出现：同事务内 <1ms 走完的节点）；
3. **余数为 0 时别显示**：`3 小时 0 分钟` 很难看，写成 `3 小时`。

**为什么放 `utils/` 不放页面里**：已审批页和轨迹弹窗都要用。这是本项目**第一个工具函数文件**（`utils/` 之前只有 `request.ts`）。

**自测**：临时在页面里 `console.log(formatDuration(116000))` 看是不是「1 分钟」，`formatDuration(null)` 是不是 `—`。测完删掉。

## Step 3 · 新建共享组件 `src/components/TraceDialog.vue`

**这是本项目第一个自己写的组件**，慢一点。

### 3a · 先定 props 和职责边界（组件版的"第①步"）

| props | 类型 | 必填 | 用途 |
|---|---|---|---|
| `v-model`（`modelValue`） | `boolean` | ✅ | 显隐，父页面控制 |
| `instanceId` | `string` | ✅ | 拉数据用 |
| `processName` | `string \| null` | 选填 | 弹窗顶部摘要，**纯展示** |
| `status` | `InstanceStatus \| null` | 选填 | 顶部摘要的状态 tag |

**职责边界**：组件**自己拉数据**（父只给 id），理由见 `组件选型解析.md` 第四节。
⚠️ **`processName` / `status` 必须由父传**——轨迹接口里没有这两样（`ActivityTraceVO` 只有节点信息），想在组件里"自己查"是查不到的。

### 3b · `v-model` 用 `defineModel()`

```ts
const visible = defineModel<boolean>({ required: true })
```

Vue 3.4+ 的宏，本项目 3.5.39 可用。它是 `props + emit('update:modelValue')` 的糖，展开写法见 `组件选型解析.md` 第五节。**别在组件里直接改 props**，那是单向数据流红线。

### 3c · 什么时候去拉数据

用 `watch` 监听「弹窗被打开」这件事：

- 监听 `visible`（或同时监听 `instanceId`），**为 true 时**才请求；
- 不要在 `onMounted` 里拉——组件挂载时弹窗还没开、`instanceId` 可能是空串；
- 请求前把上一次的 `list` 清空，否则**第二次打开会先闪一下上一条实例的轨迹**（前三页没遇到过这个，因为页面级数据不会"换一条再看"）。

### 3d · 渲染：`el-timeline` + 四条 null 规则

1. **先过滤连线**（本步最容易漏）：
   ```ts
   const nodes = computed(() => list.value.filter(a => a.activityType !== 'sequenceFlow'))
   ```
   后端故意不滤（P3 Day 14 决策 2）。不滤的话 4 个节点会变成 7~8 行，一半是箭头。
2. **节点名兜底**：`activityName` 为空时按 `activityType` 给中文（`startEvent`→开始、`endEvent`→结束），再兜不住就显示 `activityId`。
3. **圆点三态**：走完 `type="success"`；`endTime === null` 用 `type="primary"` + **`hollow`**；流程已终止时最后一行 `type="danger"`。
4. **办理人**：`assigneeName` 为 null 就整段不渲染，别出现「办理人：null」。

`el-timeline-item` 的 props 全表在 `组件选型解析.md` 第 2.1 节（源码查证过），`timestamp` 我们**不用**——三段信息一个 timestamp 装不下，全写默认插槽里自己排。

### 3e · 弹窗本体：比前两个都简单

**只读弹窗**：底部只有「关闭」，**不需要 `submitting`、不需要 `:show-close="!submitting"` 那套**。别把办理弹窗整段搬过来。

**自测**：`npm run build` 转绿。组件此时还没人用，正常。

## Step 4 · 新建 `src/views/approved/index.vue`

**做什么**：外框 + 三条带（标题 / 表格 / 分页），7 列，行内「轨迹」按钮。

**照抄自己前几页的部分**（不用重新想）：`loading` / `current` / `size` / `total` / `list` 五个 ref、`loadList()` + 空 catch、`handlePageChange`、`onMounted(loadList)`、分页器 `:disabled="loading"`。

**本页特有的三件事**：

1. **耗时列用 `formatDuration(row.durationInMillis)`**，不是直接 `{{ row.durationInMillis }}`；
2. **工具条只有标题**——后端 `approved()` 没有筛选入参，别加下拉（加了也没接口接）；
3. **轨迹按钮**：点了要把 `instanceId` / `processDefinitionName` / 状态交给 `TraceDialog`。⚠️ **已审批行没有"实例状态"字段**（`ApprovedTaskVO` 里没有），`status` 这个 props 就**不传**（组件里声明成可选就是为这个）——顶部摘要少一行 tag，可以接受。

**自测**：`npm run build` 转绿；页面能出数据（此时轨迹按钮可以先只 `console.log`）。
