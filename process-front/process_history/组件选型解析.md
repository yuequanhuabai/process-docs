## 二、轨迹：为什么是 `el-timeline`

四个候选，逐个说为什么淘汰：

| 候选 | 淘汰理由 |
|---|---|
| `el-table` | 能用，但"顺序感"和"当前停在哪"要自己造轮子——加序号列、给最后一行加背景色。**轨迹的本质是有序的流转，表格表达的是无序的集合**，语义不对 |
| **`el-steps`（最容易误选，重点说）** | 看起来最像"流程步骤"，但它的模型是**固定的步骤集合 + 一个 `active` 指针**（第几步进行中）。而我们的数据是**历史发生过的活动记录**——① 条数不固定（同一个流程被终止和走完，行数不一样）；② 可能有回退/重复节点（将来加了网关，同一个节点可能出现两次），`el-steps` 的 `active` 索引模型直接崩；③ 每行要挂"办理人 + 起止 + 耗时"三段副文本，`el-steps` 的 `description` 只有一行 |
| 自己写 `div` + CSS 画竖线 | 就是把 `el-timeline` 重写一遍。它总共也就那么点东西，但配色、圆点、间距要和全站 EP 风格对齐，自己调不划算 |
| **`el-timeline`（选它）** | 语义正好：**一串按时间排列的、条数不定的事件**。自带竖线与圆点，圆点的颜色/空心/大小都是现成 props，正好映射我们的三种节点状态 |

### 2.1 `el-timeline-item` 的 props（已查证，`timeline-item.mjs` 原文）

```
timestamp      String   默认 ''      时间戳文本
hideTimestamp  Boolean               不显示时间戳
center         Boolean               垂直居中
placement      'top' | 'bottom'      时间戳位置，默认 bottom
type           'primary'|'success'|'warning'|'danger'|'info'   圆点颜色（语义色）
color          String                圆点自定义色（与 type 二选一）
size           'normal' | 'large'    圆点大小
icon           Component             圆点换成图标
hollow         Boolean               ★ 空心圆点
```

父组件 `el-timeline` 只有两个 props：`mode`（`start`/`alternate`/`alternate-reverse`/`end`）与 `reverse`（倒序）。**我们两个都用默认值**——`reverse` 千万别开，后端已经把顺序排好了（还专门用 `TRANSACTION_ORDER_` 修过一次），前端再倒一次就错了。

### 2.2 我们用到的三个组合

| 节点状态 | 写法 | 为什么 |
|---|---|---|
| 已走完 | `type="success"` | 实心绿点 |
| **当前停留**（`endTime === null`） | `type="primary"` + **`hollow`** | 空心蓝点，一眼看出"走到这儿了" |
| 流程在此终止 | `type="danger"` | 实心红点 |

> `hollow` 这个 props 是**查源码才发现的**——它在官网示例里没有单独一节，凭印象写不出来。这正是"查证优先于回忆"的用处：想要"空心圆点"这个效果，先去 props 表里找有没有现成的，再考虑自己写 CSS。

### 2.3 `timestamp` 我们**不用**

`el-timeline-item` 自带 `timestamp` 属性会渲染一行小灰字。但我们每行要显示**三段**信息（办理人 / 起止时间 / 耗时），一个 `timestamp` 装不下。所以：**内容全部写进默认插槽自己排版**，`timestamp` 空着不传。

## 三、弹窗：为什么还是 `el-dialog`，不用 `el-drawer`

需求评审时 `el-drawer`（右侧抽屉）是候选 C，被否的理由：

- 轨迹一般 4~8 行，`el-dialog` 的高度完全够；抽屉的优势（空间大、不遮挡列表）在这里体现不出来；
- 项目里已经有**两个 `el-dialog` 的成品可参照**（myStart 发起弹窗、task 办理弹窗），三个 close 属性的坑（`close-on-click-modal` / `close-on-press-escape` / **`show-close` 才管右上角 X**）都趟平了；
- 学习成本要花在刀刃上——本 Day 已经有四个"第一次"（`01` 第四节），不必再加一个新组件。

**本弹窗比前两个更简单**：它是**只读**的，没有提交动作 ⇒ **不需要 `submitting` 锁、不需要 `:show-close="!submitting"` 那套**，底部只有一个「关闭」。别把办理弹窗的写法整段搬过来。

## 四、组件自己拉数据，还是父页面拉好传进来？

这是本次唯一一个**组件设计**层面的选择。

| 方案 | 内容 | 评价 |
|---|---|---|
| A · 父拉数据，`:items="traceList"` 传进来 | 组件是纯展示（dumb component） | 两个父页面各要写一遍 `loading` / `try-catch` / 请求竞态处理 —— **抽组件是为了少写，结果重复搬到了外面** |
| **B · 组件自己拉（选它）** | 父只传 `instanceId`，组件内部 `watch` 到 id 变化就去请求 | 加载态、错误处理、空数据都只写一份。父页面只管"打开 + 给 id" |

> 📌 **判据不是"哪种更纯"，是"重复落在谁那里"。** dumb component 是好实践，但它的前提是**多个调用方需要不同的数据来源**；我们两个调用方要的是同一个接口的同一份数据，那就该让组件自己去拿。

**代价（要知道）**：组件与 `api/history.ts` 耦合了，将来它没法用于"轨迹数据来自别处"的场景。当前没有这种场景，接受。

## 五、`v-model`：`defineModel()` 还是手写 props + emit？

父页面要控制弹窗显隐，两种写法：

```vue
<!-- 写法 1：v-model（选这个） -->
<TraceDialog v-model="traceVisible" :instance-id="traceId" />

<!-- 写法 2：拆开 -->
<TraceDialog :visible="traceVisible" @close="traceVisible = false" :instance-id="traceId" />
```

选 **写法 1**，因为它和你已经用了三页的 `el-dialog` 用法**长得一模一样**——`v-model="dialogVisible"`。组件的使用方式与 EP 组件保持一致，心智负担最小。

组件内部用 **`defineModel()`**（Vue 3.4+ 稳定，本项目 3.5.39）：

```ts
const visible = defineModel<boolean>({ required: true })
// 之后 visible.value = false 就会自动通知父组件
```

**它不是新机制，是语法糖**。等价的展开写法：

```ts
const props = defineProps<{ modelValue: boolean }>()
const emit = defineEmits<{ 'update:modelValue': [v: boolean] }>()
const visible = computed({
  get: () => props.modelValue,
  set: (v) => emit('update:modelValue', v),
})
```

`v-model="x"` 在父组件那边编译成 `:model-value="x" @update:model-value="x = $event"`——**props 向下、events 向上那条铁律一点没破**，只是把这套模板代码收进了一个宏里。原理见 `../前端答疑/v-model双向绑定.md` 与 `props向下events向上.md`。

> ⚠️ 别在组件内部直接改 props（`props.modelValue = false`）——那是单向数据流的红线，Vue 会警告，且父组件的值不会变。`defineModel()` 的存在就是为了让你**不用**手写那个 computed 也能安全地"改自己"。

## 六、耗时格式化：为什么不引库

`durationInMillis` 是毫秒整数。候选：`dayjs` 的 `duration` 插件、`humanize-duration`、自己写。

**自己写**，20 行以内：

- 只有一个用途（把毫秒说成人话），引一个库要多一份依赖、多一次构建体积、还要学它的 API；
- 中文口径是我们自己定的（「3 天 6 小时」而不是「3 days 6 hours」），库还要配 locale；
- 放 `src/utils/format.ts`，**不放页面里**——已审批页和轨迹弹窗都要用（这是本项目第一个工具函数文件，`utils/` 目录之前只有 `request.ts`）。
