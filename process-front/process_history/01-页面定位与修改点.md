## 一、这两块要干什么（需求速览，全文见 `00`）

**① 我的已审批　`/approved`**

审批人（manager / admin）回头看「我办过哪些」。调 `GET /history/approved` 分页，**无筛选条件**（后端没有过滤入参），所以工具条只有一个标题。每行一个「轨迹」按钮。

**② 流转轨迹弹窗（共享组件）**

看一条实例走过哪些节点、每个节点谁办的、花了多久。调 `GET /history/instance/{instanceId}/activities`。**两个入口**：

| 入口 | 谁在看 | 关心什么 |
|---|---|---|
| 「我的发起」每行 | 发起人（employee） | **我的申请卡在谁那了** |
| 「我的已审批」每行 | 审批人（manager/admin） | 我批过的这单后来批了吗 |

## 四、本次有四个「第一次」（前三页都没遇到过）

这是 Day 18 值得写的地方——不是又一个表格页，而是四个新东西各来一遍。

### 4.1 第一次抽**共享组件**

前三页都是"一个页面一个 `.vue`"，组件全是 Element Plus 的。这次轨迹弹窗要被**两个页面**用，抽不抽不再是风格问题——不抽就得把同一段 `el-dialog` + `el-timeline` + 加载逻辑写两遍，将来改一处忘另一处。

> 判据回顾：`../前端答疑/何时抽组件.md`。**这次满足的是最硬的那一条：同一段 UI 有两个真实调用方。**

### 4.2 第一次**自己实现 `v-model`**

以前 `v-model` 都是往 Element Plus 的组件上挂（`v-model="dialogVisible"`）。这次反过来——**你的组件要能被 `v-model` 挂**：

```vue
<!-- 父页面这样用 -->
<TraceDialog v-model="traceVisible" :instance-id="traceId" />
```

Vue 3.4+ 有 `defineModel()` 宏，一行搞定（本项目 Vue 3.5.39，可用）。它是 `props + emit('update:modelValue')` 的语法糖，展开写法与原理见 `组件选型解析.md` 第五节 + `../前端答疑/v-model双向绑定.md`。

### 4.3 第一次接**非分页接口**

`GET /history/instance/{id}/activities` 直接返回**数组**。前三页的 GET 全是 `PageResult<T>`，照抄就会写成 `request.get<never, PageResult<ActivityTrace>>`，然后 `page.records` 是 `undefined`，表格空白——又一个"编译全绿、界面没数据"。

### 4.4 第一次写**工具函数**（`utils/format.ts`）

`durationInMillis` 是毫秒整数（如 `116000`）。两个地方都要显示成人话，所以第一次出现"这段逻辑不属于任何一个页面"的情况。

## 五、数据与渲染规则（照这个写，都是后端行为决定的）

### 5.1 已审批列表：7 列

| 列 | 取值 | 注意 |
|---|---|---|
| 流程名称 | `processDefinitionName` | 后端补的 |
| 业务标识 | `businessKey` | 可能 null → `-` |
| 任务名称 | `name` | 「经理审批」 |
| 发起人 | `startUserName` | 后端补的，可能 null → `-` |
| 审批时间 | `endTime` | 后端已格式化好，直接显示 |
| 耗时 | `durationInMillis` | **要 `formatDuration()`** |
| 操作 | —— | 「轨迹」按钮 |

**不放**：`assignee`（恒等于当前登录人，零信息量）、实例 id / 任务 id（内部标识）。`processInstanceId` **留在行数据里**给轨迹按钮用，只是不显示。

### 5.2 轨迹弹窗：三个必须处理的 null + 一个必须做的过滤

| 现象 | 后端为什么这样 | 前端怎么办 |
|---|---|---|
| **有 `sequenceFlow` 行** | 后端**故意不滤**（P3 Day 14 决策 2） | **必须前端滤**：`filter(a => a.activityType !== 'sequenceFlow')`。不滤的话 4 个节点会变成 7~8 行，一半是箭头 |
| `activityName` 为空 | BPMN 里 `startEvent`/`endEvent` 通常不写 `name` | 按 `activityType` 兜底文案：`startEvent`→「开始」、`endEvent`→「结束」，其余回退 `activityId` |
| `endTime` 为 null | 该节点**是当前停留处**（还没走完） | 渲染成「进行中」+ **空心圆点**（`el-timeline-item` 的 `hollow`），不要显示空白或 `Invalid Date` |
| `durationInMillis` 为 null | 同上，还没结束 | `formatDuration` 返回 `—`，或显示「进行中」 |
| `assigneeName` 为 null | 事件/网关行本来就没有办理人 | 不显示这一段，别渲染出「办理人：null」 |

### 5.3 三种实例状态，轨迹长什么样

| 状态 | 特征 | 界面 |
|---|---|---|
| 进行中 | 最后一行 `endTime` 为 null | 空心圆点 + 「进行中」 |
| 已办结 | 有 `endEvent` 行，全都有 `endTime` | 全实心 |
| 已终止 | **没有 `endEvent` 行**，链路在中间断掉 | 最后一行标红。⚠️ **"已终止"这个信息轨迹接口给不出来**（`ActivityTraceVO` 里没有），要由打开弹窗的那一行（`ProcessInstance.status`）**当 props 传进组件** |

> 📌 5.3 最后那条同时决定了弹窗顶部那两行摘要（流程名 / 状态）的数据来源：**也是父页面传进来的**，不是轨迹接口给的。所以组件的 props 是三个：`instanceId`（必填，用来拉数据）、`processName`、`status`（可选，纯展示）。
