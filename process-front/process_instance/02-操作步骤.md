## Step 1 · 新建接口层 `src/api/instance.ts`

**做什么**：定义流程实例的 TS 类型 + 4 个调后端的函数。

**为什么先做**：和 Day 15 同理 —— 接口层是页面的"数据供给"，先备好才有函数可用、有类型提示。

**怎么写（引导）**：

1. 顶部 `import request from '@/utils/request'`，`import type { PageResult } from '@/api/user'`（复用，别重复定义）。

2. 定义 `ProcessInstance` interface —— 字段照 [`01`](./01-页面定位与修改点.md) 第四节那张表抄（13 个）。三个要点：
   - `status` 别写成 `string`，写成**联合字面量类型** `'RUNNING' | 'COMPLETED' | 'TERMINATED'`。这样后面写 `STATUS_MAP` 时 TS 能帮你检查有没有漏掉某个状态。
   - 可能为 null 的字段老实标上 `| null`：`businessKey` / `endTime` / `deleteReason` / `currentActivityName` / `startUserName`。
   - 所有 id 都是 `string`。

3. 再定义一个 `StartInstanceBody`：`{ processDefinitionKey: string; businessKey?: string; variables?: Record<string, unknown> }`。

4. 四个函数：
   - `pageInstances(current=1, size=10, definitionKey?: string)` → GET `/process-instance/page`
   - `myStarted(current=1, size=10, status?: string)` → GET `/process-instance/my-started`
   - `startInstance(body: StartInstanceBody)` → `request.post<never, ProcessInstance>('/process-instance/start', body)`
   - `terminateInstance(instanceId: string, reason?: string)` → `request.delete<never, void>(\`/process-instance/${instanceId}/terminate\`, { params: { reason } })`（URL 于 2026-08-04 调整，见 `03` 第 1 节注释）

**坑（这步最容易栽的一个）**：
- **可选筛选参数传空串会出事**。下拉选「全部流程」时你给的可能是 `''`，`params: { definitionKey: '' }` 会真的拼出 `?definitionKey=`，后端收到一个空字符串（不是 null），过滤结果就是 0 条。
  **axios 会自动丢弃值为 `undefined` 的 params，但不会丢空串** —— 所以「全部」要传 `undefined`，不是 `''`。在 api 层做转换（`definitionKey || undefined`）最省心，页面层就不用操心了。
- POST 的 body 是 `request.post(url, body)` 的**第二个参数**，不是 `{ params }`（那是 query）。

**自测**：这步没法单独跑，TS 不飘红即可。

## Step 2 · 运行中实例页骨架 `src/views/instance/index.vue`

**做什么**：先把"列表 + 分页"跑起来，筛选和操作列下一步再加。**分两步走，先让数据显示出来最好排错。**

**怎么写（引导）**——和 `views/process/index.vue` 完全同构，照抄结构换字段：

1. `<script setup lang="ts">`：五个 ref（`list` / `total` / `current=1` / `size=10` / `loading`）、`loadList()`、`handlePageChange(p)`、`onMounted(loadList)`。
   `loadList` 内部记得**补一个空 `catch`** —— Day 15 踩过的坑，错误已由 `request.ts` 拦截器统一弹，这里只是别让 rejection 逃出去。

2. `<template>`：外层 div + toolbar（标题「运行中实例」）+ `el-table` + `el-pagination`。
   列先放简单字段：`processDefinitionName`（流程名称）/ `businessKey`（业务标识）/ `currentActivityName`（当前节点）/ `startUserName`（发起人）/ `startTime`（发起时间）。

**坑**：
- **好几个字段可能是 null**，直接 `prop` 绑上去会显示成空白，看着像 bug。`businessKey` 为 null 时该显示一个「—」。用插槽兜底：`{{ row.businessKey || '—' }}`。
- `startUserName` 万一为 null（比如老数据查不到用户），兜底显示 `row.startUserId`，别显示空白。
- `startTime` 后端已经格式化成 `yyyy-MM-dd HH:mm:ss` 字符串了，**前端不用再格式化**，直接 `prop` 绑。加个 `class="nowrap"` 或 `width` 防止折行。

**自测**：临时挂个路由（或先跳到 Step 6 挂好再回来），能看到你发起的那几条实例。**先确认数据出来，再往下加。**

## Step 3 · 加「流程筛选 + 终止操作」

**做什么**：工具条加一个流程下拉，表格加一个终止操作列。

**怎么写（引导）**：

1. **流程下拉的数据从哪来**：`GET /process-definition/page?latestOnly=true` —— 就是 Day 15 写好的 `pageDefinitions`，**直接 import 复用，别重新封一个**。
   ```
   const defs = ref<ProcessDefinition[]>([])
   // onMounted 时拉一次：pageDefinitions(1, 100, true) → defs.value = page.records
   ```
   `size` 给个 100 一次拉完（流程模板就四个，不必分页）。

2. **`el-select` 怎么绑**：`v-model="definitionKey"`，选项 `v-for` 遍历 `defs`，`:label="d.name"`（显示中文名）`:value="d.key"`（提交 key）。**再手工加一个「全部流程」选项，`value` 给 `''`**。
   `@change` 里：`current.value = 1`（回第一页）然后 `loadList()`。

3. **终止操作**：`<el-button link type="danger">终止</el-button>`，`handleTerminate(row)` 里：
   - 先 `ElMessageBox.prompt('请输入终止原因', '终止流程', { ... })` —— **注意是 `prompt` 不是 `confirm`**，因为后端要收 `reason`。
   - 它 resolve 出来的是一个对象，原因在 `.value` 里（`const { value } = await ElMessageBox.prompt(...)`）。
   - 用户点取消会 **reject**，所以要 `try/catch`，catch 里 `return` 掉。
   - 然后 `await terminateInstance(row.id, value)` → `ElMessage.success` → `loadList()`。

**坑**：
- **`prompt` 的取消和请求失败要分开处理**。照 Day 15 `handleDelete` 的写法：**两个独立的 `try/catch`** —— 第一个包 `prompt`（catch 里 `return`，表示用户取消），第二个包真正的接口调用（catch 里留空，错误拦截器已弹）。写成一个 try 会把"用户取消"和"接口报错"混在一起。
- **原因别让它空着**。`ElMessageBox.prompt` 的配置项里有 `inputValidator`，可以要求非空。为什么不能空见 [`组件选型解析.md`](./组件选型解析.md) 第六节。
- 终止的是**实例 id**（`row.id`），不是 definitionId。

**自测**：终止一条 → 列表里消失（因为这页查 RU，只装在途的）。**别把仅剩的在途样本全终止掉**，留一条给下一步用。

## Step 4 · 我的发起页 `src/views/myStart/index.vue`

**做什么**：结构和 Step 2/3 几乎一样，但多了**状态列**和**状态筛选**。

**怎么写（引导）**：

1. **先照 Step 2 复制一份骨架**，把 `pageInstances` 换成 `myStarted`。

2. **状态映射写成常量对象**，放在 `<script setup>` 顶部：
   ```
   const STATUS_MAP = {
     RUNNING:    { text: '进行中', type: 'primary' },
     COMPLETED:  { text: '已办结', type: 'success' },
     TERMINATED: { text: '已终止', type: 'danger' },
   } as const
   ```
   状态列用插槽：`<el-tag :type="STATUS_MAP[row.status].type">{{ STATUS_MAP[row.status].text }}</el-tag>`

   **为什么不用 `v-if / v-else-if` 链**：Day 18 历史页还要再用一次这套映射，常量对象能直接搬，`v-if` 链只能重抄。而且 `status` 声明成联合字面量后，TS 会检查 `STATUS_MAP` 有没有漏掉某个状态。

3. **状态筛选**：又一个 `el-select`，选项就是「全部 / 进行中 / 已办结 / 已终止」四个（写死，不用请求）。`value` 分别是 `''` / `'RUNNING'` / `'COMPLETED'` / `'TERMINATED'`。
   **⚠️ 筛选是传给后端的**（`myStarted(current, size, status)`），**不是在前端 `list.filter()`**。前端过滤只能过滤当前这一页，`total` 还是全量、翻页会出现空页 —— 分页立刻就错。

4. **多两列**：`endTime`（结束时间，null 时显示「—」）、状态列。
   **操作列按状态区分**：只有 `status === 'RUNNING'` 的才显示「撤回」按钮（已结束的撤不了）。用 `v-if="row.status === 'RUNNING'"`。

**坑**：
- **「撤回」调的就是 `terminateInstance`**，和 Step 3 的「终止」是同一个接口，只是这一页站在发起人角度所以叫「撤回」。同样要 `prompt` 填原因。
- 已办结/已终止的行，`currentActivityName` 是 null —— 显示「—」。
- 状态筛选切换后记得 `current.value = 1` 再重查，否则可能停在一个不存在的页码上。

**自测（这步是 Day 16 的命门）**：
用 employee 发起几条 → 让 manager + admin 把其中一条**两级都批完** → 回到「我的发起」，**那条应该还在，状态是「已办结」**。
改造前它会消失 —— 这一条就是整个 Day 16 后端改造的意义所在。

## Step 5 · 发起流程弹窗（本次真正的新东西）

**做什么**：「＋ 发起流程」按钮 + 一个 `el-dialog`，选流程、填业务标识和事由，提交。

**为什么单列一步**：Day 15 全是查询和状态切换，**这是第一次往后端提交一份表单**。

**怎么写（引导）**：

1. **状态**：`dialogVisible = ref(false)`、`form = reactive({ processDefinitionKey: '', businessKey: '', reason: '' })`、`formRef = ref()`、`submitting = ref(false)`。

2. **模板**：`<el-dialog v-model="dialogVisible" title="发起流程" width="500px">`，里面 `<el-form :model="form" :rules="rules" ref="formRef" label-width="92px">` 三个 `el-form-item`：
   - 流程：`el-select`（数据源同 Step 3 的 `defs`，**两个页面都要拉一次流程列表**）
   - 业务标识：`el-input`
   - 申请事由：`el-input type="textarea"`
   底部 `#footer` 放取消 / 确定两个按钮。

3. **校验规则**：只有「流程」必填（`rules = { processDefinitionKey: [{ required: true, message: '请选择流程', trigger: 'change' }] }`）。

4. **提交逻辑** `handleSubmit()`：
   - `await formRef.value.validate()`（不通过会 reject）
   - 组装 body：`processDefinitionKey` 直接给；`businessKey` **空串要转成 undefined**（别把空串存进数据库）；`variables` 组装成 `{ reason: form.reason }`
   - `await startInstance(body)` → `ElMessage.success('发起成功')` → 关弹窗 → `loadList()`
   - 用 `submitting` 控制确定按钮的 `:loading`，防重复提交

5. **打开弹窗时要重置表单**，否则上次填的还在。`formRef.value?.resetFields()` —— 注意它依赖每个 `el-form-item` 上写了 `prop`，没写 `prop` 的字段重置不了。

**坑**：
- **传 `processDefinitionKey` 不是 `id`**。后端按 key 自动取最新版本 —— 这是设计如此，别传 `d.id`。
- **`variables` 是个 Map，不是平铺字段**。请求体长这样：`{ processDefinitionKey, businessKey, variables: { reason: '...' } }`，`reason` 在 `variables` 里面一层。
- **变量名是弱契约**：引擎不校验拼写，你写 `reason` 还是 `resaon` 它都收下、悄悄新建一个变量。所以前端字段名要和后端/BPMN 里的用法对齐。这是 `deep_dive/hi_tables/04` 记的坑，也是 P6 表单 schema 该管住的事。
- **现在这几个输入框是写死的，别过度设计**。P6 表单设计器做完后这块会换成"按 schema 动态渲染"，到时候整块替换 —— 现在提前抽通用组件是白费功夫。

**自测**：发起一条报销 → 弹窗关闭 → 列表顶部出现新的一条，状态「进行中」，当前节点「经理审批」。

## Step 6 · 挂路由 + 加菜单

**路由**（`src/router/index.ts`）：在 layout 的 `children` 里 `process` 那条后面加两条：
```
{ path: 'instance',  name: 'Instance', component: () => import('@/views/instance/index.vue') }
{ path: 'my-start',  name: 'MyStart',  component: () => import('@/views/myStart/index.vue') }
```

**菜单**（`src/layout/index.vue`）：`menus` 数组加两项 `{ index: '/instance', title: '运行中实例' }`、`{ index: '/my-start', title: '我的发起' }`。

**坑**（Day 15 提过，再念一遍）：路由子路由 `path` **不带**前导斜杠（`'instance'`），菜单 `index` **要带**（`'/instance'`）。两处规则不一样。

**自测**：侧栏两个新菜单点得进去、高亮正常。

## Step 7 · 联调 + 验收

**起后端**：`process-back` 下 `./mvnw spring-boot:run`
**起前端**：`process-front` 下 `npm run dev`，浏览器登录

**逐项验**（三级流程要**批两次**才结束，这是和 Day 15 最大的不同）：

1. **employee 登录** → 「我的发起」→ 发起一条**报销流程**（三级）→ 列表出现，状态「进行中」，当前节点「经理审批」
2. **manager 登录** → 「运行中实例」能看到它 → （待办页是 Day 17，这里先用 knife4j 或直接在待办接口办理第一级）
3. 第一级批完后 → 回「运行中实例」，那条的**当前节点变成「财务审批」** ← 这一条能验出 `currentActivityName` 真的在动
4. **admin 登录**办理第二级 → 流程结束
5. **employee 回「我的发起」** → **那条还在，状态「已办结」，有结束时间** ← **Day 16 的命门，改造前它会消失**
6. 状态筛选切「已办结」→ 只剩它；切「进行中」→ 它消失；切「全部」→ 都在。三次的「共 N 条」相加应等于全部的条数
7. 撤回一条进行中的 → 填原因 → 状态变「已终止」，**仍在列表里**
8. 「运行中实例」按流程筛选 → 只出对应流程的实例；选「全部流程」→ 都出来

**代码级验收**：`npm run build`（含 `vue-tsc`）通过、无红。

全部通过 → Day 16 关闭，回填 [`../../plan/P4-业务前端批量.md`](../../plan/P4-业务前端批量.md) 的 Day 16 条目与打卡行，更新 [`../../测试进度断点.md`](../../测试进度断点.md)。

## 附：和 Day 15 流程管理页的异同

| | 流程管理页（Day 15）| 本次两个页面（Day 16）|
|---|---|---|
| 列表 + 分页 | ✅ | ✅ 一样 |
| 需要改后端 | ❌ 纯前端 | ✅ **双端**（VO 补 5 字段 + 换查询）|
| 筛选控件 | `el-switch`（2 个态）| **`el-select`**（4 个态，switch 装不下）|
| 状态展示 | `el-tag` 二色 | `el-tag` **三色 + 常量映射表** |
| 表单提交 | ❌ 没有 | ✅ **发起弹窗**（`el-dialog` + `el-form`）|
| 危险操作 | `ElMessageBox.confirm` | **`.prompt`**（要填终止原因）|
| 页面数 | 1 个 | 2 个（结构同构，第二个是第一个的扩展）|

**结论**：两个页面 ≈ 流程管理页**换字段**，再加上「状态三态映射」「后端筛选」「表单弹窗」三样新东西。骨架你已经会了，把注意力放在这三样上。
