## Step 1 · 新建接口层 `src/api/task.ts`

**做什么**：定义 `Task` / `TaskForm` / `CompleteTaskBody` 三个类型 + 3 个函数。

**怎么写（引导）**：

1. 顶部照例 `import request from '@/utils/request'`、`import type { PageResult } from '@/api/user'`。
2. `Task` interface：字段照 [`01`](./01-页面定位与修改点.md) 第四节那张表抄（11 个）。可空的老实标 `| null`（`assignee` / `businessKey` / `startUserName`），id 全 `string`。
3. `TaskForm`：**`extends Task`** 再加 `variables: Record<string, unknown>` 和 `formKey: string | null`——后端就是 `TaskFormVO extends TaskVO`，前端类型照着继承，别平铺重抄 11 个字段。
4. 三个函数：
   - `pageTodo(current = 1, size = 10)` → GET `/task/todo`
   - `taskDetail(taskId: string)` → GET `` `/task/${taskId}` ``
   - `completeTask(body: CompleteTaskBody)` → `request.post<never, void>('/task/complete', body)`

**坑**：

- **`pageTodo` 没有第三个参数**。从 `api/instance.ts` 照抄时把 `definitionKey || undefined` 那行删干净——后端没这个参数，类型里声明了就是对页面撒谎。
- **`completeTask` 的 `taskId` 在 body 里**，不是拼在 URL 上。旧文档写错过 `/task/{taskId}/complete`，以 Controller 为准。
- `request.get<never, X>` 双泛型的现状写法继续用（拆包问题，P4 收尾再评估门面方案），别在这条支线上创新。

**自测**：TS 不飘红。

## Step 2 · 列表骨架 `src/views/task/index.vue`

**做什么**：先把"列表 + 分页"跑起来，弹窗下一步再加。**先让数据显示出来最好排错**——第三次说了。

**怎么写（引导）**：

1. `<script setup lang="ts">`：五个 ref（`list` / `total` / `current=1` / `size=10` / `loading`）+ `loadList()`（空 catch + finally 收 loading）+ `handlePageChange(p)` + `onMounted(loadList)`。**比实例页还少**：没有 `defs`、没有筛选 ref。
2. `<template>`：4 div 范本——`.task-page` > `.toolbar`（只有标题「待办任务」）/ `.table-wrap` / `.pager-wrap`。
3. 列照原型第 ① 节：`processDefinitionName` / `businessKey`（插槽 `|| '-'` 兜底）/ `name`（列头叫「任务名称」）/ `startUserName`（插槽 `|| '-'`）/ `createTime` / 操作列（下一步）。
4. `el-pagination` 照抄实例页，含 `:disabled="loading"`。

**坑**：

- 工具条**别手滑把状态下拉抄过来**（组件选型解析第二节：不摆假控件）。
- `createTime` 后端已格式化，直接 `prop` 绑，给足 `min-width` 防折行。

**自测**：先跳 Step 4 挂好路由再回来看——manager 登录应看到停在 `managerApprove` 的现成样本（数据库 08-11 就有）；**employee 登录应看到「暂无数据」空态而不是报错**。

## Step 3 · 办理弹窗（本页真正的新东西）

**做什么**：操作列「办理」→ 拉详情 → 弹窗（只读区 + 意见输入）→ 提交 → 刷新。

**怎么写（引导）**：

1. **状态**：`dialogVisible = ref(false)`、`submitting = ref(false)`、`detail = ref<TaskForm | null>(null)`、`comment = ref('')`。**没有 `formRef`、没有 `rules`**——零校验字段，`el-form` 全家桶这次不请（组件选型解析第四节）。
2. **打开**：`openHandle(row)` 里先 `await taskDetail(row.id)` 存进 `detail`，**成功了才** `comment.value = ''` + `dialogVisible.value = true`。
   - catch 里直接 `return`——详情拉不到（如"已被他人认领"）时拦截器已弹错，**弹窗不打开**，别让空弹窗立在那。
3. **只读区**：`el-descriptions :column="1" border`——固定两行（「流程 / 节点」拼 `detail.processDefinitionName` 和 `detail.name`；「业务标识」`|| '-'`）+ 动态行（`v-for` 遍历 `Object.entries(detail.variables)`，key 做 label、value 直接插值）。
   - 遍历入口建议包一层 `computed`，顺手兜住 `detail` 为 null 的窗口期。
4. **意见输入**：一个自己写 label 的 `el-input type="textarea" :rows="3"`，placeholder 写明「选填」。
5. **提交** `handleSubmit()`：
   - 组装 `variables`：`approved` **固定 `true`**（决策②）；`comment` 走 `.trim()` 后**非空才塞**（决策③——空值不进 variables，别让引擎存个空串变量）。
   - `await completeTask({ taskId: detail.value.id, variables })` → `ElMessage.success` → 关弹窗 → **末页回退判断**（该行要消失：`list.length === 1 && current > 1` 则 `current -= 1`，照实例页 `handleTerminate` 那三行）→ `loadList()`。
   - `submitting` 控制提交按钮 `:loading`；**catch 里什么都不做**——办理失败（任务刚被别人办掉等）**不关弹窗**，用户填的意见还在，可看清错误后重试或取消。
6. **弹窗竞态三件套**照 myStart 抄：`:close-on-click-modal="false"`、`:close-on-press-escape="!submitting"`、`:show-close="!submitting"`。

**坑**：

- **成功路径和失败路径对弹窗的处理相反**（成功关、失败不关），写的时候注意 `dialogVisible.value = false` 必须在 try 成功分支里，放 finally 就错了。
- `variables` 的值是 `unknown`，模板里直接 `{{ v }}` 插值，别调用任何方法。`initiator` 显示数字 userId 是已知现状（01 第五节坑 5）。
- 办理成功后**不需要**像发起那样重置筛选——本页没有筛选。

**自测**：manager 办掉一条**三级流程**（报销/采购/出差）的「经理审批」→ 行消失；此时**先别切号**，把 Step 4 做完再走完整验收。

## Step 4 · 挂路由 + 加菜单

**路由**（`src/router/index.ts`）：layout 的 `children` 里 `my-start` 后面加：
```
{ path: 'task', name: 'Task', component: () => import('@/views/task/index.vue') }
```

**菜单**（`src/layout/index.vue`）：`menus` 数组「我的发起」和「关于」之间加 `{ index: '/task', title: '待办任务' }`。

**坑**（第三遍念）：子路由 `path` 不带前导斜杠（`'task'`），菜单 `index` 要带（`'/task'`）。

**自测**：侧栏「待办任务」点得进去、暖金高亮正常。

## Step 5 · 联调 + 验收（= 需求文档第六节 6 条）

起后端（改过要重启）+ 前端 `npm run dev`：

1. **manager 登录** → 待办列表出现停在 `managerApprove` 的样本，流程名称/发起人/业务标识三列有值
2. manager 在**界面**办掉一条**三级流程**的一级（弹窗里能看到申请变量，填条意见提交）→ 行消失
3. **切 admin 登录** → 待办出现该条，任务名称是「财务审批」（报销）或「总监审批」（采购/出差）⇒ **界面办理 + 两级流转都通**
4. admin 再办掉它 → **切 employee** →「我的发起」里该条变「已办结」
5. employee 看「待办任务」→ 空态「暂无数据」，不报错
6. `npm run build`（含 `vue-tsc -b`）转绿

**代码级自查**：分页器和提交按钮的竞态挂了没（`:disabled="loading"` / `:loading="submitting"`）；③ 步样式写完后照 Day 16 的教训**看一眼 `dist/assets/*.css` 里选择器真的生成了**（静默失效那个坑）。

全部通过 → Day 17 关闭，回填 [`../../plan/P4-业务前端批量.md`](../../plan/P4-业务前端批量.md) Day 17 条目与打卡行，更新 [`../../测试进度断点.md`](../../测试进度断点.md)。

## 附：和 Day 16 的异同

| | 我的发起（Day 16）| 待办页（Day 17）|
