## 一、请求管道相关

### Q1：为什么 `await pageDefinitions()` 直接就是 `{records, total,...}`，不用再 `.data.data`？

**A**：因为 `utils/request.ts` 的**响应拦截器**已经拆过一层了。后端统一返 `R{ code, msg, data }`，拦截器在 `code==200` 时 `return res.data`——把最里层的 `data` 直接交给你。所以你在业务层拿到的就是 `data` 本身（这里是 `PageResult`）。

**延伸**：这也是为什么 api 函数的泛型写 `request.get<never, PageResult<ProcessDefinition>>`——第二个泛型就是"拆包后的类型"。第一个 `never` 是请求体类型（GET 没有请求体，占位）。

### Q2：接口出错了，我要不要自己 `ElMessage.error` 弹提示？

**A**：不用。拦截器已经统一处理：业务失败（`code!=200`）会 `ElMessage.error(res.msg)`，网络错/401 也各有处理。所以你的 `catch {}` 里**通常留空**，只是为了阻止异常继续往上抛、以及在删除时"用户点取消"那种场景 `return` 掉。

### Q3：token 我要手动加吗？

**A**：不用。**请求**拦截器自动从 `localStorage.fe_token` 读 token 注入 `Authorization: Bearer xxx`。你只管调接口。

## 二、TypeScript / 类型相关

### Q4：`PageResult` 定义在 `api/user.ts` 里，我在 `process.ts` 里 import 它，会不会很奇怪（流程依赖用户）？

**A**：目前可以直接 `import type { PageResult } from '@/api/user'`，能跑、也不算错。它只是个通用分页壳，恰好第一次写在了 user.ts。**更干净的做法**是把 `PageResult` 抽到一个共享文件（如 `@/api/types.ts` 或 `@/types/page.ts`）再各自 import——但那会动到 user.ts，属于重构。Day 15 先复用不纠结，等 P4 四个页面都要用时再抽也不迟。

### Q5：`id` 为什么必须是 `string`，不能是 `number`？

**A**：两个原因。① 流程定义 id 形如 `leaveProcess:1:xxx`，本来就不是数字。② 项目里其它 id（如雪花 id）是大整数，用 number 会丢精度，全项目统一用字符串传。记住流程域 id 全是 string。

## 三、Element Plus 组件相关

### Q6：`el-table-column` 什么时候用 `prop`，什么时候用 `#default` 插槽？

**A**：
- 直接显示某个字段的原文 → `prop="name"`，简单省事。
- 需要**加工后再显示**（状态转 tag、角色转中文、时间格式化、放按钮）→ 用 `#default="{ row }"` 插槽，在里面自己写模板，`row` 就是那一行的数据对象。

本页：name/key/version/resourceName 用 `prop`；状态列和操作列用插槽。

### Q7：`ElMessageBox.confirm` 用户点「取消」为什么会进 `catch`？

**A**：`ElMessageBox.confirm` 返回一个 Promise——点「确定」resolve，点「取消」（或关闭）**reject**。所以要 `try/catch`，在 `catch` 里 `return` 表示"用户放弃，什么都不做"。如果不 catch，取消会抛出一个未处理的 rejection。

### Q8：`el-button` 的 `link` 是什么？`type` 有哪些？

**A**：`link` 让按钮变成"文字链接"样式（表格操作列常用，不占地方）。`type` 决定颜色：`primary`(蓝) / `success`(绿) / `warning`(橙) / `danger`(红) / `info`(灰)。本页挂起用 `warning`、激活用 `success`、删除用 `danger`。

## 四、路由 / 布局相关

### Q9：为什么路由子路由 `path` 写 `'process'`（不带斜杠），侧栏菜单 `index` 却写 `'/process'`（带斜杠）？

**A**：两套规则：
- **路由子路由**：`path` 是相对父路由拼接的。父路由是 `/`，子路由 `'process'` 拼成 `/process`。写成 `'/process'` 反而语义混乱（虽然多数情况也能解析）。习惯：子路由不带前导斜杠。
- **el-menu 的 `index`**：`el-menu` 开了 `router` 属性后，点菜单会把 `index` 当**完整路径**去跳转。所以要写完整的 `/process`。

记法：**路由子路由相对（不带斜杠）、菜单 index 绝对（带斜杠）**。

### Q10：为什么新页面要挂在 layout 的 children 里，不单独一条顶级路由？

**A**：因为 layout 提供了侧栏+顶栏+登录守卫保护。挂成子路由，页面就自动套上这套外壳、自动被守卫保护。单独顶级路由就得自己再处理布局和鉴权，重复劳动。

## 五、联调 / 调试相关

### Q11：页面 404 或白屏，怎么排？

**A**：分层看：
1. 打开浏览器 **DevTools → Network**，看 `/workflow/process-definition/page` 这条请求：
   - 没发出去 → 路由/组件路径写错，看 Console 报错。
   - 发了但 **401** → 没登录/token 失效，先登录。
   - 发了但 **404** → 后端路径不对（检查 api 里的路径拼写）。
   - 发了但 **500** → 后端错，去后端日志看。
2. 请求成功但表格空 → 看返回 JSON 的 `data.records` 有没有数据、字段名和你的 interface 对不对得上。

### Q12：删除时想验"有在途实例删不掉"，具体怎么测？

**A**：当前数据库现场里 `leaveProcess` 那个部署下有 test-0005 在途。你在页面上删那个部署（`cascade=false`）→ 后端会因外键冲突走友好报错分支 → 前端弹出错误提示、删除失败。这就是预期行为，证明 `cascade=false` 生效。**别去改成 cascade=true 真删**，那会清掉 test-0005（后面页面还要用）。
