# 01 · 流程管理页：定位与修改点

> P4 · Day 15。目标：做一个「流程管理」页，列出已部署的流程定义，支持挂起 / 激活 / 删除。
>
> 本篇解决两个问题：① 先看懂现有前端骨架长什么样（宏观）；② 基于需求，定位这次到底要改哪几个文件、各改什么（微观）。**先宏观后微观**，看完这篇你应该能自己说出"我要动哪几个地方"。

---

## 一、这个页面要干什么（需求）

一句话：**把后端已部署的流程定义查出来，摆成一张表，每行能挂起/激活/删除。**

拆成可执行的点：
- 进 `/process` 路由 → 看到一张流程定义表格（名称 / key / 版本 / 状态 / 资源名）
- 表格分页
- 每行操作：**挂起**（禁止再发起新实例）↔ **激活**（恢复）二选一、**删除**（删掉整个部署）
- 不做「部署（新增）」——部署要上传 BPMN 文件，留给 Day 22 的设计器

> 💡 所以这页比「用户管理」还简单：**没有新增/编辑弹窗**。它就是「表格 + 分页 + 操作列」。

---

## 二、先看懂现有前端骨架（宏观架构）

在动手前，你得知道一个请求从点击到拿到数据，中间流过哪些部件。现有骨架有五个关键件，各管一段：

```
[视图 views/xxx.vue]  发起调用
        │  调 api 函数
        ▼
[接口层 api/xxx.ts]   定义"调哪个后端接口、参数/返回是什么类型"
        │  用 request 实例
        ▼
[HTTP 管道 utils/request.ts]  注入 token、拆 R{code,msg,data}、失败弹错、401 跳登录
        │  baseURL=/workflow
        ▼
[vite proxy]  /workflow → http://localhost:9090
        ▼
[后端 9090]
```

外加两个"框架件"：
- **`router/index.ts`**：路由表 + 登录守卫。所有受保护页面作为 `layout` 的**子路由**挂进来。
- **`layout/index.vue`**：整体布局（左侧栏菜单 + 顶栏 + 主区 `<router-view>`）。侧栏菜单是一个 `menus` 数组，每项 `{ index, title }`。

### 三个"范式"是你要照抄的模板

1. **HTTP 管道已经替你干了脏活**（`utils/request.ts`）——你在业务层**不用**手写：
   - 加 token（拦截器自动从 `localStorage.fe_token` 注入 `Authorization`）
   - 拆包（后端返 `R{code,msg,data}`，拦截器 `code==200` 时直接把 `data` 交给你）→ **所以 `await api函数()` 拿到的就是 `data` 本身**
   - 弹错（`code!=200` 或网络错，拦截器已 `ElMessage.error`）→ **所以你 `catch` 里通常什么都不用写**
   - 401 自动跳登录

2. **接口层范式**（看 `api/user.ts`）——每个后端接口对应一个类型化函数：
   ```ts
   export function pageUsers(current = 1, size = 10) {
     return request.get<never, PageResult<SysUser>>('/user/page', { params: { current, size } })
   }
   ```
   注意泛型 `<never, PageResult<SysUser>>` 的第二个参数 = **拆包后你实际拿到的类型**。`PageResult<T>` 就定义在 `api/user.ts` 里（`{ records, total, current, size }`），可直接复用。

3. **列表页范式**（看 `views/user/index.vue`）——一套固定套路：
   - 五个 ref：`list / total / current / size / loading`
   - `loadList()`：`loading=true` → 调分页接口 → 填 `list`/`total` → `finally loading=false`
   - `handlePageChange(p)`：换页码后 `loadList()`
   - `onMounted(loadList)`：进页面即加载
   - 模板：`toolbar`（标题+按钮）+ `el-table`（列）+ `el-pagination` + （用户页还有 `el-dialog`，我们这页**不需要**）

## 三、定位：这次要改哪几个点

对照上面的骨架，"流程管理页"这个需求落到 **4 个文件**（2 新建 + 2 修改）：

| # | 文件 | 新建/改 | 干什么 |
|---|---|---|---|

## 四、后端契约速查（写 api 层时对着填）

base 路径：`/process-definition`（request 的 baseURL 已是 `/workflow`，所以这里写相对路径即可）

| 用途 | 方法 + 路径 | 参数 | 拆包后返回 |
|---|---|---|---|
| 分页列表 | `GET /process-definition/page` | query: `current, size, latestOnly` | `PageResult<ProcessDefinition>` |
| 挂起 | `PUT /process-definition/{definitionId}/suspend` | 路径：**definitionId** | `void` |
| 激活 | `PUT /process-definition/{definitionId}/activate` | 路径：**definitionId** | `void` |
| 删除部署 | `DELETE /process-definition/deployment/{deploymentId}` | 路径：**deploymentId**；query：`cascade` | `void` |

`ProcessDefinition`（对齐后端 `ProcessDefinitionVO`）字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 流程定义 id，形如 `leaveProcess:1:xxx`。**挂起/激活传它** |
| `key` | string | 流程 key（跨版本不变，如 `leaveProcess`）|
| `name` | string | 流程名称 |
| `version` | number | 版本号 |
| `deploymentId` | string | 部署 id。**删除传它** |
| `suspended` | boolean | 是否挂起 |
| `resourceName` | string | BPMN 资源名 |
| `diagramResourceName` | string \| null | 流程图 png 资源名，可能 null |

## 五、⚠️ 三个坑（写之前先记住，能省一半调试）

1. **两个 id 别接反**：挂起/激活用 `row.id`（definitionId），删除用 `row.deploymentId`。它俩都是长字符串，接反了后端找不到对象直接报错。这是 P4 头号坑。
2. **所有 id 都是字符串**：TS 里类型声明成 `string`，别写 `number`（`id` 里带 `:` 本来也不是数字）。
3. **删除是危险操作**：本页固定 `cascade=false`。若该流程下有在途/历史实例，后端会**友好报错删不掉**（这正好能让你验证到后端的报错分支）；`cascade=true` 会连实例带历史一起抹掉，本页不做。
