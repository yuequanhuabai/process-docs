## Step 1 · 新建接口层 `src/api/process.ts`

**做什么**：定义流程定义的 TS 类型 + 4 个调后端的函数。

**为什么先做这个**：页面要调接口才有数据。接口层是页面的"数据供给"，先把它备好，写页面时才有函数可用、有类型可提示。

**怎么写（引导）**：

1. 顶部 `import request from '@/utils/request'`。分页返回要用 `PageResult<T>`，它已在 `api/user.ts` 里 `export`，直接 `import type { PageResult } from '@/api/user'` 复用（别重复定义）。

2. 定义 `ProcessDefinition` interface —— 字段照 `01` 第四节的表抄（8 个字段，注意 `id`/`deploymentId` 都是 string，`diagramResourceName` 可为 null）。给 `id` 和 `deploymentId` 各写一行注释标明"谁给挂起激活用、谁给删除用"，逼自己记住别接反。

3. 写 4 个函数，照 `api/user.ts` 的 `pageUsers` 范式：
   - `pageDefinitions(current=1, size=10, latestOnly=false)` → `request.get<never, PageResult<ProcessDefinition>>('/process-definition/page', { params: {...} })`
   - `suspendDefinition(definitionId: string)` → `request.put<never, void>(\`/process-definition/${definitionId}/suspend\`)`
   - `activateDefinition(definitionId: string)` → 同上，路径换 `activate`
   - `deleteDeployment(deploymentId: string, cascade=false)` → `request.delete<never, void>(\`/process-definition/deployment/${deploymentId}\`, { params: { cascade } })`

**坑**：
- PUT/DELETE 的动态段用**模板字符串**拼路径（反引号 + `${}`），别写成字符串加号拼、也别漏了反引号。
- `params` 是 query 参数（拼到 `?` 后面）；路径里的 `{definitionId}` 是**路径段**，直接拼进模板字符串。两者别混。

**自测**：这步没法单独跑，等页面写好一起验。写完 TS 不飘红（类型都认得）即可。

## Step 2 · 新建页面骨架 `src/views/process/index.vue`（先让表格出数据）

**做什么**：先把"列表 + 分页"跑起来，操作列下一步再加。**分两步走，先让数据显示出来，最有成就感也最好排错。**

**在哪**：新建 `src/views/process/index.vue`。用 `<script setup lang="ts">`。

**怎么写（引导）**——照 `views/user/index.vue` 的范式，但去掉弹窗相关的一切：

1. `<script setup lang="ts">` 里：
   - import：`ref, onMounted`（vue）、你 Step 1 写的 `pageDefinitions` 和 `type ProcessDefinition`
   - 五个 ref：`list`（`ref<ProcessDefinition[]>([])`）、`total`、`current=1`、`size=10`、`loading`
   - `loadList()`：`loading.value=true` → `const page = await pageDefinitions(current.value, size.value)` → `list.value = page.records`、`total.value = page.total` → `finally { loading.value=false }`
   - `handlePageChange(p)`：`current.value = p; loadList()`
   - `onMounted(loadList)`

2. `<template>` 里：
   - 一个外层 `<div class="process-page">`
   - `toolbar`：标题「流程管理」（先不放按钮，部署是 Day 22）
   - `<el-table :data="list" v-loading="loading" border>`，列先放：`name`(流程名称) / `key`(流程 Key) / `version`(版本) / `resourceName`(资源名)。状态列和操作列 Step 3 再加。
   - `<el-pagination>`：`layout="total, prev, pager, next"`、`:total="total"`、`:current-page="current"`、`:page-size="size"`、`@current-change="handlePageChange"`

3. `<style scoped lang="scss">`：可直接照抄 user 页的 `.toolbar` / `.pager` 样式（改类名前缀）。

**坑**：
- `el-table` 的列有两种写法：简单字段用 `prop="name"` 直接取；需要自定义渲染（如状态 tag）用 `#default="{ row }"` 插槽。这步全是简单字段，用 `prop` 即可。
- `list` 初值给 `[]`，别给 `undefined`，否则表格首帧可能报错。

**自测**：此时应能在 `/process`（下一步才挂路由，可以先临时把 user 页路由改成这个组件测，或先跳到 Step 4 挂好路由再回来）看到 `leaveProcess` 的若干版本行 + 分页。**先确认数据能出来，再往下加操作。**

## Step 3 · 加「状态列 + 操作列」（挂起 / 激活 / 删除）

**做什么**：给表格补两列——状态（tag）和操作（三个动作按钮）。

**怎么写（引导）**：

1. **状态列**（自定义渲染，用插槽）：
   ```
   <el-table-column label="状态" width="90">
     <template #default="{ row }">
       <el-tag :type="row.suspended ? 'info' : 'success'">
         {{ row.suspended ? '挂起' : '激活' }}
       </el-tag>
     </template>
   </el-table-column>
   ```

2. **操作列**：一个「挂起/激活」按钮（按 `row.suspended` 二选一显示）+ 一个「删除」按钮。`<el-button link ...>`。

3. **script 里补两个处理函数**：
   - `handleToggleSuspend(row)`：`if (row.suspended) await activateDefinition(row.id) else await suspendDefinition(row.id)`，成功 `ElMessage.success(...)`，然后 `loadList()` 刷新。用 `try/catch`，**catch 里留空**（错误提示 request 拦截器已弹）。
   - `handleDelete(row)`：先 `await ElMessageBox.confirm('确定删除...？若有在途/历史实例将失败', '删除确认', { type: 'warning' })`（用户点取消会 reject → `catch { return }`）；确认后 `await deleteDeployment(row.deploymentId, false)` → `ElMessage.success` → `loadList()`。
   - 记得 import：`ElMessage, ElMessageBox`（from 'element-plus'）、`suspendDefinition/activateDefinition/deleteDeployment`（from '@/api/process'）。

**坑（重点，务必对照）**：
- 挂起/激活传 **`row.id`**，删除传 **`row.deploymentId`**。接反是最常见的错，写的时候回头看一眼 `01` 第五节。
- `ElMessageBox.confirm` 用户点「取消」会走 reject（抛异常），所以要用 `try/catch`，`catch` 里 `return` 掉，别让它继续往下删。
- 删除成功后若删的是当前页最后一条且不在第一页，`current.value -= 1` 再 `loadList()`，避免停在空页（可选优化，照 user 页做）。

**自测**：挂起一行 → 状态变「挂起」、按钮变「激活」；再点激活切回来。

## Step 4 · 挂路由 `src/router/index.ts`

**做什么**：让 `/process` 能访问到你的新页面。

**怎么写**：在 layout 的 `children` 数组里，`user` 那条后面加一条：
```
{ path: 'process', name: 'Process', component: () => import('@/views/process/index.vue') }
```

**为什么**：受保护页面都作为 `layout` 的子路由挂，这样自动套上侧栏+顶栏布局，也自动被登录守卫保护。

**坑**：子路由 `path` 不要写前导斜杠（写 `'process'` 不是 `'/process'`），它是相对 layout 的 `/` 拼出来的；用 `() => import(...)` 懒加载，和其它条目保持一致。

**自测**：浏览器地址栏输 `/process` 能进页面（且带着侧栏布局）。

## Step 5 · 加侧栏菜单 `src/layout/index.vue`

**做什么**：侧栏加一个「流程管理」入口，能点进去。

**怎么写**：找到 `menus` 数组，在「用户管理」后面加一项：
```
{ index: '/process', title: '流程管理' }
```

**为什么**：`el-menu` 上有 `router` 属性，点菜单项会按 `index`（当作路由 path）跳转。所以 `index` 要填**完整路径** `/process`（带前导斜杠，和菜单里其它项一致——注意这里和路由子路由的写法不同）。

**坑**：菜单 `index` 用 `/process`（带斜杠），路由子路由 `path` 用 `process`（不带）。两处规则不一样，别搞混。

**自测**：侧栏点「流程管理」→ 跳到列表页，菜单项高亮。

## 附：这页和「用户管理页」的异同（帮你迁移已有认知）

| | 用户管理页 | 流程管理页（本页）|
|---|---|---|
| 列表 + 分页 | ✅ | ✅ 一样 |
| 新增/编辑弹窗 | ✅ 有 | ❌ **没有**（部署走 Day 22）|
| 操作列 | 编辑 / 删除 | 挂起-激活 / 删除 |
| 删除参数 | `id` | **`deploymentId`**（不是 id！）|
| 状态切换 | 无（编辑弹窗里改 enabled）| **挂起/激活直接调接口**（无弹窗）|

**结论**：流程管理页 ≈ 用户管理页**砍掉弹窗**、把操作列换成「挂起/激活 + 删除」。你已经会写 user 页，这页是它的简化版。
