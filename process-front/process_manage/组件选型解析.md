# 流程管理页 · 组件选型解析（答疑笔记）

> 由答疑 CLI 整理。视角：**从"要展示什么"倒推"用什么 Vue / Element Plus 组件"**，而不是顺着代码读。
> 配套：主 CLI 的 `02-操作步骤.md`（怎么做）、`03-完整代码.md`（参考答案）。本篇解释"为什么这么选"。
> 对应代码：`src/views/process/index.vue` 的 `<template>`。

---

## 先明确这一页要展示什么

流程管理页的本质需求：**把后端返回的一批"流程定义"记录，让用户看清楚、能翻页、能对每条做操作（挂起/激活/删除）**。

拆成 6 个具体的展示子需求，逐个看选型。核心方法：**先问"这块信息是什么形态"（一批/单条/状态/开关/操作/翻页），再从形态映射到组件**。同一个效果往往有好几个组件能做，选型看的是 **语义匹配 + 交互惯例 + 复杂度是否配得上**。

---

## 需求 1：展示"一批结构相同的记录"（主体）

后端返回 `ProcessDefinition[]`——多条、每条字段一样（name/key/version/状态…）。这是最核心的展示决策。

| 候选 | 适合场景 | 为什么不选 |
|---|---|---|
| **`el-table`** ✅ | 多条同构记录、需要对齐成列对比、带排序/分页/操作列 | —— |
| `el-card` 列表（卡片流） | 每条内容异构、图文并茂（商品、文章卡） | 流程定义是规整字段表，卡片让"版本/状态"难横向对比 |
| `div + v-for` 自己拼 | 结构极特殊、组件满足不了 | 要自己实现表头对齐、分页联动、加载遮罩、操作列——重复造轮子 |
| `el-descriptions` | **单条**记录的详情展示（键值对） | 它是给"一条"用的，不是列表 |

**结论**：一批同构、需要列对齐 + 翻页 + 每行操作 → `el-table`。
`el-table` 的哲学：**你只声明"有哪些列"，它自己把 `:data` 数组一行行铺出来**——声明结构、渲染交给组件，省掉后端那种手动循环拼行。

## 需求 2：展示"状态"（挂起 / 激活）

一个二元状态，要一眼能分辨。代码用 `el-tag` 带颜色。

| 候选 | 效果 | 取舍 |
|---|---|---|
| **`el-tag`** ✅ | 带背景色的小标签，`type` 控制红绿灰 | 状态类信息的行业惯例，色块比纯文字醒目 |
| 纯文字 `{{ }}` | 直接显示"挂起"/"激活" | 无视觉区分，扫一眼分不出哪些停了 |
| `el-badge` | 小圆点/角标（未读数 99+） | 语义是"数量提醒"，不是"状态标签" |
| 图标 `el-icon` | 一个 ✔/✖ 图标 | 无文字，用户要猜含义 |

**结论**：离散状态 + 要视觉分组 → `el-tag`，`type="success/info"` 把激活/挂起染成绿/灰。

## 需求 3：一个"只看最新版本"的开关（工具条）

布尔选项，开=只看最新，关=全部版本。代码用 `el-switch`。

| 候选 | 什么时候用 | 为什么这里选它 |
|---|---|---|
| **`el-switch`** ✅ | 表示"立即生效的开/关状态"（像电灯开关） | 切换后马上重查列表（`@change` 触发），"拨一下立刻见效"正是 switch 语义 |
| `el-checkbox` | 表单里"勾选后一起提交"的选项 | 更适合"填完表单再统一提交"，不强调即时性 |
| `el-radio` 单选组 | 3 个以上互斥选项 | 只有两态，radio 摆两个选项啰嗦 |
| `el-select` 下拉 | 选项多、占空间要收起 | 两个值用下拉是杀鸡用牛刀，多一次点击 |

**结论**：二元 + 即时生效 → `el-switch`。口诀：**"拨一下马上就变"用 switch，"勾了待会儿提交"用 checkbox**。

---

## 需求 4：每行的操作（挂起/激活、删除）

放表格最后一列，每行两个动作。代码用 `el-button link`（文字按钮）。

| 候选 | 效果 | 取舍 |
|---|---|---|
| **`el-button link`** ✅ | 一行平铺"挂起""删除"文字链接 | 操作少（2 个）、要一眼可见可点，最直接 |
| 普通 `el-button`（实心/描边） | 带边框块状按钮 | 塞进窄操作列太占地方、显拥挤 |
| `el-dropdown`（更多▾菜单） | 操作收进"⋯"下拉 | 操作 4、5 个以上才值得收起；2 个反而多一次点击 |
| 纯图标按钮 | 一个垃圾桶图标 | 省地方但要猜含义，删除这种危险操作最好有文字 |

**结论**：操作数量少（≤3）、要直接可点 → `el-button link`。多了才考虑收进 `el-dropdown`。
另注：删除叠了一层 `ElMessageBox.confirm` 做**危险操作二次确认**——这是交互惯例，不是组件选型。

## 需求 5：翻页（底部）

后端是分页接口（`current/size/total`）。代码用 `el-pagination`。

| 候选 | 适合 | 取舍 |
|---|---|---|
| **`el-pagination`** ✅（页码条） | 后台管理系统、要精确跳页/看总数 | 管理端要"看到共几条、跳第几页"，页码条最合适 |
| 无限滚动（滑到底自动加载） | 信息流、移动端（微博、抖音） | 后台表格要能回看、按页定位，无限滚动找不回位置 |
| "加载更多"按钮 | 移动端折中方案 | 同上，管理端不合适 |

**结论**：后台分页数据 → `el-pagination`。这里只用 `layout="total, prev, pager, next"`（不显示每页条数选择器），因为需求简单。

---

## 需求 6：整页怎么排（布局骨架）

三块（工具条/表格/分页）竖着摞，工具条内部左右分布。靠 `div` + `class` + `<style>` 里的 flex。

| 候选 | 取舍 |
|---|---|
| **`div` + flex（CSS）** ✅ | 简单的上下堆叠 + 一处左右分布，手写 flex 最轻，无额外组件负担 |
| `el-container`/`el-header`/`el-main` | 给**整个应用大框架**（侧栏+顶栏+内容区）用的，页面内部小布局太重 |
| `el-row` / `el-col`（24 栅格） | 适合**并排多列**的表单/仪表盘；这页竖向堆叠，用不上栅格 |

**结论**：页面内部竖向堆三块 → 一个 `div` 套三块 + `<style>` 几行 flex，不必上重型布局组件。

## 一张总表带走

| 展示需求 | 选中组件 | 一句话理由 | 什么时候换别的 |
|---|---|---|---|
| 一批同构记录 | `el-table` | 列对齐+分页+操作列标配 | 内容异构图文→`el-card` |
| 二元状态 | `el-tag` | 色块比文字醒目 | 只是数量提醒→`el-badge` |
| 即时开关 | `el-switch` | 拨一下马上生效 | 待提交的勾选→`el-checkbox` |
| 少量行内操作 | `el-button link` | 直接可见可点 | 操作≥4 个→`el-dropdown` |
| 后台翻页 | `el-pagination` | 要总数+跳页 | 信息流→无限滚动 |
| 页面骨架 | `div`+flex | 竖向堆叠最轻 | 并排多列→`el-row/col` |

---

## 方法论小结

> 组件选型不是背 API，而是：**"这块信息是什么形态" → 映射到语义匹配的组件 → 在多个能做的组件里，按交互惯例 + 复杂度取舍**。
> 后续任何页面（待办页、历史页…）都能用这套问法自己推出组件。
