# 插槽 slot 与作用域插槽（答疑笔记）

> 由答疑 CLI 整理。通用前端原理。触发点：`el-table` 里 `<template #default="{ row }">` 看不懂。
> 关联：`何时抽组件.md`（抽组件时 slot 常与 props 二选一）、`props 向下/events 向上`。
> 注：本篇偏难，第一次看不透正常，可结合真实代码 `views/process/index.vue` 状态列反复对照。

## 一句话定义

> **插槽 = 组件预留的"内容洞"**，让使用者把自定义 UI 填进去。
> 对比：**props 传数据（值），slot 传内容（UI/标记）**。

## 1. 解决什么问题

props 只能传数据（字符串/数字/对象），传不了"一段 UI 内容"。当父组件想把**一段界面**塞进子组件的某个位置（如按钮里的文字、卡片的头部）时，用插槽。
组件负责把这个洞摆在正确位置、套好外观；使用者只管填内容。

## 2. 你早就在用（没意识到）

```html
<el-button link type="danger">删除</el-button>
```
「删除」就是塞进 el-button **默认插槽**的内容。el-button 内部：
```html
<button class="el-button ..."><slot></slot></button>   <!-- <slot> 就是那个洞 -->
```
你写在 `<el-button>…</el-button>` 中间的东西，会被填到 `<slot>` 的位置。

## 3. 具名插槽：一个组件多个洞

组件给每个洞起名字：
```html
<div class="card">
  <div class="card-header"><slot name="header"></slot></div>
  <div class="card-body"><slot></slot></div>        <!-- 没名字的叫 default -->
  <div class="card-footer"><slot name="footer"></slot></div>
</div>
```
填的时候用 `#洞名` 指定（`#header` = `v-slot:header` 简写）；**没起名的主洞叫 `default`**，故 `#default` = 填主洞。

## 4. 作用域插槽：组件把数据"回传"给你（关键）

普通插槽写内容时就知道填什么。但 **el-table 的行数据在写代码时还不存在**——运行时才从 `:data="list"` 来，在 el-table 内部循环里。你写模板时拿不到 `row`。

解法：**el-table 反过来把每行数据"递给"你的插槽内容**。这种插槽叫**作用域插槽**。el-table 内部（伪代码）：
```js
for (const [index, row] of list.entries()) {
  渲染单元格( 你的default插槽内容({ row, column, $index: index }) )  // ← 回传当前行
}
```
它**像调函数一样调用你的插槽内容**，把 `{ row, column, $index }` 当参数传进去。
你的 `<template #default="{ row }">…</template>` 就是那个"函数体"，`{ row }` 是它的参数。

## 5. 拆解 `<template #default="{ row }">`

```
<template   #default   ="{ row }">
   零件A       零件B        零件C
```

**零件A `<template>` —— 隐形包裹标签**
本身不产生任何 HTML，是"透明外壳"，作用仅是给插槽指令找地方挂。

> ⚠️ 别混：这个内层 `<template>` 和文件**最外层**那个 `<template>` 只是**名字撞车**：
> - 最外层 `<template>`：SFC 规定的"本组件界面写这里"，全文件仅一个，编译器固定结构。
> - 内层 `<template #xxx>`：透明分组标签，专门挂插槽指令（或 v-if/v-for），自己不渲染成 DOM。
> 记忆：外层是"组件的皮"，内层是"给插槽挂指令的隐形夹子"。

**零件B `#default` —— 填哪个洞**
填 el-table-column 的 `default` 插槽（单元格内容洞）。`#default` = `v-slot:default` 简写。

**零件C `="{ row }"` —— 接收回传数据**
接住 el-table 递来的对象 `{ row, column, $index }`，用 **JS 解构**只挑出 `row`（其余不要就不写）。

**整体读法**：「我来填 el-table-column 的默认单元格，请把当前行数据给我，我只取 row。」→ 洞里就能用 `row.suspended` 判断。

## 6. 后端类比

| 前端 | 后端类比 |
|---|---|
| props（传数据） | 方法传**值参数** |
| 普通插槽（传内容） | 传一段**代码块/回调**进去，由方法在合适位置执行（模板方法模式） |
| 作用域插槽（`{ row }`） | 传一个 **lambda**，方法循环时带参回调：`list.forEach(row -> 你的代码(row))` |

el-table 就像 `forEach`：**循环由它控制，每格画什么它回调你的插槽内容、并把 row 喂给你**。即"循环归 el-table、单个格子内容归你"。

## 一句话总结

> 插槽 = 组件预留的内容洞（props 传数据、slot 传内容）。`#default` 填默认洞；**作用域插槽**让组件把数据回传给填洞内容。`<template #default="{ row }">` 中：`<template>` 是挂指令的隐形夹子（≠ 组件最外层同名标签），`#default` 指定洞，`{ row }` 解构接住 el-table 回传的当前行。整体就像 `forEach(row -> 你的模板(row))`。

## 用途场景（本项目）

P4 所有表格的自定义列都是这一套路：状态列（彩色 tag）、操作列（按钮）、时间格式化列等——凡是"不能原样显示字段文字、要加工或渲染组件"的列，都用作用域插槽。反之纯文字列用 `prop`（见 `../process_manage/组件选型解析.md` / 状态列答疑）。

# 补充：插槽的背景 / 目的 / 场景

> 上面偏"机制怎么运作"，这里补"为什么存在、用在哪"。抓手：**props 传数据、slot 传 UI**。

## 先看那句话的"墙"

"props 只能传数据"背后有一堵墙。封装一个"卡片"组件：边框/阴影/圆角固定，但**里面放什么内容由使用者定**（文字/表格/表单）。只有 props 时怎么传"内容"？

- **把 HTML 当字符串传** `content="<h1>…</h1>"`——死的，不能响应式、不能用指令、有 XSS、塞不了 Vue 组件。走不通。
- **把每种内容都做成 props** `title/body/hasButton/buttonText…`——内容一复杂 props 就爆炸，且永远预测不完。

**这堵墙就是插槽诞生的根本原因：数据能用 props 传，但"一段任意 UI 结构"传不了。** 插槽来拆这堵墙。

## 一、诞生背景

老思想 + Web 标准的汇流：

1. **"带洞的模板"（transclusion）**：固定框架、留几个空让使用者填。像合同/简历模板印好格式、留"姓名____"让你填。前端框架很早就有（Angular 1 的 transclusion）。
2. **原生 `<slot>` 元素**：浏览器 Web Components 标准（Shadow DOM）里有原生 `<slot>`，专管"预留内容洞"。Vue 直接沿用其名字与概念，与 Web 标准对齐。

> React 用 `children` / render props 解决同一问题。"让组件接收外部内容"是所有组件化框架的共同刚需。

## 二、设计目的

1. **内容的控制反转**——组件管"框架长啥样、洞开在哪、外观"；使用者管"往洞里填什么"。类比后端**模板方法模式**：骨架定好、留一步让人填。
2. **避免 props 爆炸、换取真复用**——组件只开一个洞，就能容纳无限种它当初没预料的内容；"通用组件"通用的关键是**不需预知你要放什么**。
3. **精确划分数据归属（作用域插槽）**——有些数据只有组件内部才有（如 el-table 循环出的 `row`），组件把它回传给使用者内容，变成"**组件掌管数据、使用者掌管怎么渲染**"。解决"想自定义渲染、但数据在组件肚子里"的矛盾。

## 三、应用场景（配项目实例）

| 场景 | 说明 | 在哪遇到 |
|---|---|---|
| ① 容器/布局组件 | 外壳固定，中间内容任填 | `el-card`、`el-dialog`——P4 编辑/办理弹窗：主体放表单（默认插槽）、底部放按钮（`#footer` 插槽） |
| ② 列表/表格自定义渲染 | 组件负责循环，每格怎么画交给你（作用域插槽） | `el-table-column` 状态/操作列（已遇到）、`el-select` 自定义选项 |
| ③ 包裹/装饰组件 | 给任意内容套一层行为或样式 | `el-tooltip`、`el-popconfirm`（给删除按钮套二次确认）、可折叠面板 |
| ④ 默认内容兜底 | 洞里预设默认内容，没填就显示默认 | 空状态、占位提示 |
| ⑤ 无渲染/逻辑组件 | 组件只管逻辑和数据、不画界面，把数据交给你画 | 进阶：数据请求器、拖拽器等"只提供能力、UI 你定" |

①②③ 是 P4/P5 一定会碰的：编辑弹窗（①）、表格自定义列（②）、删除二次确认（③）。

## 补充小结

> **背景**：props 传不了"任意 UI 结构"（字符串死板、props 爆炸），催生插槽；承接"带洞模板"老思想 + Web Components 原生 `<slot>`。
> **目的**：内容控制反转、避免 props 爆炸换真复用、精确划分数据归属（作用域插槽）。
> **场景**：容器/布局、表格自定义渲染、包裹装饰、默认兜底、无渲染逻辑组件。
