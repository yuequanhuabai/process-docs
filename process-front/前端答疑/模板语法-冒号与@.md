# 模板里的 `:` 和 `@` 是什么（答疑笔记）

> 由答疑 CLI 整理。通用前端原理 · **地基级**。触发点：读 `el-pagination` 时问"每个字段什么意思"，顺带发现——**一直不知道组件标签里的 `:` 和 `@` 是干嘛的**。
> 关联：`v-model双向绑定.md`、`change事件.md`、`props向下events向上.md`、`插槽slot与作用域插槽.md`、`受控组件与el-pagination.md`。
> 环境：Vue 3.5.39 / Element Plus 2.14.2。

---

## 一、一句话

> **`:` 是 `v-bind:` 的简写，`@` 是 `v-on:` 的简写。** 它们不是什么特殊符号，就是把前面那截指令名省掉了。

```html
<el-pagination :total="total"   @current-change="fn" />
<el-pagination v-bind:total="total" v-on:current-change="fn" />   <!-- 完全等价 -->
```

认出这一点，模板里 90% 的"看不懂的符号"就没了。

---

## 二、三类属性，一眼分辨

同一个标签上常常三种混着写，这是最初的困惑来源：

```html
<el-pagination
    class="pager"                          ← ① 静态：原样传字符串
    layout="total, prev, pager, next"      ← ① 静态（虽然长得像配置，仍是字符串）
    :total="total"                         ← ② 动态：把引号里当 JS 表达式求值
    @current-change="handlePageChange"     ← ③ 事件：订阅
/>
```

| | 写法 | 引号里的东西被当成 | 传过去的值 |
|---|---|---|---|
| ① 静态 | `total="10"` | **字符串字面量** | 字符串 `"10"` |
| ② 动态 `:` | `:total="10"` | **JS 表达式** | 数字 `10` |
| ② 动态 `:` | `:total="total"` | **JS 表达式** | 变量 `total` 当前的值 |
| ③ 事件 `@` | `@click="fn"` | **JS 语句/函数引用** | —— 订阅事件，不传值 |

**加不加冒号，是"字符串"和"JS"的分界线。** 这是 Vue 模板里最重要的一条语法直觉。

### 一个能立刻看出差别的对比

```html
<el-pagination :total="total" />   <!-- ✅ 传变量的值，比如数字 23 -->
<el-pagination  total="total" />   <!-- ❌ 传字符串 "total" 这五个字母 -->
```

第二种不会报语法错，但组件声明 `total` 是 `Number`（`pagination.d.ts:9`），拿到字符串会在控制台报类型警告，页数算出来是 `NaN`，页码区直接乱掉。**这种 bug 不会在编译期被抓到**（`vue-tsc` 对模板里 Element Plus 组件的 prop 类型检查有限），只能靠你认得这个语法。

## 三、为什么必须有这个区分：HTML 的先天限制

**HTML 属性的值天生只能是字符串。** 原生 HTML 里：

```html
<input maxlength="10">   <!-- 这个 10 在 DOM 里是字符串 "10" -->
```

但组件的 props 需要各种类型——数字、布尔、数组、对象、函数：

```html
<el-pagination :total="23" :disabled="false" :page-sizes="[10, 20, 50]" />
```

如果没有"动态绑定"这个开关，上面这些全会变成字符串 `"23"`、`"false"`、`"[10, 20, 50]"`——**注意 `"false"` 是个非空字符串，布尔判断为真**，`disabled` 反而会生效。

所以框架必须提供一个标记，告诉编译器："**这个引号里装的不是文本，是代码，请求值后再传。**" Vue 选的标记就是属性名前面加一个 `:`。

**为什么选 `:` 和 `@` 这两个符号**：HTML 规范对属性名很宽松，浏览器解析 `<div :foo="1" @bar="2">` 不会报错（当成普通未知属性），Vue 的编译器再把它们识别成指令。既短，又不与已有语法冲突。

## 四、历史：从 `v-bind:` 到 `:`

**Angular 1（2010）**：`ng-bind`、`ng-click`、`ng-model` —— 用属性名前缀区分"这是框架指令"，思路的源头。
**Vue 1.x（2015）**：`v-bind:total`、`v-on:click`，同时**一开始就提供了 `:` 和 `@` 简写**。
**Vue 2/3**：语法保持不变，简写成为绝对主流——现实项目里几乎见不到有人写全称。
**React 走的另一条路**：JSX 用 `{}` 表示求值 —— `<Pagination total={total} onChange={fn} />`。**同一个问题的两种答案**：Vue 在 HTML 里开一个"进入 JS"的口子（冒号），React 直接在 JS 里写 HTML（JSX）。

**为什么要有简写**：`v-bind:` 六个字符，一个中等复杂的表单几十个绑定，全写会让模板被指令名淹没、看不见结构。简写后 `:` 和 `@` 是两个视觉上很轻的符号，扫一眼就能分辨"这行是传数据还是接事件"。

**代价**：对新手来说是**两个没有字面含义的符号**——不知道它是 `v-bind` 的缩写时，`:total` 看起来像凭空出现的魔法。这正是你之前卡住的原因，也是简写永远的学习成本。

## 五、简写全表（Vue 3）

| 指令 | 简写 | 用途 | 本项目里的例子 |
|---|---|---|---|
| `v-bind:x` | `:x` | 传值给 prop / 设置属性 | `:total="total"` |
| `v-on:x` | `@x` | 监听事件 | `@current-change="handlePageChange"` |
| `v-slot:x` | `#x` | 具名插槽 | `<template #default="{ row }">` ← **`el-table` 里那个 `#`** |

三个符号一次记全。`#` 那个正是 `插槽slot与作用域插槽.md` 里出现的写法——原来它和 `:` `@` 是同一类东西。

### 几个衍生写法（认得即可）

```html
<!-- 无参数 v-bind：把对象的每个键都当成 prop 铺开 -->
<el-pagination v-bind="paginationProps" />

<!-- 同名简写（Vue 3.4+，本项目 3.5.39 可用）：:id="id" 可省成 :id -->
<el-input :id />

<!-- 事件修饰符：在 @ 后面串修饰行为 -->
<form @submit.prevent="onSubmit">     <!-- 自动 event.preventDefault() -->
<div @click.stop="fn">                <!-- 自动 event.stopPropagation() -->

<!-- 动态参数：属性名本身也能是变量 -->
<el-input :[propName]="value" />
```

`.prevent` / `.stop` 这类修饰符的意义：这些是**每次写事件处理都要重复的样板代码**，Vue 把它们提成了声明式后缀，省得每个 handler 里都写一遍 `e.preventDefault()`。

## 六、一个真实的坑：属性名的大小写

组件内部的 prop 是驼峰（`pageSize`、`currentPage`），模板里写成**短横线**（`:page-size`、`:current-page`）。

- **在 `.vue` 单文件组件里**，两种写法 Vue 都能认（编译器会自动转换）；
- **但在 in-DOM 模板里**（直接写在 `index.html` 的标签里）**只能用短横线**——因为浏览器解析 HTML 时会把属性名统一转成小写，`:pageSize` 会变成 `:pagesize`，Vue 就认不出来了。

**约定统一用短横线**，与 HTML 习惯一致，也不用记哪种场景能用哪种。事件名同理：`@current-change` 而不是 `@currentChange`。

## 七、动手实验

在 `views/process/index.vue` 上临时改，看完改回来。

**实验 1 · 冒号的有无**
把 `:total="total"` 改成 `total="total"` → 控制台出现 prop 类型警告，页码区异常（`total` 变成了字符串）。

**实验 2 · 静态值也可以加冒号**
把 `:page-size="size"` 改成 `:page-size="10"` → 一切正常，因为 `10` 作为 JS 表达式求值就是数字 10。再改成 `page-size="10"`（去掉冒号）→ 传的是字符串 `"10"`，虽然多数情况下能"歪打正着"（JS 弱类型会隐式转换），但会有类型警告。**这两个实验放一起看，冒号的作用就彻底清楚了。**

**实验 3 · 展开成全称**
把 `:total="total" @current-change="handlePageChange"` 改写成 `v-bind:total="total" v-on:current-change="handlePageChange"` → 行为**完全一样**。亲手验证"简写就是简写"。

## 八、常见误解速查

| 误解 | 实际 |
|---|---|
| `:` 是 Vue 的特殊变量语法 | ❌ 只是 `v-bind:` 省略了前面 6 个字符 |
| 加不加冒号差不多 | ❌ 差别是"传字符串"还是"传 JS 求值结果"，类型完全不同 |
| `@` 是装饰器 / 特殊注解 | ❌ 是 `v-on:`，订阅事件而已 |
| `:total="total"` 里两个 total 必须同名 | ❌ 左边是 **prop 名**（组件定的），右边是**你的变量名**（随便叫）。这里同名纯属巧合 |
| `#default` 是另一套语法 | ❌ 是 `v-slot:default` 的简写，与 `:` `@` 同族 |
| 引号里只能写变量名 | ❌ 是完整 JS 表达式：`:total="total * 2"`、`:disabled="loading || !list.length"` 都合法 |

---

## 九、一句话总结

> **`:` = `v-bind:`（传值，引号里当 JS 求值）；`@` = `v-on:`（订阅事件）；`#` = `v-slot:`（插槽）。**
> 它们存在的根本原因：HTML 属性天生只能装字符串，而组件 props 需要数字/布尔/数组/对象——必须有个开关告诉编译器"这里面是代码不是文本"，那个开关就是冒号。
> 简写是为了让模板里看得见结构而不是指令名，代价是对新手成了三个无字面含义的符号。

## 十、往下可以再挖的

- **`v-model` 的真面目**：它是 `:modelValue` + `@update:modelValue` 的组合语法糖 —— 见 `v-model双向绑定.md`，现在可以用本篇的眼光重读一遍。
- **模板到底被编译成了什么**：`<el-pagination :total="total" />` 最终会变成 `createVNode(ElPagination, { total: total.value })` 这样的渲染函数调用。想彻底破除"模板是魔法"的感觉，可以在 [Vue SFC Playground](https://play.vuejs.org) 里贴一段模板，右侧直接看编译产物。
