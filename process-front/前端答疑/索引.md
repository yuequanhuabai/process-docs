## 这条原理链（Vue 数据流 / 组件）

几个高频概念是连贯的一条链，建议按此顺序理解（**均已成文**）：

0. **`模板语法-冒号与@.md`** —— **地基，建议先看这篇**：`:`／`@`／`#` 分别是 `v-bind:`／`v-on:`／`v-slot:` 的简写。认出这三个符号，下面四篇里的写法就都不神秘了。
1. **`v-model双向绑定.md`** —— 双向绑定，是 `:绑值 + @监听回写` 的语法糖。
2. **`change事件.md`** —— `v-on:change`，订阅组件发出的 change 事件；对比 `watch`。
3. **`props向下events向上.md`** —— 单向数据流总纲，`v-model`/`@change` 都是它的招式。
4. **`何时抽组件.md`** —— 什么时候为一段 UI 定义 props/events 契约。
5. **`插槽slot与作用域插槽.md`** —— props 传数据、slot 传内容；抽组件时的另一种传递方式。
6. **`受控组件与el-pagination.md`** —— 前五篇的合流实例：一个真实组件是怎么把 props 向下 + events 向上组装成"受控"契约的。P6 表单设计器要**自己写**这套契约，这是那时的地基。
7. **`配置型子组件与el-table.md`** —— 同一页的另一半。第 6 篇讲"组件与你之间"怎么传，这篇讲"父组件与子组件之间"怎么传：`<el-table-column>` 不渲染任何东西，只把一份配置注册进父表格。`<el-option>`／`<el-tab-pane>`／`<el-step>` 全是同一套。**第 6、7 两篇合起来是 P6 表单设计器的两块基石。**
8. **`原生控件的外衣与el-switch.md`** —— **回到第 1、2 篇的源码级复盘**，链条在这里闭合：`v-model` 展开成什么、`@change` 和它谁先谁后（有源码为证）、组件底层藏着什么。第 1、2 篇讲"怎么用"，这篇讲"为什么它一定是对的"。**第 1、2 篇看过一遍后再读这篇，收获最大。**

## 另一条链（JS 异步）

与上面的 Vue 数据流链无关，是另一条独立地基：

1. **`async-await与JS单线程.md`（第二版）** —— await 挂起函数而非线程；单线程 + 事件循环为什么必须这样；**编译成 ES5 状态机看它的真身**。第八节已顺带讲了微任务队列与实测时序。
2. **`请求竞态与控件禁用.md`** —— **第 1 篇的直接后果**：函数在 `await` 处交出控制权 ⇒ 用户能点第二下 ⇒ 两个请求同时在飞 ⇒ **响应顺序无保证** ⇒ 后回的静默覆盖先回的。第 1 篇讲"await 不阻塞"是好事，这篇讲**它的账单**。收口在 `:disabled="loading"` 与 `try/finally` 的咬合。**实验 3 专门证明"再加个 await"治不了。**
3. *（待写）事件循环的完整图景* —— 宏任务 / 微任务 / 渲染时机（`requestAnimationFrame` 插在哪）。第 1 篇只用到了"微任务优先"这一层。
4. *（待写）`Promise.all` 并发 vs 逐个 await 串行* —— 页面要同时拉多份数据时用得上；循环里 await 是最常见的性能陷阱。第 1 篇第四节的适用场景表已给了结论，这篇展开。
5. *（待写）`AbortController` 与请求取消* —— 第 2 篇 §9 留的坑：`disabled` 是 80% 方案，搜索框那种"每敲一个字发一次"的场景它完全失效。P6 表单设计器会撞上。

> **两条链的交汇点**：`原生控件的外衣与el-switch.md` 第四节讲的"变量同步更新、DOM 异步更新"，那个"异步"就是本链的微任务队列（Vue 的 `nextTick`）。

## 第三条链（TypeScript 语言本身）

与上面两条都无关，是 2026-08-04 起的新链 —— 前两条讲 Vue 和 JS，这条讲**类型系统**。贯穿全链的一条主线是：**TS 的类型只活在编译期，擦除后运行时一无所有**，由此推出的结论比要背的条文多得多。

1. **`字面量联合类型与enum.md`** —— **本链地基**：`'A' | 'B' | 'C'` 是什么、为什么不是 enum、为什么 enum 被生态判出局。核心概念「类型 = 值的集合」在后面每一篇都要用。
2. **`null与undefined.md`** —— 同一个文件的另一半疑问：`| null` 和 `?:` 什么时候用哪个。答案是**方向决定写法**，根据是「JSON 里没有 undefined」。含 JS 为什么有两个空值、`strictNullChecks` 的来历。**第 1、2 两篇合起来，`api/instance.ts` 的每一行类型标注就都有出处了。**
3. **`Record与映射类型.md`** —— **本链最抽象的一篇**（首次涉及"用类型生成类型"），文内有分两次读的指引：现在只看第零、四节就够写代码，机制那层留到 P6 再啃。含 `unknown` vs `any` vs Java `Object` 的三方对照。**它同时是 P6 表单设计器的动机说明**（见下）。
4. *（待写）TS 的冒号语法为什么类型在后* —— 硬约束「任何合法 JS 必须是合法 TS」→ `function f(Type row)` 会被解析成"两个参数少了逗号"，语法撞车 → 只能把类型塞到标识符后面。语序来自 Pascal / ML 一脉。**讲法已成型，见仓库根 `../../讲解规则.md` §二 范例 B，尚未落成单篇。**
5. *（待写）`as const` 与从值推导类型* —— 第 1 篇的直接续集，也是 `statusOptions` 那个口子的正经修法。
6. *（待写）`keyof` 与映射类型修饰符* —— 第 3 篇第九节列的坑：`Partial<T>`/`Required<T>` 怎么就一行写出来的，以及怎么从一个对象**反推**出它的键集合。
7. *（待写）类型收窄与穷举检查* —— `switch` 全部分支走完后配合 `never`，做到"漏一个状态就编译报错"。
8. *（待写）结构化类型 vs 名义类型* —— 为什么 TS 里两个字段相同的 interface 能互相赋值，Java 里不行。**后端背景的人最容易在这里栽跟头。**
9. *（待写）边界校验 zod / valibot* —— **本链的收口**：前三篇各挖出一个洞（类型不校验后端返回值、`| null` 只是人肉承诺、值类型的真实约束在 Flowable 引擎里），正经修法都是在 HTTP 边界做一次运行时校验。

> **贯穿全链的一句话**：**TS 的保护到 HTTP 边界为止。** 第 1 篇（后端返回非法 status 拦不住）、第 2 篇（`| null` 只是手抄的承诺、`suspended` 类型对了值不对）、第 3 篇（Flowable 只认几种变量类型，TS 和 Java 都表达不出来）都是这句话的实例，第 9 篇是它的解法。
>
> **通往 P6 的伏笔**：第 3 篇第七节 ② 说清了「键开放 = 拼错不报错」为什么是病，以及**把 K 从无穷集换成有限集，拼写错误就从运行时静默变成编译期报错** —— 这正是 P6 表单 schema 存在的理由。做 P6 前回读那一节。
>
> **与后端的交汇点**：第 1 篇第六节把前端 `InstanceStatus`、后端 `ProcessInstanceVO.java:17-19` 的 String 常量、`statusOf()`、`applyStatusFilter()` 四处串了起来 —— 四处字面值必须人工对齐，两边编译器都帮不上忙。
