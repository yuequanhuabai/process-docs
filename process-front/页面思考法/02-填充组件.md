## 一、方法：选型三问

**不要背「列表页用 el-table」。** 要背这三句——它对任何 UI 库、任何框架都成立：

| 问 | 在问什么 |
|---|---|
| **① 用户在这个位置要做什么动作？** | 读 / 选 / 点 / 输 —— 四种之一 |
| **② 这个动作的「选项空间」有多大？会变吗？** | 2 项？5 项？无穷？将来会增加吗？ |
| **③ 哪个组件的形态，恰好匹配这个空间？** | 组件是**形态**，动作是**需求**，选型就是配对 |

下面把三问在三条带上各跑一遍。

---

## 二、条带 ① 工具条

**外壳**：一个普通 `div`，里面左右两样东西。

**不用栅格**（`el-row`/`el-col`）——栅格是为「多列等分、随屏幕换行」设计的；这里只是左右各一个、永不换行，用 flex 两端对齐更直接（怎么对齐是第 ③ 步的事）。

**左边**：标题，纯文字，一个 `span`。**没有动作就不需要组件**。

**右边**——真正要决策的地方，跑三问：

| 问 | 答 |
|---|---|
| ① 动作 | **选**：从若干流程里挑一个来过滤列表 |
| ② 选项空间 | 4 个流程 + 「全部」= **5 项**，而且**会增长**（P5 部署新流程后就是 5 个、6 个…） |
| ③ 匹配 | 见下表 |

| 候选 | 适用的选项空间 | 这里行不行 |
|---|---|---|
| `el-radio-group` | **≤ 3 项且恒定** | ❌ 5 项横排已经很挤，加流程会把工具条撑破 |
| `el-tabs` | 切换的是**不同视图** | ❌ 语义错位。tabs 说「这是另一个页面」，这里只是「同一个列表换过滤条件」 |
| `el-input` 手输 | 选项**无穷**（如搜名字） | ❌ 选项有限已知，让用户手打 key 是灾难 |
| **`el-select`** | **4 ~ 10 项，可增长** | ✅ **选它**。宽度恒定，选项再多也不撑破布局 |

### 分界线为什么大致在 3 和 10

⚠️ **这是重点，不是「项数少用 radio」这么一句。** 分界线来自**两条相反的成本曲线**：

```
项数：  1    2    3    4    5  ...  10   11   12  ...
       └──radio 划算──┘         └──select 划算──┘   └─要加搜索─┘
```

| | radio（全部常驻可见） | select（收成一个框） |
|---|---|---|
| **横向空间** | 每加一项就变宽 → **随项数线性增长** | **恒定**，不管几项 |
| **点击成本** | **0 次**，看见就能点 | **1 次**，得先点开 |

- **左边界 ≈ 3**：项数少时 radio 那点宽度不算事，而「省一次点击」是实打实的收益 → radio 赢。项数一多，宽度成本超过省下的那次点击 → 换 select
- **右边界 ≈ 10**：select 宽度虽恒定，但**展开后的列表长到要滚动**，用户得用眼睛线性扫 → 该加搜索，把「扫」变成「打」

> **真正的判据不是项数，是「空间成本 vs 点击成本，谁先超标」。** 3 和 10 只是这两条曲线在常见字号下的交点——换个场景（比如手机屏）交点就前移。

## 三、选完组件才是一半：两个衍生决策

⚠️ **这一节是新手和熟手的分水岭。** 选中 `el-select` 只解决了「用什么」，还有两个问题没答。

### 衍生① 选项列表从哪来？

| 方案 | 做法 |
|---|---|
| **A 硬编码** | 把四个 key（`leaveProcess` / `reimburseProcess` / …）写死在前端 |
| **B 调接口** | 拉流程定义列表回来动态渲染 |

成品选了 **B**（`loadDefs()` 调 `pageDefinitions(1, 100, true)`）。

**理由：流程模板是「数据」，不是「常量」。** P5 做完设计器后可以在界面上部署新流程——硬编码的下拉当天就漏项。

**代价（要认）**：多一个 ref 存选项、多一次请求、页面加载时**两个请求并发**（一个拉选项、一个拉列表）。

> `size` 给了 100——流程模板就几个，一次拉完，**故意不给下拉做分页**。这是「知道数据量级后的合理偷懒」，不是 bug。

### ⚠️ 硬编码方案真正输在哪：静默漏项

问「硬编码会出什么问题」，容易只答出「新流程筛不到」。**关键的后半句是：会报错吗？**

**不会。** 一行错误日志都没有，控制台干干净净，页面看起来完全正常——只是那个下拉里**少了一项**。用户永远筛不到新流程，而且**不会有人知道**，直到某天有人问「为什么采购流程筛不出来」。

> **静默漏项**：代码没错、不崩、不报警，只是**默默地少做了一部分工作**。它比崩溃危险得多，因为崩溃会立刻被发现。
>
> **判断方案好坏，不能只问「会不会出错」，要问「出错时我会不会知道」。** —— 见 `00-总纲` 元方法 B。

### 衍生② 「全部流程」这一项，值用什么？

用**空字符串 `''`**，不是 `null`、不是 `undefined`。三个理由连成一条链：

1. `v-model` 绑的 ref 需要**初始值**，空字符串天然表示「还没选」
2. `api/instance.ts:35` 写的是 `definitionKey || undefined` —— 空串被转成 `undefined`，axios 遇到 `undefined` 的参数**直接不拼进 URL**，后端就收到「不过滤」
3. 「全部」这一项**要手写一条选项**（`value=""`），它不会自动出现

> 这三步正好是 [`../前端答疑/null与undefined.md`](../前端答疑/null与undefined.md) 讲的事：**空值在「界面 → 前端变量 → HTTP 参数 → 后端」四段路上，每段的表示法都不一样**，写代码时得知道自己在哪一段。

## 四、条带 ② 数据区

**组件**：`el-table` + 若干 `el-table-column`。

跑三问几乎没有余地——二维结构化数据、要表头、要对齐，表格就是唯一答案。（唯一替代是卡片列表，适合手机端和图文混排。）

### 真正要决策的是：每一列怎么渲染

⚠️ **不要背规则表。记这一句：**

> **「这一格，能不能把字段的值原样打印出来？」**
> **能 → `prop` 直出。不能 → 用插槽。**

现在用这一句现场推一遍，规则自己长出来：

| 列 | 能原样打印吗？ | 结论 |
|---|---|---|
| 流程名称 | 能，`"报销流程"` 打出来就是它 | `prop` |
| 发起时间 | 能 | `prop` |
| 业务标识 | **不能**——值可能是 `null`，打出来是空白 | 插槽（兜底 `—`） |
| 当前节点 | **不能**——同上 | 插槽 |
| 发起人 | **不能**——姓名为空时要退回显示 id，这是个判断 | 插槽 |
| 操作 | **不能**——要放一个能点的按钮，根本不是「值」 | 插槽 |

**「不能原样打印」只有三种原因：要兜底、要转换、要放能点的东西。** 不用背这三条——问一遍那句话，答案自己就出来。

> 插槽本身是怎么回事，见 [`../前端答疑/插槽slot与作用域插槽.md`](../前端答疑/插槽slot与作用域插槽.md)。

### 为什么空值要兜底成 `—` 而不是留白

留白会让用户分不清「**没有这个值**」和「**页面渲染坏了**」。`—` 是明确的「此处无内容」。后台表格的通用约定。

### 两个容易忽略的点

**（1）加载态挂在表格上，不是挂在整页上。**

`v-loading` 加在 `el-table` 而不是最外层 div——转圈时**工具条还是可用的**，用户能在加载中改筛选条件。遮住整页会连下拉都点不动。

**（2）操作列钉在右边（`fixed="right"`）。**

列一多，表格横向滚动，操作按钮会被滚出视野。钉住右侧让它永远可点。同样是通用约定。

### 案例的一处实际取舍：砍掉「实例 ID」列

原型图第 ① 节画了 **7 列**，含一列「实例 ID」（`a1b2c3d4-…`）；成品是 **6 列**。

| | |
|---|---|
| 砍掉的理由 | UUID 又长又对用户无意义，而「终止」操作在代码里直接拿 `row.id`，**不需要显示给人看** |
| 留着的理由 | 排错时能直接从界面拿 id 去查库 / 调 knife4j |

**2026-08-05 决策：砍掉，将来在操作列加一个「复制 ID」按钮补上排错需求。**（连带影响见 `03` 第五章：操作列宽度要跟着放大。）

> 顺带一条：**原型图会过期。** 这张图画于 07-30，上面用红虚线标了「当前节点」「发起人」是后端没有的字段——但后端 08-03 已经补上（`enrich()` 填了 `currentActivityName`，发起人也从 userId 换成了姓名）。**照原型规划前先确认字段现状。**

## 五、条带 ③ 分页条

**组件**：`el-pagination`。动作是「换页」，选项空间是「1 到 N 页」且 N 由数据决定——没有别的候选。

### 这条带唯一的知识点：受控

⚠️ **同样不要背「要传值 + 要监听」。记这一句：**

> **「这个组件自己记不记状态？」**
> **不记（受控）→ 必须双向接线：值传进去 + 变化传出来，缺一不可。**

```
你的变量 current ──:current-page──→ 分页器  （我告诉你现在第几页）
你的变量 current ←──@current-change── 分页器  （用户点了第几页，你自己去改）
```

**分页器自己不记页码。** 它只显示你给它的 `current-page`，用户点击时它**只是通知你**，改不改是你的事。

**用这句话推后果**：只传 `:current-page`、忘了 `@current-change` → 用户点「第 2 页」，分页器**通知了但没人接**，你的 `current` 还是 1，它显示的还是 1 → **点了没反应，页面像卡死一样，但控制台没有任何报错。**

> 又一次静默失败（本篇第二次）。**给「静默」留个警报器。**

**这句话还能迁移**：`el-switch`、`el-select`、`el-input`——Element Plus 里凡是 `v-model` 的东西，底下全是这套「不记状态、双向接线」。**`v-model` 只是把这两根线缩写成了一个字。**

> 详见 [`../前端答疑/受控组件与el-pagination.md`](../前端答疑/受控组件与el-pagination.md)、[`../前端答疑/v-model双向绑定.md`](../前端答疑/v-model双向绑定.md)。

### `layout` 属性

是个字符串，决定显示哪几个零件（总数 / 上一页 / 页码 / 下一页 / 每页条数…）。

这页**不给「每页条数」下拉**——`size` 固定 10。给了用户就得处理它变化，**多一个状态多一处出错**。

## 六、不参与布局的那类组件，在这一步定

第 ① 步说过弹窗是命令式的、不占模板位置。**这一步决定用哪个。**

点「终止」要让用户填原因 → 用 `ElMessageBox.prompt`，**不是 `confirm`**。

**区别**：prompt **带输入框**。

**为什么必须带**：后端 `terminate` 接口收一个 `reason` 参数（`ProcessInstanceController.java:52`）。

> **组件选型被后端接口的形状决定了。** 这种事在真实项目里很常见——所以第 ② 步之前最好已经知道要调哪些接口、各收什么参数。

对照：流程管理页的「删除」用的是 `confirm`（`views/process/index.vue:107`），因为删除接口不收原因，只需要一个「确定/取消」。

## 七、检查点

1. 「≤3 用 radio、4~10 用 select」——这个分界线**为什么大致在 3 和 10**？
2. 下拉选项如果**硬编码**四个流程，什么时候会出问题？**出问题时会报错吗？**
3. 表格 6 列里，哪几列**必须**用插槽？三种理由各对应哪列？
4. 如果给分页器传了 `:current-page="current"` 但**忘了写** `@current-change`——页面会怎么表现？
5. 为什么这里用 `prompt` 而不是 `confirm`？这个决定是谁逼出来的？

<details>
<summary>参考答案</summary>

1. 不是「项数少」。是两条成本曲线：radio 的**横向空间随项数线性增长**、但**点击成本为 0**；select **宽度恒定**、但**多一次点击**。左边界是「空间成本超过省下的那次点击」，右边界是「展开列表长到要滚动、得改用搜索」。判据是**哪个成本先超标**。
2. 新部署的流程**默默不出现**在筛选里。**不会报错**——控制台干净、页面正常，只是少一项，**没人会发现**。这叫静默漏项。
3. 业务标识（要兜底 `null`→`—`）、当前节点（同）、发起人（要转换：姓名空时退回 userId）、操作列（要放能点的按钮）。判据一句话：**「能不能把值原样打印出来」**。
4. **点了没反应**，页面像卡死，**但控制台无任何报错**。因为分页器不记状态，它只通知你，你没接就没人改 `current`，它显示的还是原值。
5. 因为后端 `terminate` 要收 `reason`（`ProcessInstanceController.java:52`），必须让用户填 → 得带输入框 → prompt。**是后端接口的形状逼出来的选型。**

</details>
