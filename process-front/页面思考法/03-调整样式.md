## 一、为什么这一步这么短：90% 的视觉决策已经被替你做完了

先数一数**不用你写**的东西：表格的边框、表头底色、行 hover 变色、圆角、字号、行高、按钮配色、下拉展开动画、分页器的全部样式……**一行都不用写。**

这就是用组件库的意义：**它把「一个后台该长什么样」的答案固化了**，你只需要补它管不到的地方。

**它管不到的只有两类**：

| 类 | 为什么它管不了 | 这页对应 |
|---|---|---|
| **组件之间的关系** | 它不知道你把哪些组件放一起、间距该多大 | 三条带之间的上下间距、工具条内部的左右对齐 |
| **业务性的取舍** | 它不知道你这一列装的是什么内容 | 各列宽度、下拉的宽度 |

> **可迁移的收获**：接手任何用了组件库的项目，先问「哪些是库给的、哪些是这个项目自己加的」。**改样式改错地方（去覆盖库的默认值）是最常见的坑**——你以为在调自己的东西，其实在跟库打架。

## 二、块 1 · 工具条：让「标题在左、下拉在右」

需求一句话：**一行里两个东西，一个贴左、一个贴右，垂直居中。**

flex 的标准场景，三个属性：

| 属性 | 干什么 | 不写会怎样 |
|---|---|---|
| `display: flex` | 让俩孩子横着排 | 各占一行（div 默认独占一行） |
| `justify-content: space-between` | 剩余空间**全塞到中间** → 一左一右 | 俩东西挤在左边 |
| `align-items: center` | 垂直方向对齐中线 | 文字和下拉框**底部对齐**，看起来一高一低 |

### `space-between` 的机制值得单独记

它**不是**「一个靠左一个靠右」，而是**「把多余空间平均分配到元素之间的缝隙里」**。

两个元素只有一条缝 → 空间全给那条缝 → 结果才是一左一右。

**三个元素时会变成「左 - 中 - 右」**，不是「左左右」。

> **理解成「分配空间」而不是「靠边」，才能预测三个元素时的结果。** 这是所有 flex 对齐属性的通用读法。

### 再加一条 `margin-bottom: 16px`

把工具条和表格分开。

**为什么是 16 不是 15 或 20？** 因为 Element Plus 的整套间距是 **4 的倍数**（4/8/12/16/20/24）。跟着这个节奏走，你的自定义间距和组件内部的留白才是同一套韵律；随手写个 15px，肉眼说不出哪里怪，但就是不齐。

> 这叫**间距栅格**，几乎所有设计体系都有（Material 用 8，Element Plus 用 4）。
> **可迁移的规矩：调任何界面之前，先问这套体系的基数是多少。**

## 三、块 2 · 标题：三行

标题是个裸 `span`，组件库不管，得自己给：字号大一点、字重粗一点、颜色深一点（`18px` / `600` / 深灰）。

### ⚠️ 一个可以顺手做掉的改进：颜色用语义，不用字面量

`../process_instance/03-完整代码.md` 里颜色写的是硬编码 `#303133`。这个值其实**就是 Element Plus 主文字色的原值**——更好的写法是用它的 CSS 变量：

```
color: #303133;                        ← 说的是「这个灰」
color: var(--el-text-color-primary);   ← 说的是「主文字色」
```

**差别在哪**：硬编码的话，将来换主题（比如做暗色模式），这行文字**不会跟着变**——满页都变了就它还是深灰，在暗背景上直接看不见。用变量则自动跟随。

> 跟 [`../UI-配色规律与深色侧栏方案.md`](../UI-配色规律与深色侧栏方案.md) 讲的是同一件事：**颜色不该是字面量，该是语义。** 写 `#303133` 说的是「这个灰」，写 `--el-text-color-primary` 说的是「主文字色」——**后者才是你的真实意图**。
>
> 这条推广开来：**凡是能写成「意图」的，就别写成「值」。** 间距、圆角、层级（z-index）同理。

## 四、块 3 · 分页器：两行

`margin-top: 16px`（和表格拉开，与工具条那 16 呼应）+ `justify-content: flex-end`（推到右边）。

**为什么能直接用 `justify-content`？** 因为 `el-pagination` 内部本来就是个 flex 容器——你不是在给它「加 flex」，是在**改它已有的 flex 的对齐方向**。

**为什么靠右？** 回到 `01` 的判据：**视线终点**。中文阅读的行终点在右侧，一屏数据看完，视线自然落在右下角，分页器就该在那儿等着。

## 五、两个「写在哪」「用哪个」的选择

### ① 下拉的宽度：行内还是样式块？

成品写的是行内 `style="width: 180px"`。

| | 理由 |
|---|---|
| **行内** | 这是**这一个下拉的固有属性**，不是页面布局的一部分；看模板时一眼知道它多宽，不用跳到 style 块去找 |
| **样式块** | 模板干净、样式集中 |

两种都对。**这页只有一处，行内更直观。**

**但如果哪天变成三四个筛选框都要定宽——就该收进样式块了**，否则同一个数字散在四个地方，改的时候必漏一个（**又是静默失败**：页面还在，只是有一处宽度不一样，肉眼扫不出来）。

> **判据：一处用行内，多处必收拢。**（`00-总纲` 元方法 C）这条对所有「重复的字面量」都成立，不限于样式。

### ② 表格列宽：`width` 还是 `min-width`？

| 用哪个 | 什么时候 | 这页哪些列 |
|---|---|---|
| **`width`**（死宽，不参与分配剩余空间） | 内容**长度固定可预测** | 发起时间（`2026-07-30 14:22:05` 永远这么长）、操作列（一个按钮） |
| **`min-width`**（保底宽，还能按比例吃剩余空间） | 内容**长度不定** | 流程名称、业务标识、当前节点、发起人 |

**机制**：`el-table` 先把 `width` 的列按死宽扣掉，**剩下的空间**再按 `min-width` 的比例分给其余列。

所以：

- **全用 `width`** → 宽屏上右边留一条空白
- **全用 `min-width`** → 时间列可能被挤到换行

**混用才是对的**——定长的钉死，可变的让它伸缩。

> ⚠️ **死宽的代价，本案例马上会撞上**：操作列现在只有「终止」一个按钮（`width` 约 90）。按 `02` 第四章的决策，将来要加「复制 ID」变成两个按钮，**操作列的 `width` 必须手动放大**（约 140），否则按钮会被挤掉或换行。
>
> **钉死的东西，内容变了必须手动跟。** 这是选择 `width` 时接受的代价，不是 bug。

## 六、`scoped` 是干什么的

样式块写 `<style scoped lang="scss">`。

`scoped` 让这段样式**只作用于当前组件**——编译时给每个元素加一个独一无二的属性，选择器自动带上它。

**不写会怎样**：你这里定义的 `.toolbar`、`.title`、`.pager` 会**泄漏到全局**。而这几个名字太通用了——待办页、历史页大概率也叫 `.toolbar`，几个页面的样式会互相打架，且**打架的表现是随机的**（取决于哪个组件先加载）。

> 又一次「出错时我会不会知道」：样式泄漏**不报错**，只是某个页面偶尔长歪。**通用名 + 无 scoped = 定时炸弹。**

## 七、检查点

1. Element Plus 已经替你决定了哪些东西？你**只需要补哪两类**？
2. `space-between` 在**三个**元素时是什么效果？为什么？
3. 为什么间距要写 16 而不是 15？
4. `color: #303133` 和 `color: var(--el-text-color-primary)` 视觉上完全一样，为什么推荐后者？
5. 哪些列该用 `width`、哪些该用 `min-width`？**全用 `width` 会怎样？**
6. 样式块不写 `scoped` 会出什么事？这个错误好发现吗？

<details>
<summary>参考答案</summary>

1. 库决定了：边框、底色、hover、圆角、字号、行高、按钮配色、动画。你只补**①组件之间的关系**（间距、对齐）和**②业务性取舍**（列宽、下拉宽度）。
2. 变成「左 - 中 - 右」。因为它是**把多余空间平分到各条缝隙里**，三个元素有两条缝，不是「靠边」。
3. Element Plus 的间距体系是 **4 的倍数**，跟着基数走才和组件内部留白同韵律。15px 说不出哪里怪，但就是不齐。
4. 换主题（如暗色模式）时，硬编码那行**不会跟着变**，在暗背景上会看不见。变量表达的是**意图**（主文字色），字面量表达的只是**值**。
5. 定长内容用 `width`（时间、操作列），不定长用 `min-width`（名称等）。**全用 `width` 宽屏上右侧会留一条空白**，因为没有列去吃剩余空间。
6. 样式**泄漏到全局**，`.toolbar` / `.title` 这类通用名会和其他页面打架，且**表现随机、不报错**——典型的静默失败。

</details>
